# Fono

[English](README.md) · [Скачать для Windows](https://github.com/whitewolf06/Fono/releases/latest) · [Документация](docs/README.md)

Голосовой ввод для Windows с распознаванием на компьютере или своём Fono Server.
Запишите речь горячей клавишей и вставьте результат в нужное поле.
При необходимости включите обработку или перевод через выбранное
LLM-подключение. Интерфейс доступен на русском и английском.

В репозитории находятся **Fono Desktop** и отдельный **Fono Server** без
графического рабочего стола. Последний опубликованный выпуск —
[0.9.1](https://github.com/whitewolf06/Fono/releases/tag/v0.9.1):
установщики Windows и публичные Linux-образы API.
Более высокая версия исходников не означает ещё один опубликованный выпуск.

## Где выполняется распознавание

|                     | Windows Desktop                                    | Fono Server                                         |
| ------------------- | -------------------------------------------------- | --------------------------------------------------- |
| Окружение           | Windows x64, микрофон, горячая клавиша и индикатор | Linux x86_64 контейнер без Tauri и микрофона        |
| Основное ускорение  | Vulkan + встроенный CPU                            | Образ Vulkan + CPU                                  |
| Дополнительная CUDA | Подписанный пакет из настроек аудио                | Отдельный CUDA-образ                                |
| Подключение         | Локальная модель или настроенный Fono Server       | API по токену, встроенная панель и ключи приложений |

Auto использует Vulkan на подходящей дискретной GPU, а без неё — CPU.
Установка CUDA не меняет Auto: CUDA выбирается явно.
GigaAM и Parakeet работают на CPU. Модели загружаются отдельно.

При серверном распознавании веса модели остаются на сервере.
Windows-клиент загружает локальную модель только при использовании явно
выбранного CPU-резерва. LLM-обработка настраивается отдельно.

Standalone GPU Server для Windows, Linux Desktop и macOS Desktop не входят
в поддерживаемую поставку этого выпуска. Для контейнера нужно подходящее
Linux-окружение; GPU-сценарии Windows/WSL2 отдельно не квалифицированы.

## Установка и первая диктовка

1. Скачайте `FonoSetup.exe` или полный установщик Windows x64 из
   [Releases](https://github.com/whitewolf06/Fono/releases/latest).
2. Выберите микрофон. Загрузите локальную модель или укажите адрес,
   токен и установленную модель Fono Server.
3. Настройте удержание или повторное нажатие горячей клавиши.
4. Откройте нужное поле и продиктуйте текст. Распознавание начнётся после Stop.

В интерфейсе Windows доступны HTTPS и управляемое SSH-подключение.
Сохраните его один раз — Fono откроет канал при обращении к серверу.
Отпечаток SSH-ключа подтверждает сервер; это **не API-токен**.

Компактный индикатор сохраняет волну и статус во время обработки.
Если исходное поле недоступно, результат остаётся для копирования.
Действия с текстом и настройки описаны в [руководстве пользователя](docs/user-guide.md).

## Возможности и приватность

- Обработка текста, форматирование, стиль задачи/деловой стиль, перевод
  и собственные инструкции. Для обычной диктовки LLM не нужен.
- Профили приложений, личный словарь, сниппеты, история и речевой тренер.
  История и аналитика включаются отдельно.
- **Пробуждение «Привет, Лира» — beta.** Включается вручную; задержка,
  независимые голоса и длительные отрицательные серии требуют отдельной приёмки.
- Локальный API по токену и ограниченные голосовые команды с подтверждением.
- Windows Credential Manager для ключей и безопасный технический отчёт.

Локальное распознавание оставляет аудио на ПК. Серверное отправляет его
на настроенный Fono Server; внешний LLM получает текст для выбранной обработки.
Панель сервера не является архивом диктовок. Экспериментальный режим «На лету»
и старый мастер произвольной wake-фразы остаются выключенными.

Владелец проверил базовую локальную и серверную диктовку. Чистая Windows,
полная матрица GPU/устройств, отказов и длительной работы учитываются отдельно.
Проверка обновлений не запускает установку: она требует действия пользователя
после завершения активных операций.

## Подключение к API

Сервер поставляется через
[`ghcr.io/whitewolf06/fono-server`](https://github.com/whitewolf06/Fono/pkgs/container/fono-server):

- `:0.9.1` или `:0.9.1-vulkan` — Vulkan + CPU.
- `:0.9.1-cuda` — дополнительная CUDA-поставка.
- Подвижные теги: `:latest`, `:vulkan`, `:cuda`. Для воспроизводимого
  развёртывания закрепляйте version или digest.

Настройте volumes, модели, credentials, GPU и защищённый доступ по
[руководству сервера](docs/server.md). Откройте `/panel/` с admin-токеном,
создайте ключ приложения и скопируйте настройки:

```dotenv
FONO_HOST=http://127.0.0.1:17832
FONO_TOKEN=<ключ-приложения>
```

Адрес должен быть доступен из окружения потребителя. Пример loopback HTTP
подходит для одного хоста/network namespace; для защиты транспорта используйте
TLS или защищённый туннель. Другие приложения вызывают API напрямую,
Windows Fono для этого не требуется.

```sh
curl --fail-with-body \
  -H "Authorization: Bearer $FONO_TOKEN" \
  -H "Content-Type: audio/wav" \
  --data-binary @speech.wav \
  "$FONO_HOST/v1/recognize?language=ru"
```

[Документация API](docs/api.md) описывает discovery, форматы, задания,
отмену, OpenAI-совместимый маршрут и ошибки. На работающем сервере
`/openapi.json` и `/docs` требуют токен; `/healthz` — публичная проверка готовности.

## Разработка

Frontend устанавливается без приватных npm credentials.
Точный архив WhiteUI **0.6.0** включён в
[vendor/whiteui](vendor/whiteui/README.md).

Для интерфейса:

```sh
npm ci
npm run dev:ui
```

Откройте `http://127.0.0.1:1420/v3.html`. Это browser mock:
микрофон, Rust IPC, глобальная клавиша и вставка Windows здесь не работают.

Для настоящего CPU Desktop установите зависимости из
[development.md](docs/development.md), затем выполните `npm run dev:cpu`.
CUDA/Vulkan SDK для этого пути не нужны. Нативные устройства настоящие,
debug-профиль изолирован.
