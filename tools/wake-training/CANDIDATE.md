# Первый акустический кандидат — v0.7.67

22 октября 2026 года. Это файловый исследовательский pipeline. Он не включает
детектор в Fono, не записывает микрофон и не меняет модель диктовки.

## Фактический результат

Сохранены и проверены 36 локальных записей владельца: 28 с целевой фразой,
6 с другой речью, 2 фоновых файла. Один говорящий, 85,34 с, все записи — dev.
Два фоновых файла содержат цифровые нули: это не проверка шума комнаты.
Хэши совпали, WAV не повреждены, перегруженных сэмплов нет. Точные слова и
времена окончания фраз ещё не проверены вручную. Голос не загружался в сеть.

Один прогон прежнего ASR baseline дал 0/28 обнаружений; короткие WAV могли
закончиться до стабилизации гипотезы. Один прогон небольшого English KWS
GigaSpeech дал 0/28. Его контрольный официальный WAV с LIGHT UP проходит;
это проверка стенда, а не качества «Фоно». Время и контекст этих прогонов
различаются, сравнение скорости или формального recall между ними не заявляется.

Собственный CNN обучен на отдельной синтетике, без голоса владельца:

| Группа владельца | Обнаружено / записей с фразой |
| ---------------- | ----------------------------- |
| RU, тихо         | 4/4                           |
| RU, шумная метка | 12/12                         |
| EN, тихо         | 4/4                           |
| EN, шумная метка | 7/8                           |

Всего 27/28. На **4 из 6** файлов с меткой «другая речь» — **5 событий**.
На двух файлах цифровой тишины — 0 событий. Это ещё не подтверждённые FA/h:
отрицательные метки и присутствие фразы нужно проверить, объём крайне мал.
Кандидат не проходит приёмку и не подключён к приложению.

## Обучение и происхождение

- Собственный frontend без pretrained embedding: 16 kHz, окно 4 с, FFT 512,
  Hann 400, шаг 160, 40 mel-полос 20–7600 Hz, log floor 1e-8, нормализация
  среднего и стандартного отклонения окна. Точный контракт — `candidate.py`.
- CNN: Conv 8/16/24, pooling, adaptive 1×10, FC32/1; **12 473 параметра**.
- Seed 20261022, 16 эпох, AdamW lr=0,001, batch 64. Один кандидат, без
  подбора порога по личным записям: score ≥0,8, cooldown 2 с, шаг replay 80 мс.
  Результаты dev не возвращались в обучение.
- VoxCPM **2.0.3**, публичные уже установленные локальные веса VoxCPM2,
  revision `32279effe8c19989596f05d353d1447f51d9e915`, проверенные по
  [voxcpm2.json](voxcpm2.json). Четыре текстовых описания голоса, без reference
  audio, клонирования голоса, denoiser и normalizer. Доступ к модели offline.
- Один синтез, мягкий предел 600 с, внешний watchdog 660 с. Получены **88 из
  96 запланированных WAV**, 110,08 с: 24 положительных, 64 отрицательных.
  На лимите исходная версия скрипта завершилась с TimeoutError; готовый
  последовательный префикс отдельно проверен и оформлен как **partial**,
  без новой генерации. В текущем скрипте префикс сохраняется явно с причиной
  остановки. Снимок точного исходного скрипта и журнал сохранены рядом с
  локальными артефактами; это не полный успешный синтез 96 файлов.
- Speed/gain/noise/position augmentation только синтетических train WAV.
  Получены 768 положительных и 687 отрицательных окон, включая 48 искусственных
  noise/silence окон. Превышающие длину окна варианты не обрезаются молча.
- Обучение на CPU: **60,77 с**, предел 180 с, внешний watchdog 240 с.
  ONNX opset17: **52 182 байта**, PyTorch/ORT max abs error
  **5,960464477539063e-8** на восьми фиксированных train-окнах. Это проверка
  экспорта, не независимый quality test. Все 88 исходных клипов использованы,
  ни один исходный WAV по длине не исключён.
- SHA256 ONNX: `e711a6890584d277a792e23001f5459c5a1577f56fef62b67d99cfa3a2929f64`.
  Модель, WAV и подробные трассы остаются в игнорируемом `build/`.
  Реестра загрузки, публикации и выдуманного URL нет.

Прямые версии зависимостей записаны в
[requirements-candidate.txt](requirements-candidate.txt), точные параметры и
хэши — в локальном config/result. Это ещё не полный dependency lock, не
обещание bit-for-bit обучения на другом ПК. Публичный model card издателя
[VoxCPM2](https://huggingface.co/openbmb/VoxCPM2) указывает Apache-2.0;
никакие его веса или сторонний Python runtime в приложение не упакованы.

## Команды

Для нового pipeline нужен отдельный Python 3.12 с подготовленными зависимостями.
Не устанавливать пакеты в runtime Fono или чужого приложения. Указанный каталог
модели должен уже существовать; скрипт ничего не загружает. Для синтеза нужны
CUDA и ≥10 GiB свободной VRAM; лимит процесса — 60% памяти. Train/evaluate
используют CPU и не выгружают модели других процессов.

```powershell
python tools/wake-training/synthesize_candidate.py `
  --model-dir C:/models/VoxCPM2/32279effe8c19989596f05d353d1447f51d9e915 `
  --output-dir build/wake-candidate/new-synthetic --max-seconds 600
python tools/wake-training/candidate.py train `
  --training-manifest build/wake-candidate/new-synthetic/training-data.json `
  --output-dir build/wake-candidate/new-model --max-seconds 180
python tools/wake-training/candidate.py evaluate `
  --model-dir build/wake-candidate/new-model `
  --recordings-dir build/dev-desktop-profile/wake-recordings `
  --output-dir build/wake-candidate/new-replay
python -m unittest discover -s tools/wake-training -p 'test_*.py' -v
```

Все выходные каталоги должны быть новыми. `training-result.json` записывается
только после обучения и проверки ONNX; незавершённую модель не оценивать.
Для train принимается только explicit synthetic/train manifest; личный
`fono-wake-recording@1` импортируется только отдельной командой evaluate,
с проверкой локального согласия, dev split и хэшей WAV. Метки владельца не
превращаются в подтверждённую временную разметку. `aggregate.json` содержит
общие числа; `private-traces.json` содержит идентичности аудио — не публиковать.

Replay использует неизменённый PCM, 4 с нулевого левого контекста и 640 мс
синтетического хвоста, отдельно от записанного времени. Это ускоренное
файловое выполнение: **p95 и idle CPU не измерены**. ONNX содержит CNN head;
log-mel frontend пока выполняется в Python, native parity не проверена.

## Оставшаяся работа

1. Проверить отрицательные метки и причины пяти событий по локальным трассам.
   Следующий training-набор должен включать отдельную обычную реальную речь
   и трудные негативы обоих языков; текущие личные dev WAV сохранять вне train.
2. Зафиксировать следующий обучающий раунд и operating point на dev, затем
   проверить независимый реальный test с разметкой. Сетка порогов по этим
   36 записям не запускалась, качество после просмотра результата не объявлено.
3. Сохраняются исходные цели: recall ≥95% quiet / ≥90% noisy, ≤0,5 FA/h,
   p95≤800 мс, idle CPU<1% одного ядра, 100–300 произнесений разных людей и
   микрофонов, ≥10 ч разрешённых негативов. Эти записи не закрывают общий gate.
4. После принятого качества — native frontend/ONNX contract, AudioHub и
   registration/download artifact, FONO-145 и ручная проверка. Персонализация
   FONO-146 остаётся отдельным шагом. Постоянное прослушивание выключено.
