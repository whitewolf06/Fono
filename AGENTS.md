# Fono: правила для агентов

## Версия приложения и коммиты

- Источник версии Fono — `package.json`. Версия приложения должна совпадать в `package-lock.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` и записи `fono` в `src-tauri/Cargo.lock`.
- Новая схема начинается с базового коммита `0.5.0`; актуальную версию всегда читать из `package.json`. Каждый следующий коммит поднимает patch ровно на 1 (`0.5.0` → `0.5.1`) через `npm run version:bump -- patch`.
- При подготовке публикации предложить пользователю следующую minor-версию и её состав. Поднимать minor (`0.5.x` → `0.6.0`) через `npm run version:bump -- minor` только после согласования; публикация и изменение minor — отдельные решения.
- В теме **каждого** нового коммита указывать версию в виде `vX.Y.Z`, например `fix(wake): сохранить фразу [v0.5.1]`. Не создавать коммит без изменения версии, включая docs, исправления и merge-коммиты.
- Перед коммитом запускать `npm run version:check`. Для локальной проверки сообщения коммита установить репозиторный hook через `npm run hooks:install`; hook сравнивает staged-версию с `HEAD`, проверяет синхронизацию файлов и наличие версии в теме. Проверять, что в коммит попали и код, и все файлы версии.
- Не менять версии внутренних Rust crates (`fono-core`, `fono-wake` и других) вслед за версией приложения без отдельной причины: их номера описывают внутренние пакеты.

## Фронтенд Fono (Vue)

- Единственный рабочий интерфейс — `src/v3/` на Vue 3 + TypeScript (`<script setup>`). `index.html` и `v3.html` запускают его общий entrypoint; Tauri открывает `v3.html` в основном окне и `v3.html?view=overlay` в индикаторе. Не возвращать удалённые React-интерфейсы, автономные HTML-прототипы и отдельный набросок overlay. Рабочий `OverlayIndicator.vue` используется в native и browser preview.
- Использовать `@whitelife-core/ui-kit` строго версии 0.6.0, `WlConfig`, собственные компоненты/сервисы WhiteUI и SVG-иконки. PrimeVue и PrimeIcons в V3 не использовать. Тему устанавливать на html для Teleport. Версия кита не меняет minor Fono. Стили подключать в порядке `reset.css`, `base.css`, тема, стили Fono. Реестр пакета — `.npmrc`; токен хранить в пользовательской конфигурации npm, не в репозитории.
- Цвета, типографику, радиусы, отступы и размеры основных областей задавать через `src/v3/styles/tokens.css`. Цветовые роли Fono ссылаются на `--wl-*` UI Kit; не добавлять новые цвета и шкалы прямо в CSS компонентов.
- Сохранять слои `domain`, `application`, `infrastructure`, `presentation` по фичам. Vue-компоненты не вызывают Tauri IPC, browser storage или window API; доступ идёт через внедрённые типизированные порты. Browser API находятся в адаптерах. Composition root выбирает native runtime только внутри Tauri; в обычном браузере используется mock. В браузере сохраняются только разрешённые демонастройки, без ключей и текстов. Нативные настройки и история сохраняются через Rust; последний результат сессии хранится в памяти независимо от архива.
- Проверка браузерного V3: `npm run dev:ui`, открыть `http://127.0.0.1:1420/v3.html`. Там mock runtime и демонстрационные данные. `npm run dev:desktop:v3` открывает настоящий V3 с Rust и Tauri IPC. Не подменять в desktop реальные устройства, модели или результаты демонстрационными значениями.
- Перед сдачей V3 проверять фронтенд: `npm run typecheck:v3`, `npm run lint` с `.vue`, `npm run build`, `npm run version:check`, `npm run format:check` и browser-сценарии на 720×560, 900×720, 1440×900. После нативных изменений также запускать `npm run test:v3` и Rust-тесты. Browser mock не подтверждает работу Rust, микрофона или глобальной клавиши. Для debug-проверки можно задать абсолютный `FONO_TEST_DATA_DIR` и отдельный `FONO_API_PORT`: история/настройки изолируются, Windows credentials и автозапуск недоступны. Release игнорирует тестовый каталог. Installer готовить по запросу; не устанавливать автоматически. В текущем обновлении пользователь проверяет окна и поведение самостоятельно: не управлять его приложением ради UI-проверки.

## Голосовое ядро и диктовка на лету

- Режим горячей клавиши `hold`/`toggle` независим от режима распознавания: оба используют классическую диктовку. Автоповтор клавиши и запоздалый Release не должны запускать или завершать другую сессию.
- Ручная обработка удерживает исходный текст и активную сессию до решения пользователя; запись архивируется один раз после принятого действия. Стиль и перевод, выбранные в индикаторе, сохраняются как предпочтения следующих диктовок и применяются к точно указанной активной сессии только после успешного сохранения. Быстрые настройки обработки включены по умолчанию и могут быть скрыты; в режиме повторного нажатия доступны во время записи. Перед Stop необходимо дождаться сохранения последнего выбора. Ошибка сохранения возвращает подтверждённый выбор, ошибка ИИ оставляет исходный текст для повтора, копирования или вставки. Выключенная обработка не вызывает ИИ даже при сохранённом языке перевода.
- Принятие кнопкой оверлея завершает запись без внешней вставки: результат остаётся для копирования или закрытия. Успешное копирование закрывает индикатор и завершает сессию; ошибка оставляет текст доступным. Повтор сочетания в режиме `toggle` применяет сохранённый выбор, вставляет результат и закрывает индикатор. Иконки обработки и перевода декоративные; переключатели меняют включение, отдельные шестерёнки открывают стиль и язык.
- Режим обработки `raw` («Без изменений») без перевода возвращает исходный текст без запроса к LLM и не требует настроенного подключения. С переводом он вызывает только перевод. Для `clean`/`format`/`task`/`formal` выбор встроенного или собственного системного промпта хранится отдельно; отключение собственного промпта сохраняет его содержимое. Обычная диктовка, повторная обработка и тест используют общий составитель инструкций. Входная расшифровка является материалом для редактирования, вопросы в ней не требуют ответа.
- Проверка промпта использует черновую инструкцию и сохранённое подключение; не сохраняет текст, историю или последний результат и не вставляет в Windows. Пробная диктовка имеет собственный идентификатор, речевой VAD, ограничение времени, отмену при закрытии формы и общий STT scheduler. Старые Stop/Cancel и поздние результаты не действуют на следующую запись. Фоновая распознающая работа удерживает admission lease до своего фактического завершения.
- Для отложенной вставки сохранять исходное поле при старте. Смена поля и частичная вставка блокируют повторную отправку; результат остаётся для копирования. Pending и фактическая фоновая работа удерживают admission lease обновлений до завершения.
- Пустые и случайные записи отсеивать речевым VAD до STT, истории и вставки. Не заменять проверку речи списком запрещённых текстов или отсечкой всех коротких/тихих слов.
- После ручной проверки режим «На лету» временно скрыт. В UI, browser mock и native runtime доступен только классический режим; сохранённый `live` и входящие настройки приводятся к `standard`. Не включать экспериментальный режим до отдельного согласования его качества.
- WakeWord, обычная диктовка и режим «На лету» используют общий AudioHub: RT-callback только пишет в ограниченную очередь. Детектор публикует готовность после открытия модели и микрофона; ошибки и потеря пакетов не должны выглядеть как нормальное ожидание.
- Собственная фраза RU/EN проверяется реальным потоковым детектором: пять образцов настройки, три новых положительных и два отрицательных. RMS не является обучением. При изменении фразы, устройства, модели или параметров профиль инвалидируется и пробуждение выключается до повторной проверки.
- «На лету» вставляет только стабильный префикс. Подтверждённый текст неизменяем; черновик можно заменить. LLM в этом режиме не вызывается. Не обрезать PCM после каждого слова: завершение сегмента определяется речевым VAD, длинные окна ограничены и сохраняют перекрытие.
- Смена окна или доступного поля приостанавливает вставку. Возобновление требует явного действия и нового выбора поля. Частично отправленные события не повторяются автоматически; доступный текст остаётся для копирования. Проверка UI Automation не читает содержимое чужих полей.
- Native overlay должен оставаться без активации (`focus: false`, `focusable: false` в основном и dev-конфигах): его кнопки не должны отбирать фокус у внешнего поля при возобновлении вставки.
- API-задания имеют отдельный lifecycle, ограниченные окна и уступают STT интерактивной диктовке; отмена окна для вытеснения не отменяет само задание. Повторный Stop ожидает один результат, Cancel блокирует поздние вставки и публикацию от старой операции.
- GPU worker протокол и бинарники обновлять вместе: `npm run build:workers`. Release проверяет handshake каждого worker, `prepare:release-resources` тоже. Несовместимые старые бинарники нельзя выдавать за проверенную сборку.
- Для этого этапа не записывать микрофон и не управлять пользовательским приложением автоматически. Проверять код и публичные WAV; пользователь самостоятельно проверяет голос, hotkey, поля и overlay. Короткий replay не подтверждает recall, длительные false activations или качество на личном голосе. Инструкции и оставшаяся приёмка — `docs/fono-voice-reliability.md`.

## Диагностика, история, словарь и обновления

- Личный словарь выключен по умолчанию. Использовать локальные точные замены целых слов и фраз после обработки обычной диктовки; исходный текст и голосовые команды не изменять. Выключение сохраняет записи. В browser mock записи словаря остаются только в памяти.
- Метаданные истории отражают конкретную сессию: фактический backend из `Transcript.device`, выбранное ускорение отдельно, модель из снимка настроек, длительности записи и обработки. Генерация измеряется от Stop до готового итогового текста, до вставки. Старые записи без метаданных поддерживать; неизвестные значения не выдумывать.
- Диагностический отчёт строить из разрешённых технических полей. Не включать тексты, сырые логи и ошибки, ключи, адреса профилей, пути, имена устройств, инструкции и содержимое словаря. Экспорт остаётся локальным действием пользователя.
- GitHub-репозиторий `whitewolf06/fono` публичный; бесплатный канал — GitHub Releases. Публичный ключ и endpoint находятся в `src-tauri/update-channel.json`; приватный signing key хранится вне Git с ограниченными правами. Не выводить и не включать его в отчёты, логи или артефакты.
- Updater проверяет HTTPS, подпись и подписанную версию; не допускает downgrade. Автоматическая проверка включается пользователем. Установка запускается только явной кнопкой после подтверждения и завершения активных операций. Новые фоновые операции должны участвовать в admission fence `application::updates::activity`; асинхронная подготовка удерживает lease до завершения фактической работы.
- Перед сдачей выполнять также `npm run test:release` и проверки CI workflow. Подготовка подписанного installer, публикация release, установка и приёмка на чистой Windows — разные этапы. Приёмка на чистой Windows отложена пользователем; не считать unit tests её заменой.

## Онлайн-установщик

- `tools/fono-setup` — самостоятельный Windows x64 Cargo workspace. Версию EXE брать из корневого `package.json`; внутреннюю версию crate не поднимать вместе с Fono. Статический CRT настраивать только в этом workspace, не менять профиль Whisper ради размера загрузчика.
- Загрузчик использует встроенный публичный канал и ключ, докачивание и обязательную проверку подписи/подписанной версии до запуска NSIS. Сохранять запрет отката для NSIS/MSI, блокировку кэша и защиту проверенного EXE от подмены. Не добавлять приватные ключи, токены или runtime-переопределение канала через аргументы.
- `npm run build:setup` проверяет format, tests, strict Clippy и собирает локальный EXE. Диагностические команды `--check-only`, `--download-only`, `--verify-package` не запускают установку. Реальные GUI/UAC/NSIS проверяет пользователь; не устанавливать автоматически. Сборка загрузчика, публикация asset и обновление установленного приложения — разные этапы. Подробности: `docs/online-installer.md`.

## Временные ограничения и память модели

- WakeWord временно недоступен. Флаги `WAKE_WORD_AVAILABLE` в Rust и V3 остаются выключенными до отдельной задачи на качество детектора и ручной проверки голоса. Старые настройки включения нормализуются в `false`; фраза и профиль сохраняются. Горячие клавиши диктовки и голосовых команд доступны.
- `gpu_model_residency` управляет только локальной моделью Whisper: `resident` — прежнее постоянное хранение, `adaptive` — освобождение при устойчивой нехватке выделенной видеопамяти и простое. Не выгружать активную модель, не менять ускорение на CPU и не перезагружать её по таймеру. Следующий запрос загружает модель через существующий `ensure_loaded`.
- Монитор видеопамяти использует глобальный Windows PDH `GPU Adapter Memory` и точное сопоставление DXGI LUID. Пока поддерживается одна аппаратная видеокарта с выделенной памятью от 1 ГБ. Не использовать расход основного процесса вместо расхода worker, максимум другой GPU или выдуманный нулевой расход при неизвестной метрике.
- Автопроверка обновлений опциональна: один планировщик, попытка не чаще раза в сутки с сохранением времени между запусками. Ручная проверка доступна независимо; установка запускается только отдельной командой пользователя. История версий основана на коммитах и не означает публикацию каждого номера.

## Варианты тестирования

Не смешивать три разных уровня проверки и явно указывать, какой из них выполнен:

- **UI в браузере:** `npm run dev:ui`, затем `http://127.0.0.1:1420/` или `http://127.0.0.1:1420/v3.html`. Vue-интерфейс работает на mock runtime; Rust, Tauri IPC, микрофон, глобальный hotkey и внешняя вставка не работают. `#/overlay` показывает браузерный предпросмотр индикатора.
- **Desktop dev / собранный Tauri + Rust:** `npm run tauri dev` для разработки либо прямой запуск `src-tauri\\target\\release\\fono.exe` после production-сборки. Это приложение с настоящим Tauri и Rust-бэкендом, но без установки через installer; использовать для функциональной проверки основной и overlay окон.
- **Финальная release-проверка:** `npm run release` создаёт NSIS/MSI installer. Установщик нужен только для проверки поставляемой релизной сборки (упаковка ресурсов, установка и запуск как у пользователя), а не для каждой итерации разработки.

Подробная схема и применимость правил: `docs/frontend-architecture.md`.
