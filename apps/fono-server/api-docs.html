Fono Server API v2

Standalone speech recognition on CPU and, in the CUDA worker build, NVIDIA GPUs. Fetch /v1/capabilities and /v1/models to discover this server's observed devices, limits, installed models, and feature gates.

Open the server panel for token sign-in, status, installed models, aggregate queue counts, API documentation and an audio-file request playground. The public login shell contains no server data. Tokens and request results stay in tab memory and are cleared on sign-out or reload.

API data and this reference page require Authorization: Bearer <token>. /healthz and the panel login shell/assets are public. Administrative model commands and metrics require an admin token. Keep bearer tokens in your client or local environment; this reference page does not collect or store them.

Recognize an audio file

curl -H "Authorization: Bearer $FONO_TOKEN" \
  -H 'Content-Type: audio/wav' --data-binary @speech.wav \
  'http://127.0.0.1:17832/v1/recognize?language=ru&timestamps=segments'

Raw audio/L16;rate=16000;channels=1 means signed big-endian 16-bit PCM. WAV and Ogg/Opus are supported as complete bodies. Use timestamps=none|segments|words and decoding=fast|accurate; the selected model must support the requested options. Timings are measured or supplied by the recognizer, never synthesized.

X-Fono-Glossary contains base64url UTF-8 JSON with an array of strings. Decoded JSON is limited to 4096 bytes; the native prompt additionally limits input to 32 terms and 896 term bytes. See per-model feature flags before sending glossary or accurate decoding.

OpenAI-compatible clients

from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:17832/v1", api_key=token)
with open("speech.wav", "rb") as audio:
    result = client.audio.transcriptions.create(
        model="whisper:tiny", file=audio, language="ru")
print(result.text)

POST /v1/audio/transcriptions accepts multipart file, model, optional language, prompt, response_format, timestamp_granularities[] and temperature. A prompt is limited to 224 UTF-8 bytes and requires a model with initial-prompt support. Larger prompts are rejected instead of silently truncated. Formats: json, text, srt, vtt, verbose_json. Temperature from 0 through 1 is accepted and ignored. Timestamp arrays in verbose JSON use seconds; Fono recognition segments use milliseconds.

Application keys

Sign in to the server panel with an admin token and open Applications to create a recognition-only key and copy a ready FONO_HOST/FONO_TOKEN environment snippet. Set server.client_url once to the origin reachable from consumers, or enter that address in the panel. The browser's SSH-forwarded address is not inferred. Inside a Docker container, localhost points to that container.

The clients API is admin-only: POST /v1/clients accepts {"name":"my-app"} and returns HTTP 201 with the one-time secret. GET /v1/clients returns names, creation dates and the optional configured origin, never secrets or hashes. DELETE /v1/clients/my-app returns 204 and revokes the key for subsequent requests. Administrative keys cannot be issued or revoked through this API. Secrets are stored only as salted digests; the panel clears a new secret when leaving Applications or ending the session. The private credential directory must be writable by the server account.

Limits, errors and cancellation

Every response carries X-Request-Id. JSON errors contain a stable code and safe message. HTTP 401 means a missing or revoked token; 403 means insufficient scope or a disabled feature; 404 means an unknown or missing model; 408 means a body reception timeout; 413 means a size or duration limit; 429 means admission is busy and includes Retry-After. A slow upload has a total reception deadline, while recognition may continue longer.

Disconnecting a synchronous recognition request cancels its operation. Native work holds admission until it actually returns. Batch jobs have an independent lifecycle and use explicit cancellation. Do not automatically repeat a request if the first operation's outcome is unknown.

Client model control is disabled by default. Enable models.client_model_load=true explicitly to use admin load/unload. Model files are installed through the server CLI; the API never downloads them. Metrics are enabled independently with metrics.enabled=true.

The default listener is loopback. For a protected private network, configure the exact Host allowlist and explicit network assertion. Native rustls supports TLS 1.2/1.3 with HTTP/1.1 and HTTP/2. Configured certificate and key files are validated before startup; SIGHUP reloads a valid replacement without interrupting existing connections. An invalid replacement preserves the previous certificate. Certificate issuance and renewal scheduling are operator actions. CORS grants no cross-origin browser access.

Per-credential request quotas default to 120 requests/minute with burst 20. Exhaustion returns 429 rate_limited and Retry-After before body extraction. Queue exhaustion returns the separate 429 busy code. Health probes and the public panel assets require no token; API data, this reference page and OpenAPI require bearer authentication. The panel pauses automatic status polling for the advertised retry interval and never automatically repeats audio requests.
