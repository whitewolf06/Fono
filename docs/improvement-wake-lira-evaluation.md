# Проверка «Привет, Лира» — v0.7.70

22 октября 2026 года. Владелец завершил запись нового набора. Выполнены один
синтез, одно обучение и один файловый прогон новой модели с фиксированным
порогом 0,8. **Кандидат не принят: пропущены 2 целевых клипа и получены
4 события на 7 записях другой речи.** WakeWord остаётся выключенным.

## Реальные записи и результат

Проверены schema, согласие на локальное использование, принадлежность фразе,
dev split, WAV PCM16 mono 16 kHz, SHA256 и длительности. Все 31 новые записи
целы, перегруженных сэмплов нет. Прежние 36 записей не переименованы и не
участвовали в этом прогоне. Голос владельца не использовался для обучения.

| Группа                     | Клипы с событием / всего | События |
| -------------------------- | ------------------------ | ------- |
| Фраза, тихая комната       | 9/10                     | 9       |
| Фраза, метка фона          | 11/12                    | 11      |
| Другая речь, тихая комната | 2/4                      | 2       |
| Другая речь, метка фона    | 2/3                      | 2       |
| Фоновые файлы              | 0/2                      | 0       |

Всего 74,02 с: 34,01 с положительных, 31,93 с другой речи и 8,08 с фоновых
файлов. Из фона **6,38 с — цифровая тишина**, реального звука только 1,70 с.
Цифровая тишина не считается проверкой устойчивости к шуму. Метки условий
задал пользователь; сами условия и временные границы фраз не размечены.
Поэтому обнаружение в клипе не объявляется формальным recall, а эти секунды
не заменяют длительную проверку FA/h, задержки или idle CPU.

Отдельный локальный Whisper medium/Vulkan, protocol4, использован как помощь
разметке, без target prompt. Он распознал полную фразу в 16/22 положительных
и в 0/7 речевых негативов за 41,33 с. Это не человеческая ground truth и не
изменение меток. В новых негативах ASR не подтвердил iPhone и заранее
перечисленные похожие имена; нельзя объявлять этот контроль пройденным.
Полные расшифровки остаются только локально.

Из уже полученных выходов, без нового inference, посчитано пересечение
CNN и точного ASR: 16/22 целевых и 0/7 речевых негативов. Такой каскад
тоже не подключён: устранение событий ценой шести пропусков не подходит.

## Единственный обучающий раунд

- Локальный VoxCPM2, четыре текстовых voice designs, без reference audio и
  голоса владельца: **36/36** синтетических WAV, 43,36 с, 8 positive и
  28 negative. Среди учебных негативов — «Привет, Лера», «Привет, Мира»,
  «Привет, Ира», упоминание айфона и отдельные слова. Синтез 115,78 с,
  peak reserved VRAM 5 966 397 440 байт. Веса и SHA проверены по прежнему
  [voxcpm2.json](../tools/wake-training/voxcpm2.json), revision
  `32279effe8c19989596f05d353d1447f51d9e915`.
- Дополнительно 20 публичных RU/EN FLEURS клипов, 235,35875 с,
  revision `437d9e667fa3a2a08a1957f810bf2c3b5050d221`, CC-BY-4.0.
  Их upstream test явно назначен wake train; весь FLEURS исключён из
  будущего независимого wake test. Manifest
  `9135c5d2c751146ce229dbedac783d89bd584590dd3840342567f12d57360241`.
  Используются существующие PCM replay с проверкой **replay_sha256**:
  сохранённое исходное число сэмплов отличается на один от результата
  конвертера. Первичная проверка отклонила неверный выбор поля хэша ещё
  до создания модели; адаптер исправлен на явный контракт replay.
- Собственный log-mel/CNN без pretrained embedding, **12 473 параметра**,
  causal prefix augmentation, CPU 4 threads, seed 20261022, 32 эпохи,
  384 положительных и 1152 отрицательных окон. Обучение **72,70 с**;
  исключённых длинных синтетических файлов нет.
- ONNX 52 182 байта, SHA256
  `a9c4e2595669605325b97b7aeec62781c58073e9966a3850d360328bddaa541c`;
  checker и PyTorch/ORT parity прошли, max absolute error 1,79e-7.
- Replay 80 мс, 4 с левого контекста, явный искусственный хвост 640 мс,
  crossing/cooldown 2 с. Wall time 1,594 с не является задержкой детектора.
  Модель, порог и исходники зафиксированы до чтения dev-результата.
  После него обучения или подбора порогов не было.

Среда Python 3.12.14, NumPy 1.26.4, SciPy 1.17.1, PyTorch 2.7.1+cu128,
ONNX 1.19.1, ORT 1.23.2, VoxCPM 2.0.3. Прямые зависимости закреплены в
`requirements-candidate.txt`; полный воспроизводимый dependency lock ещё
не заявлен. Точные снимки трёх скриптов сохранены рядом с локальной моделью.

## Воспроизведение и проверки

В подготовленном Python-окружении с исследовательскими зависимостями:

```powershell
python tools/wake-training/synthesize_candidate.py --phrase-id privet_lira `
  --model-dir C:/models/VoxCPM2 --output-dir build/wake-lira-candidate/synthetic-NEW --max-seconds 240
python tools/wake-training/lira.py train `
  --training-manifest build/wake-lira-candidate/synthetic-NEW/training-data.json `
  --public-speech build/stt-quality/current/corpus.json `
  --output-dir build/wake-lira-candidate/model-NEW --max-seconds 180
python tools/wake-training/lira.py evaluate --model-dir build/wake-lira-candidate/model-NEW `
  --recordings-dir build/dev-desktop-profile/wake-recordings `
  --output-dir build/wake-lira-candidate/replay-NEW
```

Каталоги результатов должны быть новыми. Синтез offline, только по заранее
проверенным локальным весам; голос владельца не является входом train/TTS.
Private traces и расшифровки в ignored build, публичное evidence содержит
только агрегаты: [wake-lira-evaluation.json](evidence/wake-lira-evaluation.json).
Проверены 21 training и 18 benchmark contracts без моделей/микрофона,
48/48 release/CI, формат, согласованность версии и ссылки документации.
Изменений Rust или V3 в этом проходе нет; приложение не перезапускалось,
новый EXE или установщик не собирались.

## Что осталось

1. Исправить способность детектора отличать полную фразу от другой речи и
   проверить отдельные разрешённые реальные hard negatives. Маленький
   синтетический CNN пока не показал достаточного качества. Повторять
   этот train или менять порог по тем же личным записям сейчас не нужно.
   Новые записи владельца для следующего ограниченного этапа не требуются.
2. Сохранить реальные отложенные голоса и аннотации границ. Исходные цели:
   ≥95% quiet / ≥90% noisy recall, ≤0,5 FA/h, p95≤800 мс, idle CPU<1%
   одного ядра; 100–300 произнесений разных людей/микрофонов и ≥10 часов
   разрешённых негативов. Ни один из этих пунктов не объявлен закрытым.
3. После качества — dependency lock, licenses/notices итогового артефакта,
   реальный registry/download artifact с SHA256, интеграция FONO-145 и
   отдельная персонализация FONO-146. FONO-144 остаётся в работе.
