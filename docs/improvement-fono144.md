## Зависимость и границы результата

FONO-143 / W-02 — `in_review`: отдельный стенд реализован, но реального
измерительного корпуса и принятого quality-отчёта нет. Предыдущий инженерный
smoke не содержал ни одного целевого произнесения и не разблокировал обучение
или интеграцию. Требования W-03 отдельно предусматривают согласование
ресурсов, моделей и лицензий. Длительный GPU-прогон не запускался.

## Что сделано

- [`tools/wake-training`](../tools/wake-training/README.md): локальный импорт
  проверенного WAV-корпуса и два шаблона конфигурации tiny DNN для RU/EN.
  Python stdlib, без записи, сети, установки пакетов или запуска Fono.
- Общий валидатор W-02 проверяет SHA256, разрешения, аннотации и отсутствие
  общих audio/speaker/session/source groups между train/dev/test.
  В upstream `*_test` попадает только Fono dev. Настоящий test исключён.
- Точные положительные окна; слишком длинная фраза вызывает ошибку.
  Негативные окна сохраняют все исходные сэмплы, включая остаток.
  Фоновые примеры выделяются в собственный класс. RMS не используется.
- Свежий каталог без перезаписи, проверка WAV перед извлечением,
  воспроизводимые выходные хэши и provenance. Финальный manifest записывается
  последним; незаконченный каталог без него непригоден. Shareable manifest
  не содержит входных путей, имён людей или source/license строк.
- Подготовлены процедура фиксации environment/seed/resource budget,
  правила итераций hard negatives только из train/dev и требования будущего
  downloadable artifact manifest/registry. Фиктивного артефакта/SHA нет.
- Проверены upstream-кандидаты, ограничения внесены в
  [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md). Лицензия обучающего кода
  отделена от лицензий embedding, TTS, голосов и данных. У выбранного для
  изучения LiveKit commit найдено несовпадение аргументов feature extraction
  и CLI; это дополнительный вопрос рабочего pin, не отладка Fono.
- Файловые тесты подготовки добавлены в CI без моделей и микрофона.

Конфиги — шаблоны интерфейса upstream, их совместимость полным реальным
pipeline пока не подтверждена. Воспроизводима **подготовка WAV**, а не
ещё не выполненное обучение. Число обученных кандидатов и hard-negative
итераций — **0**. Приложение и его default features не менялись.

## Проверки и существующие данные

Результаты — [validation JSON](evidence/fono144-validation.json).
Новые файловые тесты — **11/11**, включая отсутствие test-утечки,
извлечение границ, сохранение остатка, запрет обрезки целевой фразы,
invalid permissions, отказ от перезаписи, изменение WAV между проверкой
и чтением, отсутствие личных строк в отчёте и повторяемость выходных байтов.

Общий валидатор W-02 — **14/14**; release/CI scripts — **48/48**,
отдельные workflow contracts — **8/8**. Format, docs, version и diff checks
прошли. Первая попытка release tests внутри Windows-песочницы не могла
создать временные Git fixtures; повтор вне неё прошёл. 20 cache tests
владельца проверены вместе с рабочим деревом, их изменения в коммит не входят.

[`inspect` существующего FONO-143 smoke](evidence/fono144-data-readiness.json)
вернул ожидаемый **код 2 / data_ready=false**: все четыре клипа относятся
к test, для обучения исключены; разрешённого train/dev входа в этом наборе
нет. `training_started=false`, `qualified=false`. Декодирование повторно
не запускалось, новых замеров качества/подборов не выполнялось.

UI/native runtime не менялись; их тесты и browser/manual сценарии заново
не запускались. Это не новая проверка Rust, голоса или Windows.

## Что осталось

1. Разрешённый train/dev корпус и независимый реальный W-02 test, фактическая
   проверка прав. Записи личного голоса владельца сейчас не требуются.
2. Утвердить точные frontend/embedding/TTS/voice/data artifacts и notices,
   рабочий upstream pin, lock зависимостей и ограниченный бюджет обучения.
3. Выполнить synthesis при необходимости, augmentation/features, train,
   ONNX export/parity, несколько измеренных hard-negative раундов. Добавить
   streaming classifier score в W-02; его текущий backend — ASR baseline.
4. Заморозить dev operating point и проверить реальный held-out test:
   recall ≥95% quiet / ≥90% noisy, ≤0,5 FA/h, p95 ≤800 мс,
   idle CPU <1% одного ядра. Критерии не ослаблены.
5. Для существующего прошедшего gate артефакта — SHA256, лицензия и registry
   entry. Публикация отдельно. FONO-145 остаётся `blocked`, WakeWord выключен.

На этом ограниченный проход закончен. Дополнительные эксперименты без этих
входов не дадут приёмку и не подменяются синтетическими успехами.
