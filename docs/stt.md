# STT, аудио и GPU

Общий движок распознавания находится в `crates/fono-stt`.
Desktop и Fono Server внедряют пути ресурсов, activity guards, progress/readiness
и проверяемые GPU package handles через `SttEnvironment`.

## Аудио и операция

Один AudioHub владеет физическим потоком выбранного устройства.
Поток создаётся и завершается на owner thread; потребители получают
ограниченные RAII-подписки. Callback преобразует frames и передаёт их
в ограниченные очереди, без STT, сетевых запросов и тяжёлой обработки.

Внутренний формат диктовки — PCM i16, моно, 16 кГц. Запись, pre-roll и очереди
ограничены; ошибки устройства и потеря пакетов отражаются явно.
Речевой VAD отсекает отсутствие речи до STT, архива и вставки.
RMS, чёрный список фраз или запрет всех коротких слов VAD не заменяют.

Движок возвращает фактическую модель и устройство. Отмена проверяется
до и после native работы; результат отменённой операции не публикуется.
Admission permit и lease принадлежат фактической работе до её окончания,
а не только ожидающему IPC/HTTP. Основные правила — в [архитектуре](architecture.md).

## Backends и ускорение

| Вариант        | Исполнение                                                     |
| -------------- | -------------------------------------------------------------- |
| Whisper CPU    | Embedded Rust/whisper-rs в процессе хоста                      |
| Whisper Vulkan | Отдельный C++/CMake worker                                     |
| Whisper CUDA   | Отдельный Rust worker из дополнительного пакета/образа         |
| Offline-модели | Sherpa при включённой `offline-stt` и установленных артефактах |
| Fono Server    | RemoteRecognizer с discovery, compatibility и отменой по HTTP  |

Auto использует Vulkan на подходящей физической дискретной видеокарте.
При отсутствии подходящего GPU backend доступен CPU. Установка CUDA-пакета
не меняет Auto; CUDA выбирается явно. Ошибка выбранного GPU, загрузки модели,
прогрева или нехватка памяти возвращается пользователю и не маскируется
незаметным переходом на CPU.

Базовые поставки Desktop и сервера содержат Vulkan и CPU.
CUDA Windows-пакет и CUDA Docker-образ отделены от базы. Обычные Cargo features
обеспечивают CPU/STT/VAD; готовый GPU worker подключается ресурсами.
Явные build features `cuda` и `vulkan` сохраняются для специальных сборок.

Vulkan worker проверяет класс и возможности GPU, фиксирует физический индекс
и прогревает модель до `model_loaded`. Прогрев не пишет историю и не вставляет
текст. Кэш шейдеров остаётся в пользовательском cache; Compose сохраняет его
отдельным volume. Возможности другой ОС или модели не выводятся из наличия
одного runtime.

## Worker contract и восстановление

GPU worker изолирует native crash и крупные библиотеки от UI.
`fono-stt-protocol` задаёт handshake, capabilities, request/operation IDs,
ограниченные frames, cancel, health и shutdown. Supervisor владеет процессом,
stdio и cleanup; поколение сессии защищает новый worker от старых ответов.
После сбоя действует ограниченное восстановление выбранной модели.

C++ Vulkan и Rust CUDA поддерживаются как отдельные реализации.
`scripts/worker-contract.mjs` проверяет общий исполняемый process contract.
Изменения протокола, capabilities и декодирования требуют обновления обеих
реализаций и пересборки. Различия whisper.cpp и Greedy/fallback не исчезают
из-за совпадения handshake. Быстрый Rust CPU/CUDA использует Greedy
`best_of=1`, C++ Vulkan сохраняет vendor Greedy `best_of=5`.
Точный режим использует Beam Search 5 и vendor fallback `greedy.best_of=-1`.
Выравнивание этих параметров требует отдельной проверки распознавания.

Отмена активного запроса не должна штатно уничтожать прогретую модель.
При сбое транспорта или нарушении протокола supervisor завершает и убирает
собственный процесс. Pending cleanup остаётся наблюдаемым и блокирует новую
загрузку до подтверждённого освобождения ресурсов. Intentional unload,
adaptive release и shutdown не запускают crash recovery.

## Пул и очереди

ModelPool владеет слотами по ModelId, ограничивает их количество и может
применять оценочный лимит памяти. RAII-заём удерживает модель во время работы.
LRU вытесняет только неактивные модели; worker в cleanup продолжает занимать
ёмкость. Повторная привязка ModelId к другой конфигурации отклоняется.

DeviceScheduler имеет независимые полосы CPU, CUDA-устройств и Vulkan.
Interactive получает приоритет над batch на границе ограниченного окна.
Для уступки отменяется текущее batch-окно, задание продолжает с checkpoint.
Desktop отдельно сохраняет резервирование записи и Stop в своём SttScheduler.

RemoteRecognizer проверяет API/capabilities и выбранную серверную модель
до отправки аудио. Он не загружает сохранённые локальные веса.
Локальный резерв включается явно; ошибка remote не разрешает неявно менять
источник. Подробнее — [удалённое распознавание](remote-recognizer.md).

## Память

`gpu_model_residency` относится только к локальной Whisper-модели.
`resident` удерживает её; `adaptive` освобождает idle-модель после устойчивого
давления памяти. Активная операция, очередь, pending и cleanup блокируют
выгрузку. Следующий запрос использует обычный `ensure_loaded`;
перезагрузка по таймеру и принудительная смена ускорения не нужны.

Windows-монитор сопоставляет глобальные PDH GPU Adapter Memory с DXGI LUID.
Поддерживается одна аппаратная GPU с выделенной памятью от 1 ГБ.
Неизвестное измерение остаётся неизвестным. Расход основного процесса,
другой GPU или бюджет `VK_EXT_memory_budget` текущего worker не заменяют
глобальную свободную VRAM. Remote STT не переносит на сервер WebView,
VAD, Лиру или сторонние LLM.

## Wake и границы проверки качества

Legacy WakeWord исключён из обычного графа и выключен в Rust/V3.
Фраза и профиль сохраняются, мастер произвольной фразы недоступен.
Режим «На лету» скрыт; входящий `live` становится `standard`.

Фиксированная «Привет, Лира» — отдельная opt-in Windows beta:
AudioHub → CNN proposal → T-one CTC verifier → обычная диктовка.
Release проверяет комплект runtime, модели и SHA256 до открытия микрофона;
системный Python и личные dev-образцы не служат release runtime.
Пользователь начинает говорить после сигнала готовности.

Производные аудио и расшифровки FLEURS сохраняют CC-BY-4.0 и атрибуцию
The Google and HuggingFace Datasets Authors (2022). MIT-лицензия кода Fono
не меняет лицензию этих данных. Производный resampled replay не равен
нативному захвату микрофона; фиксированный регрессионный корпус не становится
независимым holdout после повторных запусков или настройки на его результатах.

Исторические model-quality fixtures сохраняют происхождение,
условия использования и границы корпуса. Replay и protocol smoke
не подтверждают личный голос, длительные false activations, recall,
активную отмену inference или весь парк GPU. Методики и ограничения —
в [тестировании](testing.md); лицензии остаются рядом с ресурсами.
