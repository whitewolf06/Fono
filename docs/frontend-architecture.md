# Архитектура фронтенда Fono

Единственный рабочий интерфейс находится в `src/v3/`: Vue 3, TypeScript,
Vue Router 4 и WhiteUI 0.6.0. Версия приложения берётся из `package.json`.
Исходники прежних интерфейсов доступны в истории Git.

## Запуск и маршруты

`index.html` и `v3.html` запускают `src/v3/main.ts`. Основное окно Tauri
открывает `v3.html`, индикатор — `v3.html?view=overlay`.

- `npm run dev:ui` → `http://127.0.0.1:1420/v3.html` — браузер с mock runtime.
- `npm run dev:desktop:v3` — Tauri с настоящими устройствами, настройками,
  историей, STT, LLM и API-сервисом.

Composition root выбирает native runtime только внутри Tauri. В браузере
используются демонстрационные данные; микрофон, глобальная клавиша и вставка
в Windows там не работают. Прослушивание образца в desktop запускается
отдельным действием пользователя.

Hash-маршруты задаются в `src/v3/app/router.ts`. Прямые ссылки и кнопка
«Назад» используют тот же router.

| Маршрут                           | Содержимое                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------- |
| `#/`                              | Главная, быстрые настройки, запись и последний текст сессии                         |
| `#/history`                       | Поиск, фильтры, статистика и архив диктовок                                         |
| `#/trainer`                       | Речевые привычки, периоды, длительности и разбор диктовок                           |
| `#/commands`                      | Поддерживаемые команды, горячая клавиша и приложения                                |
| `#/api/tasks`, `#/api/connection` | Очередь API и сведения о подключении                                                |
| `#/settings/{section}`            | `general`, `audio`, `activation`, `processing`, `overlay`, `privacy`, `diagnostics` |
| `#/releases`                      | История версий с разделением разработки и публичных выпусков                        |
| `#/updates`                       | Установленная версия, проверка и явная установка обновления                         |
| `#/onboarding`                    | Первоначальная настройка: пять шагов, возврат и продолжение позже                   |
| `#/overlay`                       | Предпросмотр подробного и компактного индикатора                                    |
| `#/scenarios`                     | Демонстрационные состояния и сброс mock; в desktop недоступен                       |

## Слои и порты

```text
src/v3/
  app/                          # composition roots, router и оболочка
  features/                     # фичи со своими слоями
  shared/domain/                # общие порты и чистые правила
  shared/application/           # общая координация
  shared/infrastructure/native/ # IPC, события и транспортные DTO
  shared/presentation/          # общие компоненты
  styles/                       # токены и общие стили
```

- `domain`: типы и чистые преобразования без Vue, Tauri и браузерных API.
- `application`: сценарии, состояние и координация через внедрённые порты.
- `infrastructure`: адаптеры Tauri IPC, событий, clipboard, storage и focus.
- `presentation`: Vue-компоненты, композиция и отображение.

`src/v3/main.ts` выбирает runtime и внедряет порты. `app/mockWorkspace.ts`
и `app/nativeWorkspace.ts` собирают адаптеры и общее реактивное состояние.
Контракты UI-портов находятся в `shared/domain/contracts.ts`, транспортные
DTO Rust — в `shared/infrastructure/native/ipcTypes.ts`. Вызовы Tauri
и подписки изолированы в `shared/infrastructure/native/ipc.ts`.

Компоненты не вызывают IPC, browser storage или window API напрямую.
Rust управляет аудио, моделью, workers, горячими клавишами, вставкой
и жизненным циклом индикатора. Фичи используют публичные API друг друга;
общие элементы появляются после второго потребителя. Сложные правила
остаются вне шаблонов, файлы около 300 строк разделяются по ответственности.

## Стили, настройки и данные

Порядок стилей: WhiteUI reset → base → тема → Fono. Тема устанавливается
на `html`, чтобы Teleport-диалоги и списки наследовали её. Цвета, размеры,
отступы и движение задаются в `styles/tokens.css`; цветовые роли ссылаются
на `--wl-*` UI Kit.

Browser mock сохраняет только разрешённые демонстрационные настройки.
История, тексты, системные промпты, ключи и записи словаря остаются в памяти.
Native runtime сохраняет настройки и историю через Rust, ключи подключений —
через Windows Credential Manager.

Переключатели применяются сразу: ожидание блокирует повторное действие,
ошибка возвращает подтверждённое значение. Остальные параметры используют
общий черновик, сохранение, отмену и защиту несохранённых правок.

Последний результат сессии хранится отдельно от архива. Редактирование
и повторная обработка меняют текущий черновик; копируется отображаемый
вариант. Архив автоматически не перезаписывается, поздний ответ ИИ
не заменяет новую диктовку. Сохранение исходных расшифровок для тренера
требует согласия пользователя.

## Диктовка и индикатор

Доступна классическая диктовка: `hold` записывает при удержании,
`toggle` — между двумя нажатиями. Сохранённый `live` нормализуется
в `standard`; поэтапный вывод скрыт. WakeWord временно недоступен,
включение и тесты заблокированы. Фраза и профиль сохраняются для доработки.
Ограничения ядра описаны в [architecture.md](architecture.md).

Общий `features/overlay/presentation/OverlayIndicator.vue` используется
в native overlay и браузерном предпросмотре `#/overlay`. Native overlay
сохраняет `focus: false` и `focusable: false`.

Кнопка записи на главной возвращает текст в редактор Fono. Горячая клавиша
завершает запись с вставкой в исходное поле. Принятие в overlay завершает
запись без вставки: текст остаётся для копирования или закрытия.
Успешное копирование закрывает индикатор; ошибка оставляет текст доступным.
Смена поля и частичная вставка блокируют повторную отправку.

Быстрые настройки индикатора включены по умолчанию. В режиме `toggle`
обработку, стиль и перевод можно менять во время записи. Выбор сохраняется
для следующих диктовок. Скрытие быстрых настроек сохраняет предпочтения.

`update_overlay_processing_choice` получает `sessionId: null` при ожидании
новой записи, идентификатор активной сессии — при записи или ожидании действия.
Выбор применяется к этой сессии после успешного сохранения. Начавшаяся
обработка и вставка не меняются. Перед Stop индикатор ждёт сохранения
последнего выбора; ошибка возвращает подтверждённое значение.

Ручная обработка и ошибка ИИ удерживают исходный текст до решения
пользователя. Запоздалые ответы привязаны к своей операции, принятую
сессию архивируют один раз.

## Промпты и обновления

Для `clean`, `format`, `task` и `formal` доступны встроенные или собственные
системные промпты. Проверка текстом и пробная диктовка используют отдельный
порт, черновой промпт и сохранённое подключение с моделью. Они не меняют
историю или последний результат и не вставляют текст в Windows.

`raw` без перевода возвращает исходный текст без LLM; с переводом вызывает
только перевод. Выключенная обработка не вызывает ИИ даже при сохранённом
языке. Общие правила промптов и нативный lifecycle описаны
в [architecture.md](architecture.md).

Проверка обновлений доступна вручную. Автоматическая проверка включается
пользователем и выполняется при запуске и затем раз в сутки с общим
ограничением 24 часа. Загрузка и установка требуют явного действия
и подтверждения. Активные операции и несохранённые настройки блокируют
установку. В браузере раздел демонстрационный, без GitHub-запросов
и установки.

## Проверки и приёмка

`npm run typecheck:v3`, `npm run lint`, `npm run test:v3` (также `test:ui`),
`npm run test:release`, `npm run format:check`, `npm run build`,
`npm run version:check`. После нативных изменений выполняются Rust-тесты
через `scripts/test-native.ps1`. UI-тесты находятся в `tests/ui/`.

Браузерную приёмку проводят при 720×560, 900×720 и 1440×900: маршруты,
длинный текст и названия моделей, клавиатура и фокус диалогов, сохранение
и ошибки, история, тренер, команды, очередь, onboarding и индикатор.
Результат конкретного прогона относится к проверенной версии.

Пользователь самостоятельно проверяет приложение, голос, глобальные
клавиши, внешнюю вставку и установку. Агент не управляет его приложением
ради UI-проверки. Browser mock, unit tests и сборка не заменяют приёмку
установленной версии и чистой Windows.
