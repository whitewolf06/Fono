# Лёгкий онлайн-установщик Fono

`FonoSetup.exe` — самостоятельный Windows x64 EXE. Он скачивает полный
подписанный NSIS-пакет из публичного канала Fono и открывает обычный мастер
установки. Node.js и WebView2 для самого загрузчика не нужны. Требования
основного приложения, включая WebView2 и GPU-драйверы, остаются прежними.
Полный установщик сохраняется как вариант установки без докачивания.

## Как работает

1. Пользователь нажимает «Установить». Проверяется `latest.json` в
   `whitewolf06/fono` на GitHub Releases.
2. Пакет скачивается с прогрессом и объёмом загрузки. При отмене частичная
   загрузка остаётся в `%LOCALAPPDATA%\FonoSetup\cache`.
3. При повторе загрузчик проверяет возможность докачивания. Если сервер
   больше не подтверждает тот же файл, загрузка начинается заново.
4. Проверяются Minisign-подпись, подписанная версия и отсутствие отката
   относительно установленного Fono. Учитываются NSIS и MSI установки.
5. Только после проверки запускается штатный NSIS через UAC. Отмена в UAC
   или мастере не считается успешной установкой.

Версия загрузчика берётся из `package.json`; версия устанавливаемого Fono —
из `latest.json` публичного канала. Эти версии могут различаться: сборка
загрузчика не меняет manifest и не публикует приложение. Загрузчик уменьшает
первоначальную загрузку; полный NSIS-пакет всё равно скачивается перед установкой.
Модели распознавания скачиваются отдельно.

## Проверки и границы

- Публичный канал и ключ встроены из `src-tauri/update-channel.json`.
  Произвольные endpoint и ключи через аргументы не принимаются.
- Допускаются HTTPS-ссылки на релизы Fono и их официальный GitHub asset host.
  Файл должен называться `Fono_<version>_x64-setup.exe` и соответствовать
  версии в manifest и подписанном trusted comment.
- Поддерживаются подписи Minisign `Ed`/`ED`; минимальный допустимый выпуск —
  0.6.12 (`MINIMUM_SUPPORTED_VERSION` в `tools/fono-setup/src/manifest.rs`).
  Недостоверные сведения об установленной версии блокируют запуск.
- Общий предел пакета — 512 MiB; сетевые запросы ограничены по времени.
  При зависшем запросе отмена может занять до 20 секунд. Продолжающаяся
  загрузка ограничена 30 минутами; временные ошибки повторяются.
- Кэш блокируется от параллельной установки. Reparse points и hardlinks
  отклоняются; проверенный EXE защищён от изменения до выхода NSIS.
- Подпись скачанного пакета не является Windows Authenticode-подписью
  загрузчика. Статус Authenticode проверяется отдельно для поставляемого EXE.

## Сборка

```powershell
npm run build:setup
```

Нужны PowerShell 7, закреплённый в `tools/fono-setup/rust-toolchain.toml` Rust,
MSVC и Windows SDK.
`tools/fono-setup` — отдельный Cargo workspace со статическим CRT.
Параметры сборки основного Fono и Whisper не меняются.

Команда выполняет Rust format/test/strict Clippy и release build. Результат:

- `build/online-installer/FonoSetup.exe`;
- `build/online-installer/FonoSetup.exe.sha256`;
- `build/online-installer/build-info.json` с версией, размером, SHA-256 и ревизией.

`./scripts/build-online-installer.ps1 -SkipChecks` предназначен для повторной
упаковки после уже пройденных проверок. CI проверяет загрузчик отдельным
Windows job без приватного UI Kit, сохранения artifacts и установки; устройство
workflow описано в [fono-ci-updates.md](fono-ci-updates.md).
Публикация файла в Releases и изменение ссылки на сайте — отдельный этап
после ручной проверки.

## Диагностика без установки

Аргументы обрабатываются до создания окна. Ни одна команда ниже не запускает
NSIS, Fono или UAC:

```powershell
./build/online-installer/FonoSetup.exe --check-only
./build/online-installer/FonoSetup.exe --download-only --cache-dir C:\Temp\FonoSetup-test
# Пример для имеющегося пакета 0.6.12; подставьте его фактическую версию и пути:
./build/online-installer/FonoSetup.exe --verify-package C:\path\Fono_0.6.12_x64-setup.exe --signature-file C:\path\Fono_0.6.12_x64-setup.exe.sig --version 0.6.12
```

`--check-only` подтверждает доступность manifest, но не проверяет подпись
пакета. `--download-only` скачивает и проверяет пакет, оставляя его в кэше.
`--verify-package` проверяет уже имеющийся файл встроенным публичным ключом.
Результат выводится как JSON; ошибки завершаются ненулевым exit code.

## Ручная приёмка

Пользователь самостоятельно проверяет:

1. Окно при масштабах Windows 100/125/150/200%, Tab, Enter, Escape.
2. Отмену загрузки и продолжение после повторного открытия; offline и повтор.
3. Отмену UAC, затем обычную установку с сохранением настроек и истории.
4. Блокировку более старого пакета поверх более нового NSIS/MSI Fono.
5. Установку на чистой Windows без окружения разработчика — отложенный этап.

Автоматические тесты, проверка подписи и сборка EXE не подтверждают UAC,
внешний мастер установки и работу установленного приложения.
