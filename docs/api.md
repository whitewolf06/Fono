# API Fono

У Fono два HTTP-интерфейса. Самостоятельный Fono Server обслуживает внешних потребителей. Desktop API доступен на loopback запущенного Windows-приложения и использует его локальный STT. Один API не является автоматическим proxy другого.

|            | Fono Server                                              | Desktop API                                            |
| ---------- | -------------------------------------------------------- | ------------------------------------------------------ |
| Контракт   | API v2, URI маршрутов /v1/                               | Локальный совместимый API                              |
| Назначение | Короткие запросы, фоновые задания, discovery, управление | Локальные файловые задания                             |
| Ключ       | recognize для потребителя, admin для управления          | Отдельный токен в «Сервис → API»                       |
| Схема      | [Server OpenAPI](../apps/fono-server/openapi.json)       | [Desktop OpenAPI](../crates/fono-service/openapi.json) |

Схемы доступны и через авторизованные /openapi.json и /docs соответствующего сервиса. Панель /panel/ позволяет отправить пробный файл. Версия приложения, API v2, worker protocol 4 и формат результатов заданий 1 — разные номера. Ограничения и возможности сверяйте с работающей версией, схемой и discovery.

## Подключить потребителя

Администратор создаёт recognition-ключ в [панели сервера](server.md). Потребитель обращается прямо к серверу, без Desktop и SSH-учётных данных:

```dotenv
FONO_HOST=http://127.0.0.1:17832
FONO_TOKEN=<application-key>
```

Этот origin подходит процессу на том же хосте. Для другой машины нужен защищённый endpoint, для контейнера — адрес из его сети. Приложение должно само поддерживать эти переменные или сопоставлять их настройкам. Копирование .env не настраивает сеть.

Во всех запросах ниже используется Authorization: Bearer. Публичный /healthz возвращает только готовность default-модели: 200 или 503. Статическая оболочка панели публична, данные закрыты.

GET /v1/health, /v1/capabilities, /v1/models, документация и задания требуют bearer. Capabilities сообщают API/protocol, форматы, лимиты и feature gates. Inventory содержит публичные ID и состояния моделей без локальных путей. present_unverified отражает layout/размер, а не свежую SHA-проверку; загрузка проверяет артефакты.

## Короткое распознавание

```sh
curl --fail-with-body \
  -H "Authorization: Bearer $FONO_TOKEN" \
  -H 'Content-Type: audio/wav' \
  --data-binary @speech.wav \
  "$FONO_HOST/v1/recognize?language=ru&timestamps=segments"
```

POST /v1/recognize принимает complete WAV, Ogg/Opus или audio/L16;rate=16000;channels=1. L16 — signed 16-bit **big-endian** mono PCM 16 kHz; порядок WAV определяет декодер.

Query выбирает установленный model, language, timestamps, decoding и priority, если их поддерживает модель. Пропущенная модель означает default сервера. X-Fono-Glossary — base64url UTF-8 JSON-массив строк: до 4096 байт JSON, 32 терминов и 896 байт терминов в native prompt. Неподдержанные параметры не игнорируются молча.

Ответ содержит фактические модель/backend, длительности, request ID и доступные timestamps. Native timestamps используют миллисекунды; неизвестные внутренние времена не выдумываются. Разрыв синхронного запроса отменяет работу, но ресурсы удерживаются до её фактического завершения. После неопределённого результата аудио не следует автоматически отправлять повторно.

## Файлы и задания

```sh
curl --fail-with-body \
  -H "Authorization: Bearer $FONO_TOKEN" \
  -F 'audio=@speech.wav' -F 'language=ru' \
  "$FONO_HOST/v1/transcriptions"
```

Успех возвращает 202 и ID задания. Загрузочная форма принимает multipart audio, необязательные language и model. Форматы: WAV, MP3, FLAC, Ogg/Vorbis и Ogg/Opus в пределах схемы.

| Маршрут                                 | Назначение                         |
| --------------------------------------- | ---------------------------------- |
| GET /v1/transcription-jobs/{id}         | Состояние и готовый результат      |
| POST /v1/transcription-jobs/{id}/cancel | Явная отмена                       |
| POST /v1/transcription-jobs             | Низкоуровневая отправка PCM в JSON |

Фоновые задания независимы от подключения polling-клиента. Очередь ограничена глобально и на токен; interactive получает приоритет на следующей границе batch-окна.

## OpenAI-совместимый маршрут Server

POST /v1/audio/transcriptions принимает multipart file, обязательный публичный model и поддержанные language, prompt, response_format, timestamp_granularities[] и temperature.

Форматы результата: json, text, srt, vtt, verbose_json. В verbose JSON используются секунды и только запрошенные timestamps; segments — default. Temperature 0–1 принимается без изменения декодирования. Initial prompt ограничен 224 UTF-8 байтами и поддержкой модели. Точные правила находятся в Server OpenAPI.

Это контракт самого Fono Server. Он не означает поддержку стороннего OpenAI-сервера Windows-клиентом. Пример запроса или SDK не является подтверждением проверки конкретной версии стороннего SDK.

## Управление, ошибки и ограничения

Admin дополнительно получает GET/POST /v1/clients, DELETE /v1/clients/{name}, /metrics и model load/unload. Создание клиента возвращает секрет один раз, не позволяет выдать admin scope и не отзывает admin-ключи. После неопределённого create обновите список и при необходимости отзовите ключ; не повторяйте административную запись автоматически.

POST /v1/models/{id}/load и /unload требуют models.client_model_load = true. Они не скачивают веса; активная модель и default защищены от выгрузки. /metrics требует metrics.enabled = true. Эти возможности выключены по умолчанию.

Основные HTTP-статусы: 400 неверный запрос, 401 отсутствующий/отозванный токен, 403 scope/gate, 404 модель, 408 deadline тела, 413 размер/длительность, 415 формат, 429 quota/очередь, 503 неготовность. Ответ содержит безопасный код и request ID; OpenAI-ошибки используют отдельную схему. Уважайте Retry-After. Лимит чтения тела отличается от времени распознавания. Не логируйте bearer, аудио и текст.

## Локальный Desktop API

Сервис слушает 127.0.0.1:17832; до старта приложения порт можно изменить через FONO_API_PORT. Скопируйте локальный токен из «Сервис → API» и используйте Desktop OpenAPI. Доступны multipart-загрузка, polling и cancel. Передача локального пути вместо загрузки файла не разрешается.

При remote source локальные API-задания явно отклоняются и не запускают скрытую локальную модель. Файловый экран самого приложения уже поддерживает серверные batch-задания — это другой маршрут. Подключение Windows описано в [удалённом распознавании](remote-recognizer.md), сеть и TLS — в [сервере](server.md).
