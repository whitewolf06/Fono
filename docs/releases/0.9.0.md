# Fono 0.9.0 — серверный API и удалённое распознавание

Кандидат выпуска, подготовка начата 12 ноября 2026 года. Эта страница описывает
состав версии и не означает публикацию. Доступные установщики и образы нужно
проверять в [GitHub Releases](https://github.com/whitewolf06/Fono/releases).
До отдельной публикации последним публичным выпуском остаётся 0.8.0.

## Что входит

- **Fono Server для Ubuntu x86_64:** отдельный headless-сервер без Tauri,
  микрофона и рабочего стола. HTTP API v2, синхронное распознавание, очередь
  заданий, отмена, управление моделями, CPU и CUDA worker, health/readiness,
  расширенный `doctor`, TLS с обновлением сертификатов и ограничение частоты
  запросов. Контракт — в [документации API](../server-api.md).
- **Встроенная веб-панель:** вход по токену, статус, модели, очередь,
  документация и пробный запрос с аудиофайлом. Администратор создаёт и отзывает
  отдельные ключи приложений, копирует host/token для `.env`. Ключ показывается
  один раз, сервер хранит salted digests. Подробнее —
  [панель](../server-panel.md) и [подключение приложений](../server-clients.md).
- **Удалённое распознавание в Windows:** выбор источника, HTTPS или SSH из
  интерфейса, явное доверие ключу сервера, безопасное хранение API-токена,
  проверка доступности и совместимости, выбор серверной модели. Настройка
  выполняется без ручного запуска SSH-туннеля.
- **Восстановление после сбоя:** сохранение текущей записи, явный повтор и
  выбранная политика локального резерва на CPU. История и диагностика учитывают
  фактический источник, модель и время конкретной сессии. Обработка файлов
  также использует выбранный серверный источник.
- **Компактный индикатор:** волна и статус во время обработки, без показа
  промежуточной расшифровки при обычной автоматической вставке. При потере цели
  текст остаётся для копирования с предпросмотром до двух строк. Лира beta
  остаётся доступной отдельно и включается пользователем.

## Репозиторий и совместимость

Один репозиторий содержит `src/v3/` и `src-tauri/` для Desktop,
`apps/fono-server/` для сервера, общие `crates/` и Docker-поставку в
`packaging/docker/`. Rust workspace, lockfile и toolchain общие. Версия
приложения берётся из корневого `package.json`; внутренние crates имеют свои
версии и не обязаны называться 0.9.0.

Windows проверяет API и возможности сервера, а не равенство номеров приложений.
Нужны API версии не ниже 2 и возможности выбранной модели. Worker protocol 4 —
внутренний контракт worker, его не нужно указывать в настройках подключения.
Другие приложения могут обращаться к серверному API напрямую без Windows Fono.
Проксирование серверных запросов через локальный API Windows в этот выпуск
не входит. См. [контракт клиента](../remote-recognizer.md).

| Артефакт                            | Назначение                                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------------- |
| `Fono_0.9.0_x64-setup.exe` и `.sig` | Полный Windows x64 NSIS installer и подпись updater                                          |
| `Fono_0.9.0_x64_en-US.msi` и `.sig` | Альтернативный полный MSI installer и подпись updater                                        |
| `FonoSetup.exe`                     | Онлайн-загрузчик текущего публичного подписанного канала                                     |
| `latest.json` и контрольные суммы   | Подписанная версия и адрес полного installer для обновлений                                  |
| Отдельный подписанный CUDA-пакет    | Дополнительный локальный NVIDIA backend Windows; для серверного распознавания на ПК не нужен |
| `fono-server:0.9.0-cuda`            | Локально собранный Docker-образ Ubuntu API Server с CPU и CUDA                               |

После отдельной публикации проверенный серверный образ может быть доступен как
`ghcr.io/whitewolf06/fono-server:0.9.0-cuda`. Локальная сборка не означает его
загрузку в реестр. Docker-архив, подготовленный вместе с выпуском, загружается
через `docker load --input <archive>`; конфигурация, модели и credentials
создаются отдельно по [руководству сервера](../server.md).

Подпись updater проверяется Fono и загрузчиком; она не является сертификатом
Windows Authenticode. Установщики не запускаются автоматически. До публикации
канала онлайн-загрузчик продолжает получать предыдущий публичный выпуск.

## Обновление и первая настройка

Существующие Windows-профили сохраняют локальный источник. Подключение к серверу
включается пользователем; прежние локальные модель и ускорение сохраняются.
Серверный режим не загружает локальные веса распознавания. CPU-резерв требует
отдельной локальной модели и выбранной политики. Аудио серверной диктовки
отправляется настроенному Fono Server; LLM-подключение имеет отдельные настройки.

Начните с [руководства Windows](../user-guide.md),
[развёртывания Ubuntu](../server.md) и [получения ключа](../server-clients.md).
При обновлении старого сервера раздел credentials должен быть доступен процессу
на запись, чтобы веб-панель могла выдавать и отзывать ключи. Не заменяйте
существующие модели, настройки и credentials демонстрационными файлами.

## Проверка перед публикацией

Для Windows GPU-сборки из свежего checkout нужны исходники Vulkan worker:

```sh
git submodule update --init --recursive
```

Workflow подписанной Windows-сборки получает submodules при checkout и
проверяет, что встроенная серверная панель соответствует исходникам.
Windows CUDA worker по умолчанию собирается для SM 75, 80, 86, 89, 90, 100
и 120. Смена матрицы обновляет только native-зависимость в выделенном
worker-кэше. Параметр `-CudaArchitectures` предназначен для явных локальных
сборок; оптимизация под одну видеокарту не подходит для общего дистрибутива.

Локальные результаты кандидата сохраняются в `build/release-0.9.0/`: команды,
коды завершения, ревизия исходников, контрольные суммы и описание артефактов.
Локальные проверки, GitHub CI, публикация, развёртывание и пользовательская
приёмка учитываются отдельно. Наличие этой страницы не подтверждает их успех.

- Проверить версии, документацию, frontend, release scripts, Rust tests и
  строгий Clippy. Проверить worker handshake, ресурсы Лиры и подписи артефактов.
- Собрать Windows NSIS/MSI и онлайн-загрузчик. Проверить упакованные ресурсы
  без запуска установки и без использования developer Python для Лиры.
- Собрать Docker-образ из согласованного исходного снимка. В сборке выполняются
  нативные серверные тесты; отдельно выполняется CPU API smoke на публичном WAV.
  CPU smoke не подтверждает реальное CUDA-распознавание на конкретной видеокарте.
- Пользователь проверяет финальную установленную сборку: сохранение настроек
  при обновлении, подключение после перезапуска, диктовку, потерю фокуса и
  восстановление после ошибки сервера. Сценарии — [Windows + Server](../qa/remote-stt.md).

## Известные ограничения и дальнейшая работа

Полная приёмка на чистой Windows отложена владельцем. Расширенная матрица
полей ввода, оборудования, GPU-драйверов и длительный аппаратный soak остаются
открытыми; автоматические проверки их не заменяют. Лира остаётся beta с
известной задержкой и незавершённой проверкой независимых голосов. Исходный
строгий критерий PERF-04 не закрыт.

Linux Desktop, macOS, дальнейшее выделение платформенных адаптеров, старый мастер
произвольной wake-фразы и экспериментальный режим «На лету» не включаются
вслед за выпуском сервера. Подробности — [STATUS](../STATUS.md),
[roadmap](../roadmap.md) и [QA](../qa/README.md).
