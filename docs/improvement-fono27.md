# FONO-27 — ручная редактура архивной записи

Дата: 22 октября 2026 года. Исходники v0.7.62, база `7821567` / v0.7.61.
Зависимости выполнены в порядке FONO-36 → FONO-38 → FONO-37:
контракт и вызов, хранение и приватность, интерфейс сравнения.

## Реализация

- В деталях истории появился отдельный редактор. Источник выбирается явно:
  исходная расшифровка, если она сохранена, либо итог диктовки.
- Пять отдельных стилей: «Сохранить стиль», «Лаконично», «Сдержанно»,
  «Дружелюбно», «Живее». Они не меняют обычные processing presets.
- Видны выбранные профиль и модель. По умолчанию используется назначенный
  профиль коррекции, если он существует. Для неполного подключения запуск
  недоступен; endpoint, модель и ключ из renderer не принимаются.
- LLM вызывается только кнопкой. Для облачного подключения перед отправкой
  показывается подтверждение с профилем, моделью и составом передаваемого
  материала. Snapshot конфигурации проверяется до сети и после ответа.
- Ответ становится отдельным вариантом с источником/fingerprint, стилем,
  профилем, моделью, временем и статусом. Оригинал и итог сессии не заменяются,
  внешняя вставка не запускается. Фактическая доставка старых записей
  остаётся `unknown`; неизвестные факты не выдумываются.
- Детерминированный ключ учитывает запись, источник, стиль, ревизию профиля
  и версию промпта. Повтор использует сохранённый вариант без нового запроса.
  При изменении источника/профиля старый вариант отмечается устаревшим.
- SQLite schema 1 → 2 добавляет таблицу вариантов с FK `ON DELETE CASCADE`.
  Они следуют сроку хранения записи. Можно скопировать или удалить отдельный
  вариант; удаление истории убирает связанные варианты. Число сохранённых
  вариантов само по себе не вызывает их удаления.
- Удаление/отзыв исходной расшифровки удаляет производные от неё варианты.
  Варианты от итогового текста следуют обычной политике истории независимо
  от речевой аналитики. Privacy fence и проверка перед commit блокируют
  запоздалую запись после удаления, отмены и изменения источника.
- Фоновая работа держит updater admission lease до фактического завершения,
  даже при потере IPC waiter. Старый Cancel не действует на следующую работу;
  закрытие редактора и shutdown запрашивают отмену.

## Проверки

Результат и границы автоматической проверки:
[validation receipt](evidence/fono27-validation.json).
Native-тесты используют собственные временные SQLite и локальный HTTP stub;
они не запускают Tauri-окна, микрофон, внешнюю вставку или настоящий LLM.

Итоговый прогон: native 656 passed / 0 failed / 7 ignored, V3 376/376,
release/CI contracts 48/48. Typecheck, lint, frontend build, строгий Clippy,
format, version и ссылки документации прошли.

На повторном общем прогоне старый HTTP-fixture проверки FONO-112 не дочитывал
POST перед закрытием соединения, из-за чего Windows мог скрыть ответ 503
за connection reset. Fixture теперь читает весь ограниченный Content-Length;
строгое ожидание HTTP 503 и остальные критерии сохранены.

Проверены migration/reopen, неизменность исходников, дедупликация, пять
разных cache keys, каскадное удаление/очистка, отзыв аналитики, rollback
при отмене перед commit, поздний ответ удалённой записи, смена профиля,
ошибка сервера и запрет облачного запроса без подтверждения. Проверены
typed IPC, UI-поколения, выбор другой записи, отсутствие скрытого запуска,
кэш и память browser mock.

Browser mock прошёл RU/EN на 720×560, 900×720 и 1440×900. Исправлена
обрезка внутренней области WhiteUI Card на узком окне; ширины корня и панели
не превышают доступную область. Проверены пять стилей, явный запуск,
отдельный результат другого стиля и возврат к сохранённому варианту после
выбора другой записи. Снимки остаются в `build/checks/fono27-*.jpg`.
Browser mock явно обозначает демонстрацию, не вызывает ИИ и хранит варианты
только в памяти. Буфер обмена при проверке браузера не использовался.

## Оставшиеся проверки

Desktop dev v0.7.62 собран и запущен с прежним изолированным профилем.
Запуск процесса подтверждён; окно и настоящее подключение проверяет владелец.
В этом профиле облачные Windows credentials недоступны, локальное подключение
можно настроить отдельно.

Реализация готова к ревью, owner acceptance новой функции ещё не получена.
[Короткая desktop-приёмка](qa/history-rewrite.md) проверяет настоящий
настроенный LLM, качество пяти стилей, подтверждение облачной отправки,
копирование и сохранение после полного перезапуска. Неполная настройка
должна объясняться в UI; готовый вариант не имитируется.

Текст запроса ограничен 128 КиБ, общий LLM transport сохраняет свой timeout
и лимит ответа 2048 tokens. Качество конкретной модели и поведение на очень
длинных записях остаются ручной проверкой; оригинал всегда остаётся в истории.

Публикация, installer и установленная Windows-матрица не выполнялись.
WakeWord/«На лету», обычная диктовка, STT и речевой AI-анализ не расширялись.
Отдельные изменения кэшей и PERF-04 владельца в коммит не входят.
