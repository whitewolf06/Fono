# Fono: текущий интерфейс V3

## Запуск

Интерфейс находится в ветке `main`, в `src/v3/`, на Vue 3 + TypeScript и WhiteUI 0.6.0.
Корневой `index.html` и `v3.html` используют один вход `src/v3/main.ts`.
Версия приложения читается из `package.json`.

- `npm run dev:ui` → http://127.0.0.1:1420/#/ — браузерный режим с демонстрационными данными. Адрес http://127.0.0.1:1420/v3.html#/ также работает.
- `npm run dev:desktop:v3` — Tauri с настоящими устройствами, настройками, историей, STT, LLM и API-сервисом.
- Штатный Tauri открывает `v3.html` в основном окне и `v3.html?view=overlay` в плавающем индикаторе.

Нативный runtime выбирается только внутри Tauri. Браузерный макет не обращается к настоящему микрофону, глобальной клавише или установленному приложению. Прослушивание образца в desktop запускается отдельным нажатием пользователя.
Актуальные архитектура и статус — [architecture.md](architecture.md) и [STATUS.md](STATUS.md). [fono-v3-native.md](fono-v3-native.md) описывает исторический этап подключения версии 0.5.16.

## Карта страниц

Hash-маршруты определены в `src/v3/app/router.ts`; прямые ссылки и кнопка «Назад» используют тот же router.

| Маршрут                           | Содержимое                                                                                            |
| --------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `#/`                              | Главная, быстрые настройки, запись и последний текст сессии                                           |
| `#/history`                       | Поиск, фильтры, статистика и архив диктовок                                                           |
| `#/trainer`                       | Речевые привычки, даты, длительности и разбор диктовок; в браузере — демонстрационные наблюдения      |
| `#/commands`                      | Поддерживаемые команды, горячая клавиша и приложения                                                  |
| `#/api/tasks`, `#/api/connection` | Очередь API-сервиса и сведения о подключении                                                          |
| `#/settings/{section}`            | Разделы `general`, `audio`, `activation`, `processing`, `overlay`, `privacy`, `diagnostics`           |
| `#/releases`                      | История версий и описание изменений; записи разработки обозначены отдельно от опубликованных выпусков |
| `#/updates`                       | Установленная версия, проверка и явная установка обновления                                           |
| `#/onboarding`                    | Первоначальная настройка: пять шагов, возврат и продолжение позже                                     |

## Устройство фронтенда

Фичи разделены на `domain`, `application`, `infrastructure`, `presentation`; правила и преобразования находятся вне шаблонов.

- `src/v3/main.ts` выбирает runtime и внедряет порты.
- `app/mockWorkspace.ts` и `app/nativeWorkspace.ts` собирают браузерные и нативные адаптеры, используя общее реактивное состояние приложения.
- `shared/domain/contracts.ts` содержит контракты портов и состояния, используемые несколькими фичами.
- `shared/infrastructure/native/ipcTypes.ts` содержит DTO, соответствующие Rust IPC. Компоненты работают с портами, а не с этими транспортными типами.
- `shared/infrastructure/native/ipc.ts` изолирует вызовы Tauri и подписки на события. Browser clipboard, storage и focus также находятся в адаптерах.
- `styles/tokens.css` задаёт цветовые роли, размеры, отступы и анимации. Тема WhiteUI установлена на `html`, поэтому диалоги и селекты в Teleport получают те же токены.

## Настройки и данные

Только разрешённые демонстрационные настройки переживают перезагрузку браузера. История, тексты, системные промпты, ключи и словарь остаются в памяти. В desktop настройки и история сохраняются через Rust; ключи подключений — через Windows Credential Manager.

Выключатели применяются сразу. Ожидание блокирует повторное действие, ошибка возвращает подтверждённое значение. Остальные параметры используют общий черновик, сохранение, отмену и защиту несохранённых изменений.

Последний результат сессии независим от архива. Редактирование и повторное улучшение меняют текущий черновик; копируется отображаемый вариант. Архивная запись автоматически не перезаписывается, запоздалый ответ ИИ не заменяет новую диктовку. Исходный текст в архиве для речевой аналитики требует согласия пользователя.

Проверка обновлений доступна вручную; автоматическая проверка включается пользователем и выполняется при запуске и затем раз в сутки. Загрузка и установка требуют явного действия и подтверждения. Во время активной операции или при несохранённых настройках установка недоступна. В браузере этот раздел демонстрационный: без GitHub-запросов и установки.

## Диктовка и индикатор

Доступна только классическая диктовка. Экспериментальный режим «На лету» скрыт: сохранённый `live` и входящие настройки приводятся к `standard`. Режим горячей клавиши независим от распознавания: `hold` записывает при удержании, `toggle` — между двумя нажатиями.

WakeWord временно недоступен до доработки качества распознавания. Его карточка и параметры объясняют ограничение; включение и тесты пробуждения заблокированы, сохранённое включение нормализуется в выключенное. Настройка фразы и профиль сохраняются. Обычная диктовка и голосовые команды через горячие клавиши остаются доступны.

Кнопка записи на главной возвращает результат в редактор Fono. Горячая клавиша предназначена для вставки во внешнее поле. Галочка принятия в индикаторе завершает запись **без вставки**: результат остаётся для копирования или закрытия. Копирование закрывает индикатор только после успешного действия. Смена исходного поля и частичная вставка блокируют повторную отправку; доступный результат остаётся для ручного копирования.

Быстрые настройки индикатора включены по умолчанию. В режиме `toggle` обработку, стиль и перевод можно менять во время записи; выбор запоминается для следующих диктовок. Выключение быстрых настроек скрывает элементы, сохраняя предпочтения. Автоматическая обработка начинается после завершения записи, ручная ждёт решения пользователя.

Изменение выбора сохраняется через `update_overlay_processing_choice`: `sessionId: null` допустим при ожидании новой записи, идентификатор активной сессии — при записи или ожидании действия. Уже начавшаяся обработка и вставка не меняются. Перед завершением индикатор дожидается сохранения последнего выбора; ошибка возвращает подтверждённое значение. Нативный индикатор не активирует окно и не забирает фокус внешнего поля.

Для очистки, форматирования, постановки задачи и делового письма доступны встроенные или собственные системные промпты. Проверка текста и тестовая диктовка используют отдельный порт, не меняют последний результат или историю; черновик промпта можно проверить до сохранения. Выбранное подключение и модель должны быть сохранены. «Без изменений» без перевода не вызывает LLM, с переводом — выполняет только перевод. Выключенная обработка не вызывает LLM даже при сохранённом языке.

## Проверки и приёмка

Автоматические проверки: `npm run typecheck:v3`, `npm run lint`, `npm run test:v3`, `npm run test:release`, `npm run build`, `npm run version:check`, `npm run format:check`. После нативных изменений отдельно выполняются Rust-тесты.

Ручная UI-приёмка включает окна 720×560, 900×720, 1440×900, клавиатуру и фокус диалогов, сохранение и ошибки, работу с текстом, архив, тренер, команды, очередь, первоначальную настройку, обновления и индикатор. Результаты конкретных прогонов фиксируются отдельно; [fono-v3-qa.md](fono-v3-qa.md) не следует считать подтверждением более поздних изменений.

Браузерные проверки не подтверждают Rust, микрофон, глобальную клавишу или вставку в Windows. Установщик, проверка установленного приложения и приёмка на чистой Windows — отдельные этапы. Пользователь самостоятельно проверяет окна и голосовые сценарии; агент не управляет приложением ради UI-проверки. Инструкции — [fono-memory-updates-qa.md](fono-memory-updates-qa.md), [overlay-prompts-qa.md](overlay-prompts-qa.md) и [fono-voice-reliability.md](fono-voice-reliability.md).
