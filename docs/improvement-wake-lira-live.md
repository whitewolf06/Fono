# «Привет, Лира»: живое пробуждение в dev — v0.7.73

23 октября 2026 года. Владелец проверил детектор из v0.7.72, не заметил
ложных срабатываний и разрешил перейти к живой проверке, оставив дальнейшую
доводку по результатам использования. Это разрешение на dev, а не закрытие
исходных требований W-02 или публикация WakeWord в обычной сборке.

## Что работает

В «Настройки → Кнопки и активация → Записи для WakeWord» появилась кнопка
**«Включить „Привет, Лира“»**. Доступна также команда в трее. После включения
модели один раз загружаются и прогреваются. Только после этого открывается
настоящий микрофон через общий AudioHub и появляется статус «Слушаю».
При каждом запуске Fono пробуждение выключено; закрытие страницы настроек
не выключает уже включённое ожидание.

Маленький CNN проверяет окно речи с шагом 80 мс. Только его предложение
передаётся точному CTC-подтверждению с прежним lookahead 640 мс. Настройки
моделей, SHA256, порог 0,8 и правило целых слов не менялись. Нового обучения
и подбора порога по личному голосу не было.

Подтверждённая фраза запускает обычную диктовку. Передаются pre-roll и
точный AudioCursor: звук, пришедший во время подтверждения и подготовки
диктовки, подхватывается из AudioHub. Точная фраза пробуждения и контекст
перед ней удаляются из расшифровки. Далее работают общие VAD, автостоп по
паузе, обработка, словарь, история и проверенная вставка в исходное поле.
Безопасный отказ вставки оставляет результат доступным в индикаторе.

Во время другой диктовки детектор приостанавливается. При возобновлении
сбрасываются старые окна, незавершённые предложения и VAD; модели остаются
в памяти. Ответ, начатый до паузы или выключения, не запускает новую запись.
Выключение адресует конкретную сессию и отменяет только её незавершённую
голосовую диктовку. Обычная запись по горячей клавише продолжает работать.

Очереди и протокол ограничены. Потеря пакетов, смена часов потока, задержка
обработки более трёх секунд, пропавший микрофон и отказ worker завершают
ожидание с ошибкой. Выключение работает и при загрузке; процесс, его
потомки и потоки ввода/вывода завершаются до освобождения ресурсов.
Постоянное ожидание блокирует установку обновления до выключения, но не
мешает адаптивному освобождению основной GPU-модели Whisper.

## Проверка владельца — один короткий проход

1. Включить «Привет, Лира», дождаться **«Слушаю»**. Первая подготовка может
   занять около 20 секунд; затем модели не перезагружаются на каждую фразу.
2. Поставить курсор в нужное поле, сказать «Привет, Лира» и сразу надиктовать
   короткую заметку. После паузы должен вставиться текст без обращения.
3. Повторить с короткой паузой после обращения, затем один раз использовать
   привычный Ctrl+Space и снова пробуждение голосом.
4. Выключить пробуждение кнопкой или через трей. Обращение больше не должно
   запускать запись. Если другая запись не идёт, микрофон освобождается.

При проблеме достаточно сообщить фразу, что произошло и на каком шаге.
Большой новый набор записей сейчас не требуется. Агент микрофон не открывал
и пользовательским окном не управлял.

## Проверки реализации

Прошли 402/402 Vue/IPC и затем 19/19 целевых проверок формы, включая
добавленную проверку остановки при загрузке. Rust: 689 passed, 0 failed,
7 штатно ignored. Python: 32/32. Локальные release/CI-контракты: 48/48.
Strict Clippy app/all-targets, typecheck, ESLint и frontend build прошли.
Browser mock проверен на 720×560, 900×720, 1440×900: без JS-ошибок и
горизонтальной прокрутки; микрофон недоступен. Голосовой desktop-сценарий
остаётся ручной проверкой владельца.

Первый общий Rust-запуск попал под запреты sandbox на временные файлы и
loopback HTTP; зависший harness остановлен. Повтор вне sandbox с отдельным
временным каталогом прошёл без изменений требований и тестовых сценариев.
Clippy потребовал сохранить совместимость с MSRV 1.75; исправлено без
изменения поведения. Финальные формат, ссылки и синхронизация версии прошли;
отдельно собран контракт `--no-default-features --features wake-word` через
`cargo check`.

Один процесс warm worker последовательно проверил прежний положительный
пример, прежний сложный негатив и публичный WAV: 1 / 0 / 0 событий. Короткий
положительный файл не содержит продолжения для lookahead, поэтому в этом
протокольном smoke после него проиграны две секунды прежней записи комнаты
с повторением короткого фрагмента. Это не независимая экспозиция и не новый
замер recall. В native используется продолжающийся поток микрофона.

Прогрев под параллельной компиляцией занял 23,313 с. Обработка трёх потоков
после него — 1,062 / 3,344 / 1,922 с на 3,18 / 4,19 / 16,92 с аудио.
Это ускоренный replay с принудительно включённой классификацией речи,
не замер задержки от конца обращения. p95 ≤800 мс и idle CPU этим не
подтверждены. [Агрегаты](evidence/wake-lira-live.json).

## Хвосты

- Ручная приёмка живой диктовки и выключения на микрофоне владельца.
- Два прежних пропуска CNN, независимые голоса и похожие обращения,
  длительные негативы, p95 и idle CPU. Прежний парный результат остаётся
  20/22 положительных и 0/7 ложных речевых событий; новые числа не выдуманы.
- Поставляемый автономный worker и зависимости вместо подготовленной
  Python-среды разработчика. В этом dev используется существующая среда
  через `FONO_WAKE_DEV_PYTHON`, без скачивания или установки пакетов.
- Персонализация собственной фразы и полноценная поставка WakeWord.

Release и browser mock не включают этот режим. Legacy-флаги
`WAKE_WORD_AVAILABLE` остаются `false`, старые настройки включения не
восстанавливаются. FONO-144 и FONO-70 требуют доводки качества; реализацию
dev-подключения следует учитывать в FONO-145 с открытой ручной приёмкой.
В текущей сессии MCP Кворума отсутствует в каталоге инструментов: запись
итогов подготовлена локально, изменение карточек пока не подтверждено.
