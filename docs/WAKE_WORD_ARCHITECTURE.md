# Архитектура wake word

Wake word изолирован в `src-tauri/crates/fono-wake`. Основной pipeline не
зависит от него: hotkey-диктовка остаётся доступной при любой ошибке wake word.

```text
audio input → fono-wake → Detected(pre-roll)
    → pause listener → post-wake dictation → STT → optional LLM → injection
    → resume listener
```

## Backends

### Потоковый RU/EN

`sherpa_streaming_ru` использует русский T-one, `sherpa_streaming_en` —
английский Zipformer. Оба поддерживают собственную фразу из 1–4 слов:
точное нормализованное совпадение соседних слов и устойчивое подтверждение,
без fuzzy-активации похожими словами. Общий DecoderSession используется
listener-ом и WAV replay; длинные окна ротируются с перекрытием.

Реестр `fono-wake/src/models.rs` фиксирует URL, SHA256, обязательные файлы
и лицензию. Загрузчик проверяет архив перед распаковкой и атомарной установкой.
После первоначальной загрузки моделей распознавание работает локально.

Мастер своей фразы: пять образцов для выбора чувствительности реального
детектора, затем три свежих положительных и два отрицательных. Записи остаются
в памяти; профиль хранит только параметры. Это калибровка, не обучение новой
нейросети. Смена фразы, микрофона, модели или параметров инвалидирует профиль
и выключает пробуждение до новой проверки.

### Whisper Experimental (прежний режим)

Распознаёт короткий фрагмент Whisper-моделью и сравнивает фразу fuzzy matcher.
Это прежний экспериментальный вариант. Задержка и нагрузка выше;
для новых RU/EN фраз используется потоковый детектор.

### Sherpa-ONNX KWS (прежний режим)

Быстрый KWS на модели
`sherpa-onnx-kws-zipformer-gigaspeech-3.3M-2024-01-01`. Модель английская и
работает по BPE-токенам, а не по свободной строке. В текущем продукте проверены
карты `hey fono` и `okay fun`; остальные фразы нельзя обещать как рабочие, пока
не появится runtime BPE-tokenizer.

Диагностика Sherpa:

- `Эталон Sherpa WAV` проверяет модель на встроенной фразе `LIGHT UP`.
- Ручная запись/распознавание проверяет текущую wake-фразу и общий audio path.
- `—` означает «KWS не выдал keyword», а не текстовую транскрипцию.

## Инварианты lifecycle

- Listener ставится на паузу при диктовке, ручном тесте и отмене.
- AudioHub владеет физическим захватом; RT-callback пишет в ограниченную очередь.
- Pre-roll и sample cursor продолжают тот же поток на точной границе handoff.
- Listening публикуется после открытия модели и микрофона, а не до них.
- Terminal state своей операции возобновляет listener; старый callback не
  может снять паузу чужой диктовки.
- Разрыв потока запускает три отменяемые попытки восстановления (0,5/2/5 с),
  после исчерпания — конкретную ошибку с действием для пользователя.
- Ошибка backend-а отправляется в UI/логи и не отключает hotkey-диктовку.

## Диктовка и приёмка

Silero VAD обрабатывает весь поток. Post-wake использует общий Stop/STT/
публикацию/архив. В обычном режиме пауза завершает диктовку, в режиме «На лету»
закрывает сегмент. Начальная wake-фраза удаляется только с начала текста.

Автоматические проверки и оставшаяся пользовательская приёмка:
[fono-voice-reliability.md](fono-voice-reliability.md).
