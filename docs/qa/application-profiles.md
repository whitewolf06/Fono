# Ручная приёмка профилей приложений

Реализация и автоматические результаты — [FONO-133](../improvement-fono133.md).
Это отдельная Windows-проверка владельца; browser mock не обращается к процессам,
микрофону, глобальной клавише и внешним полям.

1. В «Настройки → Основные» создать профиль IDE с `code.exe`, стилем «Задача»
   и включённой обработкой. Убедиться, что выбранное LLM-подключение подходит:
   облачный провайдер получит текст при обработке. Сохранить.
2. В текстовом поле VS Code начать обычную диктовку hotkey. До Stop проверить
   имя IDE и стиль в overlay, затем результат. Глобальный стиль в настройках
   не должен измениться от автоматического подбора профиля.
3. В toggle-режиме изменить стиль/перевод в overlay. Дождаться сохранения,
   завершить запись. Применяется ручной выбор. На следующей диктовке снова
   накладывается профиль; ручной выбор сохранён в глобальных предпочтениях.
4. Создать отдельный профиль для фактического exe терминала, выбрать эмуляцию
   нажатий клавиш. Проверить Unicode и фокус обычного не elevated терминала.
   Не запускать одновременно диктовки в разных полях.
5. В приложении без правила проверить глобальные параметры. Отключить профиль,
   сохранить, начать новую диктовку: global восстановлены, правило и его
   параметры остались в форме. Перезапустить Fono и проверить настройки ещё раз.
6. Во время диктовки перейти в другое поле/окно и завершить её. Новый профиль
   автоматически не выбирается; вставка в другую цель блокируется, результат
   доступен для копирования. Повтор не должен дублировать частичную вставку.
7. Быстро отменить запуск и начать следующую запись: поздний lookup/Stop/Cancel
   не меняет профиль, цель и результат следующей сессии. Не менять правила
   профиля в ожидании действия над предыдущей диктовкой.

В отчёте достаточно версии, приложения, выбранных параметров и результата
сценария. Текст диктовки, заголовки окон, URL, пути процессов и ключи не нужны.
