# Голосовое ядро Fono: контракты и проверка

Пользователь самостоятельно проверяет приложение,
микрофон, глобальные клавиши, внешние поля и overlay. Автоматические проверки
используют адаптеры и публичные WAV, не записывают микрофон.

**Текущий статус WakeWord:** пробуждение временно недоступно до улучшения
качества; native активация и тесты/калибровка через приложение заблокированы.
Описание детектора, проверки фразы и результаты ниже сохранены для будущей
доработки и qualification. Они не означают доступность WakeWord в текущем UI.
Актуальная приёмка — в [STATUS.md](../STATUS.md) и [testing.md](../testing.md).

Режим «На лету» временно скрыт после ручной проверки качества. Приложение
использует только классическую диктовку: результат появляется после завершения
записи. Ранее сохранённый `live` заменяется на `standard`, настройки обработки
текста сохраняются. Экспериментальная реализация и её тесты остаются для доработки;
переключатель, поиск настройки и демосценарии не доступны пользователю.

## Общие контракты

- Классическая диктовка получает итог после Stop и допускает необязательную
  обработку текста. Экспериментальный режим «На лету» не вызывает LLM.
- Общий AudioHub: ограниченные очереди, ресемплинг вне RT-callback и handoff по
  sample cursor. Разрыв потока и потеря пакетов отображаются как ошибки.
- Silero VAD обрабатывает весь поток. Финальный Stop сначала дренирует очередь
  захвата, чтобы сохранить последние пакеты.
- Один владелец завершает операцию; повторный Stop ожидает тот же результат.
  Поздние callback, Stop и Cancel привязаны к своей операции.
- API-задания имеют отдельные операции и уступают STT интерактивной диктовке.
  Вытесненное окно повторяется с checkpoint; само задание не отменяется.
- CPU/CUDA переиспользуют Whisper state и буферы. GPU protocol 4 поддерживает
  временные метки слов и отмену запроса с сохранением модели. Transport остаётся
  ограниченным JSON Lines/base64. Release проверяет handshake обоих workers.

## Ручная приёмка overlay правки — FONO-131

Fono v0.7.46 или новее; [отчёт](../improvement-fono131.md). Все строки матрицы
пока **ожидают проверки владельцем**. Browser mock подтверждает только общий Vue UI.

| Приложение            | UIA / получение | Фокус overlay, голос и LLM | Вставка / Copy / Cancel | Clipboard и смена поля |
| --------------------- | --------------- | -------------------------- | ----------------------- | ---------------------- |
| Браузер, обычное поле | Ожидает         | Ожидает                    | Ожидает                 | Ожидает                |
| Word                  | Ожидает         | Ожидает                    | Ожидает                 | Ожидает                |
| VS Code               | Ожидает         | Ожидает                    | Ожидает                 | Ожидает                |
| Telegram              | Ожидает         | Ожидает                    | Ожидает                 | Ожидает                |

1. Включить отдельное сочетание выделения. Оставить авто-вставку и историю
   правок выключенными. Выделить текст в одном из приложений, нажать и отпустить
   сочетание. Overlay появляется без активации главного окна; исходное поле
   остаётся активным. Повторить остальные строки матрицы отдельно.
2. Нажать «Продиктовать инструкцию», произнести формализацию/перевод/сокращение,
   завершить запись. Проверить распознанную инструкцию. Только кнопка
   «Преобразовать в LLM» отправляет материал и инструкцию в выбранное подключение.
   При ошибке внешний текст не меняется, оригинал и прежний результат доступны.
3. Проверить «Вставить» без смены активного поля и выделения. Затем Copy и Cancel.
   Cancel во время работы отменяет действие, оставляя текст для восстановления;
   Cancel после завершения закрывает сессию. Поздний ответ не вставляется и не
   архивируется.
   Повторная вставка в той же сессии отключена. Для проверки смены окна, поля,
   диапазона и содержимого, частичной/неизвестной отправки использовать сценарии
   FONO-130 ниже: результат остаётся для копирования, повтор не отправляется.
4. До нового выделения явно включить «Вставлять правку сразу после LLM».
   После успешного преобразования выполняется одна попытка с теми же guards.
   Выключить режим во время LLM: автоматическая попытка не должна начаться.
   Включение режима после получения выделения не разрешает авто-вставку старой
   сессии. Вернуть настройку по своему выбору.
5. Историю правок проверить отдельно: без согласия запись отсутствует; при
   согласии до получения и включённой общей истории Copy/отправка сохраняет один
   итог. Повторный Copy не дублирует запись. Оригинала и инструкции в архиве нет.
   Выключение общей или отдельной истории перед принятием запрещает сохранение;
   Cancel и ошибка LLM ничего не архивируют. При ошибке хранения текст доступен.
6. Проверить сохранение rich clipboard и защиту новой посторонней копии при
   завершении/отмене вставки. Явная кнопка Copy намеренно кладёт результат в буфер.
   Fallback Ctrl+C + вставка Clipboard по-прежнему отклоняется безопасно.
7. При обычной диктовке проверить прежний индикатор, Stop/Copy/Cancel и быстрые
   настройки. Overlay правки не должен скрывать активную диктовку. Для ручного
   ввода инструкции открыть основной редактор обычным способом; подтверждение
   там требует возврата в исходное поле и отдельного сочетания FONO-130.

Не заменять результаты этих строк автоматической записью микрофона,
управлением чужими полями или синтезом глобальных клавиш агентом.

## Ручная приёмка замены выделения — FONO-130

Fono 0.7.45 или новее; [отчёт](../improvement-fono130.md). Получить выделение
FONO-128 и успешно преобразовать его FONO-129. Проверку выполняет владелец.

1. Нажать «Подтвердить замену»: внешний текст ещё не меняется. Переключиться
   в исходное приложение, сохранив тот же фрагмент выделенным, и нажать сочетание
   выделения. Проверить замену в конкретных browser/Word/VS Code/Telegram.
   Не закрывать форму крестиком перед возвратом: закрытие отменяет сессию.
2. Перед сочетанием сменить окно, поле, диапазон, содержимое выделения при тех же
   границах или сделать выделение пустым. Замена отклоняется, результат доступен
   для Copy. Повтор замены в той же сессии запрещён. Получить выделение заново
   для следующей попытки; не считать совпадение одного HWND достаточной проверкой.
3. Подтвердить ответ, запустить другое преобразование, ошибку или Cancel.
   Старый ответ не вставляется. После нового успешного ответа нужно новое
   подтверждение. Быстрые старые завершения/shortcut/закрытие не меняют следующую
   сессию. Подготовку можно отменить до возврата в исходное поле.
4. Проверить SendInput и Clipboard для UIA выделения, а для fallback Edit/RichEdit
   — SendInput. Fallback + Clipboard insertion должен явно отказать без замены.
   Проверить rich clipboard, новую постороннюю копию, занятый буфер и UIPI.
5. При Cancel/переключении поля во время длинной вставки или частичном SendInput
   проверить прекращение дальнейшей отправки. Уже принятые события не отзываются;
   повторных порций автоматически нет. Осмотреть поле перед ручным Copy/Paste:
   частично принятый текст нельзя отправлять заново вслепую.
6. После успеха, отказа и частичного результата проверить «Копировать результат».
   Ошибка Copy сохраняет текст. Даже новое преобразование в той же сессии
   после попытки вставки не разрешает второй ввод. Проверить закрытие/новую
   сессию и отсутствие сохранения текстов в истории/диагностике/настройках.

## Ручная приёмка инструкции к выделению — FONO-129

Fono 0.7.44 или новее; [отчёт](../improvement-fono129.md). Сначала получить
непустое выделение способом FONO-128. Эту проверку выполняет владелец.

1. В форме нажать «Продиктовать инструкцию», сказать короткую инструкцию и
   завершить запись. Проверить отдельно «сделай формальнее», «переведи на
   английский», «сократи до трёх пунктов». Оригинал остаётся отдельно, инструкция
   доступна для исправления. Пока не нажата отправка, LLM не вызывается.
2. Проверить тишину, пустую/слишком длинную инструкцию, отсутствие модели или
   устройства. Ошибка не меняет оригинал. Cancel при открытии микрофона,
   записи, распознавании и закрытии формы должен освобождать именно эту запись.
   После отмены начать новую: старые Stop, Cancel, результат и таймаут не влияют
   на неё. Дождаться завершения очистки перед повтором действия в той же форме.
3. Проверить пояснение о передаче выделения и инструкции в выбранное подключение.
   Кнопки трёх примеров только заполняют инструкцию. Отправить явно выбранную
   проверочную пару, проверить настройки модели и отсутствие скрытых запросов
   при открытии формы. Переопределения подключения/промптов обычной диктовки нет.
4. На реальной LLM оценить формальность, перевод и сокращение без новых фактов,
   включая текст с вопросами и фразой «игнорируй правила». Ответ должен быть
   только отредактированным текстом; ни просьба, ни ответ не выполняют системные
   действия. Зафиксировать модель и фактическое качество, не считать fixture
   ответ доказательством качества провайдера.
5. Отменить медленный запрос и повторить с другой инструкцией. Поздний ответ
   не меняет новую операцию; оригинал остаётся. При отказе связи/пустом ответе
   доступны повтор и исходный текст. Учесть, что отмена не удаляет уже отправленные
   данные у облачного провайдера. После закрытия нет записи в истории, диагностике
   или настройках. Внешнее поле остаётся неизменным; замена — этап FONO-130.

## Ручная приёмка выделения — FONO-128

В Fono 0.7.43 или новее открыть «Настройки → Кнопки и активация».
[Отчёт FONO-128](../improvement-fono128.md) описывает ограничения текущего этапа.
Функция и резервный Ctrl+C выключены по умолчанию. Проверку внешних приложений
и буфера выполняет владелец; автоматические тесты их не заменяют.

1. Включить отдельное сочетание выделения. Проверить конфликт с диктовкой,
   командами, правым Alt/Ctrl и CapsLock; сохранить разные сочетания.
   При активной диктовке/обработке или выборе кнопки изменение отклоняется.
2. В обычном поле браузера, Word, VS Code и Telegram выделить точный фрагмент,
   нажать и отпустить Ctrl + Alt + Space. Если provider поддержан, Fono
   показывает только фрагмент, исходный текст не меняется. Проверить пустую
   каретку, несколько выделений и защищённое поле: отказ без чтения всего поля.
   Для каждого приложения отдельно записать поддержку/отказ и источник результата.
3. Только для fallback: разрешить резервный Ctrl+C, проверить классическое
   Edit/RichEdit с непустым выделением. Сначала подготовить clipboard с text,
   HTML/RTF/custom; после получения и Cancel должны восстановиться все форматы.
   Неподдерживаемый bitmap/owner-display или превышение лимитов должны дать отказ
   до изменения буфера. Пустая каретка не должна копировать целую строку.
4. Повторное сочетание, Cancel/закрытие preview и закрытие окна Fono должны
   очищать фрагмент. Проверить отмену во время чтения и копирования, затем новый
   запрос: поздний старый результат и старый Cancel не меняют следующий.
   Фрагмент не появляется в истории, диагностике или настройках.
5. Во время получения сменить окно, поле или выделение; результат отклоняется.
   Скопировать другой текст параллельно: новая копия сохраняется. Отдельно
   проверить занятый clipboard, повышенное приложение/UIPI, медленный provider,
   частичный ввод и ответ Ctrl+C позже 500 мс. При ошибке восстановления Fono
   сообщает о ней; клавиши автоматически не повторяются. Зафиксировать границы
   поддержанного сценария и оставшиеся ограничения, не считать их проверенными.
6. Проверить обычную диктовку, hooks и CLI после закрытия preview. Этот этап
   не записывает голосовую инструкцию и не заменяет выделение: следующие шаги
   FONO-129/FONO-130. WakeWord и «На лету» остаются выключенными.

## Ручная приёмка кнопок — FONO-127

В Fono 0.7.42 или новее открыть «Настройки → Кнопки и активация».
[Отчёт FONO-127](../improvement-fono127.md) отделяет автоматические проверки
от настоящих hooks. Эту проверку выполняет владелец.

1. Проверить выбор из списка и захват нажатием для правого Alt, правого Ctrl,
   CapsLock, XButton1/2 и обычного сочетания. Черновик применяется только после
   сохранения; Esc, «Отменить выбор», потеря фокуса, закрытие формы и ожидание
   30 секунд оставляют прежний сохранённый триггер. В момент выбора запись
   не начинается. После перезагрузки окна во время выбора прежний триггер
   должен вернуться не позднее native watchdog 45 секунд.
2. Попробовать правый Ctrl с сочетанием команд Ctrl + Shift + Space, одинаковые
   сочетания с разным порядком модификаторов и Alt + F4. Fono объясняет отказ.
   Для правого Ctrl сначала выбрать сочетание команд без Ctrl. Для правого Alt
   — без Alt. Учитывать AltGr в своей раскладке.
3. Занять сочетание в другой программе и попробовать сохранить его в Fono.
   Новый выбор не записывается; прежний триггер работает. При отказе отката
   должно быть явное сообщение о необходимости повторного сохранения/перезапуска.
4. В Блокноте, обычном поле браузера и рабочем редакторе проверить удержание,
   двойное нажатие клавиатурного hook и одиночное нажатие XButton в toggle.
   Проверить CapsLock с включённым и выключенным регистром, в том числе после
   захвата кнопки. Выбранная боковая кнопка не должна переходить назад/вперёд.
5. При записи, распознавании и ожидании ручного действия попробовать сменить
   триггер. Изменение отклоняется. После Stop/Cancel сменить кнопку, начать
   новую запись, отпустить старую — новая операция не завершается.
6. Проверить быструю печать и длительное использование без задержек клавиатуры;
   закрытие Fono с удерживаемой кнопкой освобождает hook. Зафиксировать приложения,
   устройство, результат и возможные ограничения. Работа в повышенном процессе
   отдельно проверяется владельцем, если входит в его обычный сценарий.
7. Настроить конкретную педаль/USB на поддерживаемое физическое нажатие или CLI.
   Для AutoHotkey/Stream Deck использовать команды из следующего раздела:
   синтетические события hook может игнорировать. Проверить Start/Stop/Cancel
   и отсутствие второго работающего экземпляра.

## Ручная приёмка CLI — FONO-126

Команды и ограничения описаны в [отчёте FONO-126](../improvement-fono126.md).
Эта проверка выполняется владельцем на собранном Fono 0.7.41 или новее;
тесты с подставленным AudioRecorder её не заменяют.

1. При открытом Fono выбрать внешнее поле и выполнить вторым запуском
   `Fono.exe --start`, затем `--stop`. Проверить запись, итоговую вставку
   и сохранение фокуса. Второго работающего Fono и второго API-порта нет.
2. Повторить Start при записи, несколько Stop, затем два `--toggle`.
   Сеанс и история не дублируются. При быстром Start → Stop завершается
   именно начатая запись, даже если устройство ещё открывалось.
3. Отменить запись и распознавание через `--cancel`, затем начать новую
   диктовку. Старый результат не вставляется и не меняет новую операцию.
4. В режиме toggle изменить обработку в оверлее непосредственно перед CLI
   Stop: применяется последний сохранённый выбор. При ошибке сохранения
   запись остаётся доступной для повтора Stop или Cancel.
5. Проверить `--show`, обычный повторный запуск без аргументов и холодный
   запуск с `--start`: Show и обычный запуск открывают настройки,
   а `--start` сохраняет фокус внешнего поля.
   Закрытие приложения во время старта не зависает.
6. Передать неизвестный аргумент и несколько команд: процесс завершается
   с кодом 2, основной Fono продолжает работать. Проверить сообщение
   в Windows Terminal/PowerShell. Код 0 корректной команды подтверждает
   передачу, а результат распознавания нужно смотреть в Fono.

## Отложенный эксперимент: живой вывод

Этот раздел описывает сохранённый код, недоступный в текущем UI. Возврат режима
требует отдельного согласования качества и ручной приёмки.

Два согласованных распознавания подтверждают стабильный префикс. Свежий хвост
остаётся изменяемым черновиком; граница тишины и завершение подтверждают остаток.
Принятый текст не переписывается. Сопоставление учитывает сдвиг временных меток
и настоящие повторения слов.

Сохраняется целая текущая фраза, максимум 20 секунд; на длинном окне перекрытие
2 секунды. PCM не обрезается после каждого принятого слова: это обрывало слоги
и давало пропуски. Initial prompt отключён в перекрывающихся окнах: модель
не должна считать присутствующий в аудио текст контекстом для пропуска.

Для вставки запоминаются foreground window, процесс и UI Automation runtime id
редактируемого элемента. Содержимое чужих полей не читается. Read-only поля
отклоняются. Смена поля/окна приостанавливает вставку, распознавание продолжается.
Возврат фокуса сам по себе её не возобновляет; явное возобновление выбирает
текущее поле. Перемещение курсора внутри того же поля не меняет его идентичность:
следующие фрагменты поступают в новую позицию курсора. Неподдерживаемые
UI Automation поля требуют ручного копирования.

Отправленные UTF-8 префиксы вычитаются из очереди. При частичной/неизвестной
отправке автоматический повтор запрещён; остаток можно копировать. SendInput
подтверждает отправку ОС, а не принятие текста приложением.

Последний результат сессии хранится в памяти независимо от истории. При отмене
или ошибке доступный текст остаётся; успешное завершение создаёт одну архивную
запись согласно настройкам приватности.

| Условие                               | Действие                                   |
| ------------------------------------- | ------------------------------------------ |
| Нет речи 5 секунд                     | Завершить с подсказкой проверить микрофон  |
| Тишина 30 секунд после речи           | Завершить живую диктовку                   |
| Запись 30 минут                       | Остановить захват и обработать остаток     |
| Отставание заполнило буфер 120 секунд | Остановить захват, дренировать звук        |
| Потеря пакетов/устройства             | Показать ошибку, сохранить доступный текст |

Обычный режим ограничен 5 минутами. Пауза WakeWord завершает обычную диктовку,
а в живом режиме закрывает сегменты; финальное завершение выполняется отдельно.

## Проверка текущей диктовки

Настоящий V3: `npm run dev:desktop:v3`. Браузерный `npm run dev:ui` использует
mock и не подтверждает native pipeline. Агент не запускает приложение для UAT
и не устанавливает сборку; installer готовится по отдельному запросу.

1. Проверить обычную диктовку: тихий конец, паузу, включённую/выключенную
   обработку, повторный Stop и отмену во время распознавания.
2. Проверить быстрый повторный запуск после отмены, отключённую историю,
   отключение микрофона и сон/возобновление Windows.
3. При активном API-задании начать диктовку: она получает приоритет, задание
   возобновляется. Отмена задания не должна отменять диктовку.

Основные сценарии — в [testing.md](../testing.md) и [dictation-controls-qa.md](dictation-controls.md).

### Условия будущей приёмки WakeWord

После отдельного восстановления функции проверить мастер 5 + 3 + 2 образца,
инвалидирование профиля при смене микрофона/фразы/модели/параметров и восстановление
listener после потери устройства. Это калибровка реального потокового детектора,
без обучения новой нейросети. Подробности — [WAKE_WORD_ARCHITECTURE.md](../WAKE_WORD_ARCHITECTURE.md).

Живая диктовка и её проверки смены поля/поэтапной вставки также отложены до
исправления качества. Replay ниже проверяет сохранённый экспериментальный код.

## Автоматические проверки и replay

Общие frontend/native команды и Windows wrapper для закреплённых DLL — в
[testing.md](../testing.md). Прямой `cargo test` с системным ONNX runtime может
дать несовместимое окружение.

STT benchmark принимает PCM16 mono 16 kHz WAV и необязательный UTF-8 файл
эталонной расшифровки. Без эталона сравнение с batch измеряет согласованность,
не точность. Текст включается в отчёт только явно через `--include-text`.

```powershell
cd src-tauri
cargo build -p fono-stt-worker --bin fono-stt-bench
& .\target\debug\fono-stt-bench.exe --model C:\models\ggml-model.bin `
  --wav C:\fixtures\speech.wav --language en --reference C:\fixtures\reference.txt `
  --worker C:\workers\fono-stt-cuda-worker.exe
# Новый процесс без предварительных probe/batch:
& .\target\debug\fono-stt-bench.exe --model C:\models\ggml-model.bin `
  --wav C:\fixtures\speech.wav --language en --cold-replay `
  --worker C:\workers\fono-stt-vulkan-worker.exe
```

Использовать реальные пути workers из `resources/stt-workers` согласно manifest.
CLI разделяет загрузку модели и первый текст, указывает `warmed` и использует
production agreement/window policy. В replay нет микрофона, Silero endpointing
или Windows insertion.

```powershell
cargo build -p fono-wake --no-default-features --features sherpa-wake --example wake_replay
& .\target\debug\examples\wake_replay.exe ru C:\models\wake-ru `
  'привет компьютер' C:\fixtures\wake-corpus.json
```

Нужны matching Sherpa/ONNX DLL рядом с executable. Corpus JSON:

```json
[
  {
    "wav": "positive.wav",
    "positive": true,
    "holdout": true,
    "phrase_end_ms": 1400
  },
  { "wav": "other-speech.wav", "positive": false }
]
```

`phrase_end_ms` размечается вручную по реальному концу фразы; без него p95
не вычисляется. Нужны quiet/noisy positives и многочасовые negative recordings
помимо фраз настройки.

Для W-02 подготовлен [отдельный стенд](../../tools/wake-bench/README.md)
с train/dev/test, SHA256, декларациями разрешений, paced delivery, CPU
и замороженной test-точкой. [Инженерный результат](../improvement-fono143.md)
сохраняет открытые критерии качества и не включает WakeWord в приложении.

## Личный словарь — FONO-132

Автоматический результат и точный состав публичного сравнения:
[FONO-132](../improvement-fono132.md). Ручную проверку выполняет владелец:

1. При выключенном словаре продиктовать фразу с названием проекта. Добавить
   написание и вариант произношения, сохранить. Повторить новую диктовку с
   включённым словарём; сравнить исходную STT-расшифровку и финальные замены.
2. Повторить на CPU и доступном GPU, затем с распознаванием фраз во время
   записи. Проверить tail/Stop, Cancel и отсутствие подсказок от прежней сессии.
3. Отдельно разрешить передачу терминов LLM, проверить обработку/перевод.
   Учитывать отправку списка выбранному провайдеру. Без этого согласия список
   не должен уходить в LLM; raw без перевода вообще не вызывает LLM.
4. Выключить словарь и начать новую диктовку: подсказки, отправка списка и
   замены отключены, записи сохранены. Изменение во время записи действует
   для следующей сессии. Для текущих GigaAM/Parakeet hotwords не ожидаются.

Браузерный макет подтверждает только настройки и вёрстку; микрофон, GPU,
облачный провайдер и качество личного голоса им не проверяются.

## Ограниченные замеры экспериментального кода

Замеры ниже относятся к этапу 3 октября 2026 года. Они сохранены как исходные
данные для следующего сравнения, не подтверждают текущую сборку или приёмку.

Короткий JFK WAV (22 слова), large-v3-turbo, RTX 5070 Ti: batch и replay
совпали с эталоном, WER/CER 0. Время до первого стабильного текста:

| Запуск                     | CUDA    | Vulkan  |
| -------------------------- | ------- | ------- |
| Прогретый                  | 3,23 с  | 3,11 с  |
| Холодный, после загрузки   | 3,69 с  | 17,12 с |
| Холодный, включая загрузку | 10,78 с | 20,62 с |

Холодный Vulkan пока медленный: первый inference 15,94 с. Прогретый замер
не гарантирует быстрый первый запуск. Короткий RU WAV совпал между batch/replay,
но независимого эталона для него нет. Реальная отмена CUDA/Vulkan заняла
328/62 мс и сохранила процесс/модель; поздняя отмена не затронула новый запрос.

RU/EN WakeWord обнаружили по одному положительному публичному примеру;
короткая чужая речь не дала активаций. Silero regression подтверждает, что
речь+тишина обрабатываются одинаково целиком и частями; reset убирает старую речь.
Короткие smoke не оценивают точность на личном голосе.

Запуск Wake diagnostics запрещён при активной живой диктовке. Диагностический
replay, начатый раньше неё, пока может конкурировать за CPU: он не участвует
в общем STT scheduler. Это отдельная оставшаяся оптимизация диагностического пути.

Ещё нужны recall ≥95% в тишине/≥90% в шуме, wake p95 ≤800 мс, 10 часов negatives,
live p95 ≤4 с, WER относительно batch ≤2 п.п., долгие записи/память и реальные
Windows поля. Эти цели пока не подтверждены. Артефакты коротких замеров:
`build/stt-contract-check/` и `build/wake-models/`; они не входят в репозиторий
и не содержат личных записей.
