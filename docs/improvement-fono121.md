# FONO-121 — фоновые сегменты и scheduler

Результат для ревью, версия 0.7.36. Зависимость — потоковая сегментация
FONO-120, коммит `ce919b6`, находящаяся на ревью.

## Реализация

В `SttScheduler` добавлен доступ фоновых сегментов конкретной записи:
`acquire_capture(operation_id, cancellation)`. Он допускается только для
текущего владельца capture reservation. API-задания по-прежнему ждут
освобождения интерактивного резерва. Ожидающие интерактивные запросы
получают приоритет и отменяют только выполняющееся фоновое окно, сохраняя
токен всей пользовательской операции.

`promote_stop` закрывает доступ новым фоновым сегментам этой записи и
отменяет её текущее окно. Запоздалый Stop другой операции не влияет на
новую запись. Реальный permit освобождается после возврата backend.

Один capture worker последовательно читает копии не более 512 сэмплов из
существующего ограниченного `RecordingWriter`, использует сегментатор
FONO-120 и речевой neural admission перед STT. Пока идёт STT, новый звук
продолжает поступать в исходный буфер записи. Отдельной очереди PCM-фрагментов
нет, callback захвата не ждёт VAD, загрузку модели или распознавание.

Готовые результаты содержат `operation_id`, индекс, абсолютный диапазон
PCM и типизированный `WindowTranscript`. `None` означает успешно проверенный
NoSpeech-диапазон. STT-ошибка не маскируется пустым текстом. Отменённое
из-за приоритета окно повторяется с того же диапазона; готовый префикс не
распознаётся заново.

Результаты хранятся только в памяти, без событий UI, истории, вставки и LLM.
Ограничения: два фактически выполняющихся worker, до 512 результатов и 256 КиБ
текста с языковыми метаданными на запись. Timestamp-массивы не удерживаются.
При достижении предела остаётся готовый префикс; весь остальной PCM доступен
Stop. Ограничение исходного capture-буфера остаётся пять минут.
Получение или сброс handle Stop не освобождает слот работающего worker.

Регистрация worker, получение writer и токена операции проходят через
capture fence. Lease обновлений берётся до этой блокировки и переносится
в worker; он удерживается от постановки работы до фактического выхода.
Cancel запрещает выдачу старого результата, а уже работающий непрерываемый
backend продолжает удерживать permit и lease до возврата. Устаревший
потребитель не может забрать результат следующей записи.

Stop и терминальное завершение останавливают consumer. После Stop API
`take_capture_segments_for` передаёт worker вызывающему коду; blocking
`finish` дожидается его реального завершения и возвращает только готовый
префикс с `processed_until`. Незавершённый сегмент и хвост остаются будущему
Stop-пути FONO-122. Этот join должен выполняться через `spawn_blocking`.

Native adapter использует существующий `SttEngine`, snapshot модели,
ускорения, языка и decoding options; worker-запрос получает тот же
`operation_id` и абсолютный sample offset. Загрузка и inference выполняются
под общим permit. Подготовлен порог старта 15 секунд.

## Включение по этапам

Автозапуск в обычной диктовке закрыт внутренним
`CAPTURE_STT_AVAILABLE = false`. Подключены точки запуска и Stop/Cancel,
но до FONO-122 готовые сегменты ещё не участвуют в итоговой расшифровке.
Включение сейчас привело бы к дополнительной фоновой работе и повторному
распознаванию всей записи на Stop. FONO-123 добавит пользовательскую
настройку и решение о дефолте по качеству.

Это ограничение этапа, а не включение скрытого режима «На лету»:
LocalAgreement, WakeWord и внешняя вставка во время записи не используются.
Диагностика и голосовые команды не запускают новый consumer.

## Проверки

Пройден общий прогон: 515 app native-тестов, включая восемь новых,
280 UI-тестов и 48 release/CI-контрактов. Шесть существующих app-проверок
с внешними ресурсами/soak остаются ignored. Затем отдельно пройден девятый
новый тест: сброшенный handle Stop продолжает занимать слот до реального
окончания backend; при одном таком worker и втором ожидающем третий старт
отклоняется. После изменения только этого теста повторён strict Clippy;
полный пакет повторно не запускался.

Новые проверки используют production Pipeline, capture writer, scheduler,
потоковый Silero и публичную короткую EN-фразу. Управляемый тестовый
распознаватель воспроизводит вытеснение и непрерываемую нативную работу.
Проверены последовательные индексы/диапазоны, сохранность полного PCM,
повтор только текущего окна, запрет потребления результата во время записи,
Stop посреди окна, Cancel и новая запись, neural admission тишины до STT,
предел размера текста и освобождение timestamp-массивов.

Успешны strict Clippy всех app targets, CPU-only check, check без default
features, Rust format, typecheck, lint, frontend build, version, Prettier
и локальные ссылки документации. UI не менялся, browser-матрица не
повторялась. Приложение и микрофон автоматически не открывались.
Проверки npm выполнялись с существующими локальными изменениями обслуживания
кэша владельца; эти изменения в коммит FONO-121 не включены.

## Хвосты

- FONO-122: дождаться worker вне capture fence, использовать готовый
  префикс и распознать остаток с приоритетом Stop, добавить ограниченный
  Whisper context, склеить один результат и выполнить LLM/архивирование
  один раз. Ошибка фонового worker требует безопасного обычного fallback.
- FONO-123: настройка через существующие ports/events, порог длинной записи
  и выбор дефолта после приёмки качества. В этой версии автозапуск выключен.
- WER длинных записей, замер Stop → текст, настоящая модель/GPU под нагрузкой,
  микрофон, hotkey и overlay требуют отдельной приёмки F-02. Тестовый backend
  для гонок не заменяет эти измерения.
- Remote CI, installer, публикация и установка не выполнялись; пользовательским
  приложением и личным микрофоном автоматическая проверка не управляет.
