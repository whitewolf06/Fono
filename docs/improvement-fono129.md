# FONO-129 — преобразование выделения по инструкции

Версия 0.7.44. Этап F-05.2 использует явное получение выделения из
[FONO-128](improvement-fono128.md), которое остаётся в `in_review` до ручной
Windows-приёмки. Родитель FONO-60 остаётся в работе.

## Что сделано

В форме полученного выделения добавлена отдельная инструкция: её можно
продиктовать или ввести вручную. Кнопки «Формальнее», «На английский»,
«В три пункта» только заполняют инструкцию. Отправка начинается отдельной
кнопкой «Преобразовать в LLM», после пояснения о передаче обоих текстов
в сохранённое подключение обработки. Облачному провайдеру передаются уже
отправленные данные независимо от последующей отмены; форма это поясняет.

Оригинал, инструкция и результат хранятся раздельно, только в памяти текущей
операции. Ошибка или отмена действия сохраняет оригинал и предыдущий результат.
Закрытие всей формы очищает выделение и отменяет активную работу. Новая
инструкция может быть записана повторно; старое завершение не заменяет новую.

Текущий сценарий: отдельное сочетание FONO-128 → просмотр выделения → запись
инструкции кнопкой → проверка распознанной инструкции → явная отправка.
Преобразование не меняет исходное поле. Безопасная замена, подтверждение
вставки и итоговый overlay относятся к следующему этапу FONO-130.

## Native и приватность

- Полученный материал берётся из Rust Runtime по точному selection operation ID.
  Renderer передаёт только инструкцию и явный флаг согласия на отправку,
  не подменяет оригинал, целевое поле или native selection proof.
- Редактирование имеет собственный operation ID и cancellation token. ID
  фиксируется до фоновой очереди. Stop/Cancel проверяют оба идентификатора.
  Пока реальная работа завершается, сохраняется занятость операции.
- Запись инструкции повторно использует изолированную raw capture: AudioHub,
  речевой VAD, снимок STT-настроек и общий interactive STT scheduler.
  Лимит записи — 120 секунд; после Stop результат не проходит обычную
  постобработку, не вставляется и не архивируется. Остановка устройства вынесена
  в `spawn_blocking`, как и начало/отмена захвата и загрузка credentials.
- Admission lease удерживает работу после исчезновения IPC-ожидания, отмены
  или закрытия формы. Позднее открытие микрофона после Cancel заканчивается
  отменой именно возвращённого capture ID; чужая новая сессия не затрагивается.
  Распознающая native работа сохраняет собственные scheduler/activity guards.
- Используется существующее LLM-подключение обработки текста, выбранная модель,
  secure credentials, общий HTTP client, таймауты и ограничение ответа.
  Настройки и пользовательские промпты обычной диктовки не меняются.
  Для выделения действует отдельный системный редакторский промпт: произвольная
  инструкция не смешивается с preset обычной диктовки.
- Material и instruction передаются отдельными JSON-полями. Материал не
  становится системной инструкцией. Промпт разрешает только преобразование
  формы/перевод/сокращение без новых фактов и требует только итоговый текст.
  Инструменты в запрос не включаются. `app_commands` и системный executor
  в этом пути не вызываются; даже текст ответа, похожий на команду, остаётся
  обычным текстом для просмотра.
- Инструкция ограничена 4096 UTF-8 байт; оригинал и ответ — прежними лимитами
  выделения (32 768 UTF-16 единиц, 65 536 UTF-8 байт). Пустой ответ и NUL
  отклоняются. UI получает только разрешённые сообщения, без сырых ошибок,
  endpoint, ключей и native target metadata.

## Проверки

- Полный V3-набор: **304/304**. Новые проверки: три варианта инструкции,
  отдельное согласие, сохранение оригинала, отмена позднего результата,
  точные IDs и отсутствие renderer material в IPC, описание облачной отправки.
- Полный Rust-набор: **579 passed, 7 ignored**. Новые проверки охватывают
  отмену/занятость до очистки, старое завершение, разделение инструкции/результата,
  sanitization, границы payload и JSON-разделение материала и инструкции.
- Три transport-сценария формальности/перевода/сокращения прошли через локальный
  HTTP fixture: проверены модель, точный материал, инструкция, системные guards,
  отсутствие tools и получение ответа. Fixture возвращает заранее заданные
  ответы: это проверка контракта, не оценка качества реальной LLM.
- Strict Clippy all-targets, TypeScript, ESLint, production frontend build,
  CPU-only и конфигурация без default features прошли. Native-тесты используют закреплённые
  Sherpa/ONNX DLL и отдельный test data каталог.
- Release/CI contracts: **48/48**, включая 20 cache-тестов из отдельных
  незакоммиченных изменений пользователя; эти изменения не входят в FONO-129.
- Browser mock: **720×560, 900×720, 1440×900**. Проверены пример голосовой
  инструкции, три деморезультата, отдельный оригинал, прокрутка и закрытие.
  Горизонтального переполнения нет. В демо используются готовые примеры,
  без микрофона, clipboard и сетевой отправки.
- Version/format/Rustfmt/docs checks прошли. После Cargo выполнено штатное
  обслуживание кэшей.

Логи: игнорируемый `build/checks/fono129-*`.

## Хвосты приёмки

Владелец проверяет реальный микрофон и выбранную STT-модель: короткую инструкцию,
тишину, Stop/Cancel при открытии устройства и распознавании, таймаут и закрытие
окна. Затем — согласованное LLM-подключение, точность формальности/перевода/
сокращения, сохранение фактов и отказ связи. Промпт и fixture-тесты не доказывают
семантическую точность произвольной модели. Облачные тексты автоматически
не отправлялись. [Ручная матрица](qa/voice-reliability.md) содержит эти сценарии.

Зависимость FONO-128 сохраняет свои хвосты UIA/clipboard и совместимости
Windows-приложений. Они не считаются принятыми этим этапом. FONO-130 ещё должен
проверять актуальность цели и выделения перед заменой и блокировать повтор
после частичной вставки. История этой функции пока не записывается.

Установленный Fono и чужие поля автоматически не использовались, микрофон не
записывался. WakeWord/live выключены. Installer, установка, публикация,
настоящий remote CI и production-приёмка не выполнялись.
