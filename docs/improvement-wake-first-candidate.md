# WakeWord: реальные образцы и первый классификатор

22 октября 2026 года, исходники v0.7.67. FONO-143/144, родитель FONO-70.
**Классификатор обучен и экспортирован, но качество не принято. Постоянное
прослушивание остаётся выключенным.** Приложение и его AudioHub в этом
изменении не переделывались; исследовательские модели не входят в default build.

## Что получилось

Владелец самостоятельно записал 36 WAV, 85,34 с: 28 целевых RU/EN произнесений,
6 файлов другой речи и 2 фона. Проверены PCM16 mono 16 kHz, сохранённые SHA256,
длительность, отсутствие дубликатов и перегрузки. Оба фоновых WAV — цифровая
тишина. Метки заданы владельцем, точная фраза и её временные границы пока не
подтверждены. Это личный dev-набор одного говорящего, не общий test.

Два существующих кандидата дали 0/28: один фиксированный прогон прежнего
ASR baseline и один English KWS GigaSpeech 3.3M. Для последнего официальный
контрольный LIGHT UP распознан. Короткие WAV и разные контексты replay не
позволяют выдавать эти числа за формальное сравнение детекторов.

Написан собственный log-mel/CNN pipeline без стороннего pretrained embedding.
Один ограниченный синтез VoxCPM2 offline дал 88 файлов, 110,08 с; это частичный
набор из 96 запланированных, остановленный на 600 с. Обучение на CPU заняло
60,77 с. Получен ONNX 52 182 байта / 12 473 параметра; export parity с PyTorch
прошла с max abs error 5,960464477539063e-8. Голос владельца не использовался
для train или voice cloning и не отправлялся в сеть.

При заранее фиксированном пороге 0,8 классификатор обнаружил фразу в **27/28**
помеченных положительных WAV: RU 16/16, EN 11/12. Он также выдал **5 событий
на 4 из 6** помеченных речевых негативов. На цифровой тишине — 0 событий.
Нет временной разметки и длительного фона: FA/h, p95 и idle CPU не измерены.
Эти результаты не доказывают приёмку и не разрешают включение WakeWord.

## Что добавлено в репозиторий

- `tools/wake-training/candidate.py`: synthetic-only train, детерминированный
  frontend/seed, фиксированный operating point, ONNX checker/parity, отдельный
  private dev replay с проверкой согласия, split и хэшей.
- `synthesize_candidate.py` и pinned `voxcpm2.json`: проверка уже локальных
  весов, отсутствие сетевого fallback, явный partial при лимите синтеза.
- Шесть новых contract tests: разделение train/dev и происхождения,
  ошибочные пути/хэши, недопустимые scores, cooldown без повторов постоянного
  высокого сигнала. CI запускает их вместе с подготовкой, без моделей/микрофона.
- Опциональный Rust-пример `kws_probe`: файловый KeywordSpotter со штатными
  параметрами и явным 640 мс хвостом; не входит в приложение.
- [Инструкции, точные параметры и хвосты](../tools/wake-training/CANDIDATE.md),
  [агрегированное evidence](evidence/wake-first-candidate.json).

WAV, пользовательские ID/хэши, speaker/session, пути профиля и score-трассы
не включены в Git или Кворум. Модель не опубликована, фальшивого download
manifest нет. Пакеты ONNX установлены только в исследовательский каталог Fono;
использованный ранее установленный Python/TTS runtime и веса другого проекта
не изменялись. Installer и новый native dev не собирались для этого research
изменения; функциональная форма записи остаётся из v0.7.66.

Проверки: 17/17 Python training contracts, 14/14 benchmark contracts,
19/19 unit-тестов отдельного `fono-wake`, strict Clippy и Rustfmt;
395/395 Vue/IPC, 48/48 release/CI scripts, typecheck, ESLint, frontend build,
format/version/docs checks. Default dependency tree по-прежнему без
`fono-wake`, оба availability-флага выключены. Полные native-тесты приложения
в этом проходе не повторялись, поскольку его runtime не менялся. UI в браузере
и пользовательский микрофон агентом не проверялись; 36 WAV записал владелец.

## Что осталось

Ближайшая критичная работа — проверить речевые отрицательные метки и убрать
ложные срабатывания, добавив отдельную разрешённую обычную речь и трудные
негативы в train. Личные dev-записи не переносились в обучение. Порог после
просмотра результата не менялся, повторного обучения или перебора параметров
в этом проходе не было.

После этого нужны независимый размеченный test и измерение исходных целей:
recall ≥95% quiet / ≥90% noisy, ≤0,5 FA/h, p95≤800 мс, idle CPU<1% одного
ядра. Требования корпуса 100–300 произнесений разных людей/микрофонов и
≥10 часов разрешённых негативов сохраняются. Новые записи владельца сейчас
не запрашиваются: полученный набор уже полезен для разработки.

Далее — native frontend parity и ONNX-интеграция FONO-145 после качества,
явная ручная проверка; персонализация FONO-146 отдельно. W-03 не закрыта.
Первый обучающий прогон уже выполнен, отдельного согласия на него больше
не ожидаем. Статус W-03 — `in_progress`: оставшееся исправление качества
относится к работе над классификатором, а не к неисправности MCP или ожиданию
повторной записи голоса владельцем.
