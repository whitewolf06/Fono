# Восстановление окна после сна

В v0.7.75 добавлено восстановление Windows WebView2 после сна и изменения
конфигурации дисплея. Основание — наблюдение в dev v0.7.74: приложение и
локальный Vite работали, окно оставалось чёрным после Ctrl+R, а полный
перезапуск того же EXE с тем же профилем восстановил интерфейс. Связь с VPN
и точная причина исходного сбоя не установлены.

## Механизм

Каждое окно регистрирует native-уведомления сна/пробуждения через
[RegisterSuspendResumeNotification](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registersuspendresumenotification).
На resume или WM_DISPLAYCHANGE выполняется одна объединённая проверка
на окно, после короткой паузы для восстановления дисплея.

Сначала на UI-потоке обновляются границы и видимость существующего
[контроллера WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller).
Скрытый контроллер остаётся скрытым. Навигация, focus и документ при этом
не меняются. Проверка JavaScript возвращает только факт монтирования Fono;
тексты, значения полей, адрес страницы и аудио не читаются.

Tauri закреплён на уже используемой версии 2.11.5, а webview2-com — на
совместимой 0.38.2 из текущего Cargo.lock: тип контроллера в with_webview
зависит от этих версий. Обновлять их следует согласованно.

После двух неуспешных проверок пересоздаётся соответствующее окно.
Вторая проверка отделена паузой; каждая ограничена восемью секундами.
Это автоматическое восстановление интерфейса, без перезапуска Rust,
моделей, истории, API или диктовочного runtime. Отдельный сбой или
зависание процессов WebView2 требует собственного восстановления,
что описано в [документации Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/process-related-events).

Пересоздание ждёт события Destroyed и освобождения старой метки окна
в Tauri. Создание ставится в отдельный UI-dispatch после обработчика
уничтожения. Автоматический выход при временном отсутствии обоих окон
подавляется; явный выход пользователя остаётся доступен. Shutdown
отменяет оставшиеся восстановления.

Размер, положение, видимость и свёрнутое/развёрнутое состояние сохраняются.
Overlay сохраняет focusable=false, восстановление не вызывает set_focus.
CloseRequested не используется для аварийного пересоздания, чтобы не
отменять текущую native-операцию. Update admission lease сохраняется
до фактического завершения отложенной UI-работы.

## Проверка и ограничения

Политика проверяется Rust-тестами: объединение уведомлений, независимость
окон, старые callbacks после замены окна, shutdown, скрытый overlay,
возврат видимости после ошибки и вложенное создание окон. Эти тесты и
успешная компиляция не заменяют проверку настоящего сна Windows.

Остаётся ручная приёмка владельцем:

1. Оставить основное окно открытым, отправить компьютер в сон и вернуть.
   Окно должно восстановиться без перезапуска Fono. Если документ отвечал,
   незавершённые изменения формы должны остаться.
2. Повторить с окном, скрытым в трей: после пробуждения оно не должно
   открываться само; открытие через трей должно показать интерфейс.
3. Проверить обычную диктовку после пробуждения и отсутствие перехвата
   фокуса внешнего поля индикатором.

Полностью зависший документ может потерять несохранённый UI-черновик
при пересоздании. Сохранённые настройки и native-состояние не очищаются.
Сбой самого UI-потока хоста, недоступный dev-сервер, исчерпание ресурсов
или ошибка создания нового WebView требуют отдельной диагностики.
Проверка отвечает на факт монтирования документа, а не измеряет пиксели:
исчезновение исходного чёрного экрана должно подтвердиться на реальном сне.

Публикация, installer, отдельное включение WakeWord в release и работа
через VPN этой правкой не квалифицируются. При повторении полезны версия,
время выхода из сна и технические события webview_recovery; содержимое
пользовательских документов не требуется.
