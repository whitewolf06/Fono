# Roadmap WhisperClone

Дорожная карта разработки с контрольными точками. Даты — ориентировочные,
при активной разработке ~1 этап ≈ 2–4 дня全职.

## ✅ Этап 0 — Документация и скаффолд

**Цель:** пустой, но рабочий каркас приложения с документацией.

- [x] `README.md` с обзором и инструкцией сборки.
- [x] `docs/architecture.md` — модули и потоки данных.
- [x] `docs/development.md` — настройка окружения.
- [x] `docs/roadmap.md` — этот файл.
- [x] Инициализация Tauri 2 (React + TypeScript).
- [x] Базовая структура каталогов `src-tauri/src/{audio,stt,injection,pipeline,...}`.
- [x] System tray + пустое окно настроек + прозрачное overlay-окно.
- [x] Зависимости в `Cargo.toml`: `cpal`, `whisper-rs`, `windows`, `reqwest`, `tokio`, `tracing`.

**Контрольная точка:** `npm run tauri dev` запускает приложение, появляется иконка в трее,
открывается окно настроек, overlay-окно можно показать/спрятать из кода.

## 🎯 Этап 1 — Audio capture + whisper.cpp STT

**Цель:** наговорил в окне настроек — получил текст.

- [ ] `audio/`: захват с дефолтного микрофона через `cpal`, 16 кГц mono i16.
- [ ] Lock-free SPSC ring buffer для чанков.
- [ ] Команда IPC `list_audio_devices()` — выбор устройства в UI.
- [ ] `stt/`: загрузка whisper.cpp модели (`whisper-rs`), функция `transcribe(samples) -> Transcript`.
- [ ] Скачивание моделей при первом запуске (или явный путь в настройках).
- [ ] UI: кнопка «Записать 5 секунд» → вывод транскрипта.

**Контрольная точка:** в окне настроек нажал кнопку → наговорил → увидел текст.

## Этап 2 — Текст-инъекция

**Цель:** транскрипт вставляется в активное окно.

- [ ] `injection/`: `inject_text(text)` через Win32 `SendInput` (Unicode chars).
- [ ] Альтернативный режим «через буфер обмена» для длинных текстов (с восстановлением буфера).
- [ ] Команда IPC `inject_text(text)`.
- [ ] Обработка UIPI: документирование + опция elevated-запуска.

**Контрольная точка:** dictate в Notepad, Word, браузере, Telegram → текст вставляется.

---

## 🚀 Этап 3 — Push-to-talk MVP

**Цель:** первая версия, которой **можно реально пользоваться**.

- [ ] `hotkey/`: глобальная горячая клавиша (`Ctrl+Space` по умолчанию).
- [ ] `vad/`: silero-vad для определения конца речи (тишина N мс → стоп).
- [ ] `pipeline/`: конечный автомат `IDLE → LISTENING → TRANSCRIBING → INJECTING → IDLE`.
- [ ] Overlay-индикатор статуса (слушаю / транскрибирую / готово).
- [ ] Настройки: горячая клавиша, модель whisper, чувствительность VAD.

**Контрольная точка:** зажал `Ctrl+Space` → наговорил → отпустил → текст вставился в окно.
Можно удалить/заменить введённый текст.

## 🎙️ Этап 4 — Wake word активация

**Цель:** активация голосом без нажатия клавиш.

- [ ] Ресерз и выбор движка:
  - [ ] openWakeWord (Rust ONNX через `ort`, MIT) — англ.
  - [ ] Porcupine (Picovoice) — кросс-язычный, проверка лицензии.
  - [ ] Своя ONNX-модель через `livekit-wakeword` — для русской фразы.
- [ ] `wakeword/`: отдельный лёгкий поток, читает ring buffer.
- [ ] При срабатывании → активировать pipeline.
- [ ] Деактивация по тишине (VAD) или повторной wake-фразе.
- [ ] Настройка кастомной фразы.

**Контрольная точка:** сказал «Эй, ассистент» → началась запись → наговорил → текст вставился,
без единого нажатия клавиш. CPU в IDLE < 5%.

## 🧠 Этап 5 — AI-постобработка через LM Studio

**Цель:** «грубая» речь → аккуратный, готовый к отправке текст.

- [ ] `llm/`: HTTP-клиент к `http://localhost:1234/v1/chat/completions`.
- [ ] Режимы: `off`, `clean` (по умолчанию), `format`, `command`.
- [ ] Промпт-шаблоны в `llm/prompts.rs`.
- [ ] Стриминг ответа (SSE).
- [ ] Тест подключения в настройках (`test_llm_connection()`).
- [ ] UI: переключатель режимов, выбор модели, URL.

**Контрольная точка:** сказал «надо отправить жене что задержусь» → вставилось аккуратное сообщение.

## 🐛 Backlog / Known Issues

- UIPI: нельзя вводить в elevated-окна без повышенного запуска.
- DirectInput игры: `SendInput` может игнорироваться.
- Антивирусы: глобальные хуки могут триггерить AV (решается подписью кода).
- Wake word для русского: нет готовой open-source модели, нужно обучать.
