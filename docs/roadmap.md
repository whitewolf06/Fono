# Дорожная карта Fono

Здесь собраны незавершённая приёмка и дальнейшие решения. Версия исходников —
в `package.json`, реализованные возможности и прежние результаты проверок —
в [STATUS.md](STATUS.md). Исторические планы доступны в Git.

## P0 — приёмка текущего приложения

- [ ] Пользовательский прогон V3/native: первый запуск, настройки и откат
      ошибок сохранения, `hold`/`toggle`, отмена, длинный текст и маленькое окно.
- [ ] Overlay: выбор стиля/перевода во время записи, сохранение перед Stop,
      завершение клавишей с вставкой и принятие мышью без вставки, копирование,
      повторная обработка после ошибки ИИ, отсутствие повторного архива.
- [ ] Updater из установленной версии: уведомление, ручная проверка,
      загрузка, проверка подписи/версии, установка/UAC и перезапуск с сохранением
      настроек/истории. Проверить opt-in фоновых проверок, суточное ограничение,
      отключение и ожидание активной диктовки/API/pending перед установкой.
- [ ] GPU `resident`/`adaptive`: реальное измерение выделенной памяти,
      выгрузка только в простое при устойчивом давлении, загрузка по запросу,
      пауза после загрузки, отсутствие дребезга и корректный `unsupported`.
- [ ] NSIS/MSI на чистой Windows без Rust, SDK и исходников. Проверить
      поставляемые DLL/workers, первый запуск, обновление и удаление приложения.
      Этот этап отложен пользователем и не считается выполненным по CI.
- [ ] Онлайн-установщик: пользовательский прогон GUI/UAC, докачивания после
      обрыва, повторного запуска из кэша и перехода в проверенный NSIS.
      Публикация EXE — отдельное решение; методика — [online-installer.md](online-installer.md).
- [ ] Матрица CPU-only, CUDA и Vulkan: AMD/Intel GPU, отсутствующие runtime/
      драйверы, понятные ошибки и Auto. Старый smoke на одной NVIDIA не закрывает
      остальные конфигурации.
- [ ] Реальные Windows-поля: clipboard с текстом/изображением/файлами,
      смена поля, частичная отправка и приложения с повышенными правами.

Проверку голоса и пользовательских окон выполняет пользователь. Подготовка
подписанного installer, публикация, установка и приёмка — отдельные результаты.

## P1 — стабильность, производительность и ресурсы

- [ ] Длительный Windows-прогон: быстрые нажатия/потерянный Release,
      sleep/resume, unplug USB-микрофона и смена устройства; закрытие приложения
      во время записи, STT, LLM, вставки и загрузки модели; crash/hang worker.
- [ ] Проверить два устройства/формата аудио, длинные записи и очередь API
      вместе с интерактивной диктовкой. Установить baseline потоков, handles,
      private bytes, CPU, потерянных frames и задержки очередей.
- [ ] Runtime soak/leak после warmup: 1000 циклов start/cancel, 100
      отказов/restart worker, отсутствие orphan процессов и возврат ресурсов к
      baseline в реальном Windows runtime.
- [ ] Измерить audio callback после warmup: allocations, p99 относительно
      callback period, отсутствие blocking I/O, dropped frames и overflow.
- [ ] Снять p50/p95/p99 отдельно для начала записи, Stop → capture, STT,
      обработки, вставки и подтверждённой команды. Холодную загрузку и первый
      inference считать отдельно от прогретой модели; оптимизировать холодный
      Vulkan по измерениям.
- [ ] Проверить выбранные LLM-серверы end-to-end: отмена, deadline,
      некорректный/большой ответ, вопросы внутри диктовки, пользовательские
      промпты и перевод. Общие инструкции не гарантируют поведение любой модели.
- [ ] Выполнять advisory-проверку текущего lockfile и согласовать регулярный
      CI gate. Неразрешённые исключения и порядок обновлений —
      [dependency-policy.md](dependency-policy.md).
- [ ] Добавлять property/concurrency/unsafe проверки там, где остаётся
      конкретный риск; оценить Loom/proptest/Miri для соответствующих границ.
- [ ] Проверить миграцию старых settings/history и восстановление backup
      после прерванной записи именно в установленной версии.

Ориентиры будущего soak: отсутствие монотонного роста threads/handles,
60 минут простоя, drift private bytes не более baseline + 10 MiB;
после циклов — baseline + max(5%, 10 MiB). Это цели для будущих измерений,
а не подтверждённые показатели приложения. Бюджеты закреплять вместе с
оборудованием и baseline; изменение объяснять результатом замеров.

## Отложенное решение — WakeWord

WakeWord сейчас выключен и недоступен в native/UI. Возвращение требует
отдельной задачи качества, ручной проверки голоса и согласования.

- [ ] Доработать качество потокового RU/EN detector и проверить набор
      готовых фраз и пользовательскую фразу.
- [ ] Проверить настройку фразы: пять образцов, три новых положительных
      и два отрицательных; при изменении фразы, устройства, модели или порогов
      инвалидировать профиль и требовать повторную проверку.
- [ ] Corpus с независимыми quiet/noisy positives и длительными negatives:
      цели recall ≥95% в тишине/≥90% в шуме, p95 срабатывания ≤800 мс,
      10 часов negatives. Короткие публичные WAV эти цели не подтверждают.
- [ ] При возврате проверить ready только после модели/микрофона,
      pre-roll, post-wake VAD-stop, ошибки/потерю пакетов, shutdown и 60-минутный
      idle soak одного AudioHub/detector.
- [ ] Включить диагностический replay в общий scheduling, чтобы ранее
      начатая диагностика не конкурировала с интерактивной диктовкой за CPU.

Методика и предыдущие ограниченные замеры:
[fono-voice-reliability.md](fono-voice-reliability.md).

## Отдельное решение — поэтапный вывод

Экспериментальный режим скрыт; классическая диктовка остаётся единственным
доступным режимом распознавания. Перед возвращением нужны отдельное
согласование и проверки стабильного префикса, смены поля, частичной вставки,
долгих записей, пауз и отмены. Существующие цели — p95 первого стабильного
текста ≤4 с и ухудшение WER относительно batch ≤2 п.п.; они пока не приняты.

## P2 — возможности после стабилизации

- [ ] Расширить GPU monitoring на несколько карт только с точной
      идентификацией используемой worker карты; не выбирать максимум чужой GPU.
- [ ] Command Agent через LLM: только отдельный явный запуск, строгая
      JSON-схема, валидированные аргументы, allowlist и подтверждение.
- [ ] Профили приложений и разрешённый контекст для обработки — после
      согласования UX и границ данных.
- [ ] Оценить Windows Authenticode отдельно от уже работающей подписи
      updater, если потребуется сертификат издателя.
- [ ] i18n и другие ОС — отдельный объём работ.

Эти пункты не обещаны ближайшему выпуску и требуют выбора следующего состава.
