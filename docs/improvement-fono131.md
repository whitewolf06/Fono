# FONO-131 — overlay правки и приватность

Исходники v0.7.46. Этап F-05.4 завершает реализацию цепочки
[FONO-128](improvement-fono128.md) → [FONO-129](improvement-fono129.md) →
[FONO-130](improvement-fono130.md). Зависимости остаются в `in_review`;
ручная приёмка всей истории FONO-60 пока не подтверждена.

## Поведение

После отдельного сочетания выделения Fono показывает существующий native overlay
без открытия и фокусировки главного окна. Настройки `focus: false` и
`focusable: false` сохранены. Здесь видны оригинал, инструкция, результат,
«Вставить», «Копировать» и «Отмена». Можно продиктовать инструкцию либо выбрать
формализацию, перевод на английский или сокращение до трёх пунктов. Ручной ввод
остаётся в основном редакторе; его подтверждение и возврат сочетанием из FONO-130
тоже сохранены. Запись микрофона и отправка в LLM требуют своих кнопок.

`SelectionOverlay.vue` используется в настоящем окне и browser preview `/overlay`.
Vue получает типизированный порт, не обращается к IPC, clipboard или window API.
Обычная диктовка имеет приоритет отображения; правка не заменяет её индикатор.
Окно меняет размер через существующий UI dispatcher и измерение содержимого.

Прямую вставку разрешает только IPC из overlay. Renderer передаёт selection ID
и result ID; текст, target и proof берутся из native session. Повторно
используется проверка окна/поля/выделения FONO-130. Первая попытка занимает
единственный слот; частичная и неизвестная отправка не повторяются. Ошибка
копирования/LLM/вставки оставляет доступ к тексту. Во время фоновой работы
«Отмена» отменяет свою операцию и сохраняет текст для восстановления. После
завершения отмены этой кнопкой можно закрыть сессию; уже принятые Windows
события отозвать нельзя.

## Настройки и история

- `selection_auto_insert` / `selectionAutoInsert` выключена по умолчанию,
  включая старые настройки. Только явно включённый режим для нового выделения
  разрешает отправку после успешного LLM. Повтор, target guard и проверки
  актуального результата сохраняются. Текущая настройка проверяется повторно.
- `selection_history_enabled` / `selectionHistoryEnabled` тоже выключена.
  Требуется одновременно общая история. Согласие фиксируется до получения
  выделения; включение сохранения позднее не разрешает архив старой сессии.
- Только успешное копирование либо полная подтверждённая отправка событий
  создаёт одну запись. Cancel, ошибка LLM, заблокированная/частичная/неизвестная
  отправка сами запись не создают. Copy после такой ошибки — отдельное принятое
  действие. Повторный Copy не дублирует архив.
- Сохраняется итоговый текст. Оригинал, инструкция, target, диапазон, clipboard
  backup и выдуманные STT-измерения не записываются. Запись исключена из речевой
  аналитики; новой фоновой LLM-обработки истории нет.
- Архивирование использует существующий Rust repository, срок хранения и события
  истории; выполняется на blocking delivery worker с admission lease фактической
  работы. Fence selection ID отсекает позднюю запись после Cancel/новой сессии.
  Текущие настройки удерживаются на время append, чтобы отзыв согласия не
  пересекался с записью. Ошибка хранения показана безопасным сообщением;
  автоматического повтора записи нет, текст остаётся для копирования.
- Browser demo хранит результат и демонстрационную историю только в памяти.
  В browser storage разрешены новые булевы предпочтения, без текстов и инструкций.
  Копирование в preview не меняет системный clipboard.

Перед LLM кнопка и пояснение явно сообщают о передаче выделения и инструкции
в выбранное подключение. Для облачного подключения данные получает провайдер;
отмена не отзывает уже отправленные данные. Диагностика и события не получают
сырого текста/ошибок/путей; selection events содержат только сигнал обновления.

## Проверки

- Native default: **586 passed, 0 failed, 7 ignored**, один полный запуск,
  `--test-threads=1`, изолированные данные и закреплённые Sherpa/ONNX DLL.
  Три новых теста проверяют отсутствие неявного согласия, отзыв согласия,
  однократный архив и отсутствие приватного материала/инструкции/STT-выдумок.
  Это unit/integration fixtures; реальные чужие поля и личный микрофон
  агентом не использовались.
- Strict Clippy all-targets, CPU-only и сборка без default features прошли.
- Release/CI contracts: **48/48**, включая 20 локальных cache-тестов пользователя,
  которые не входят в коммит FONO-131. Installer не собирался и не устанавливался.
- Полный V3 после проверки отмены: **313/313**, включая 86 целевых UI/adapter
  тестов. Проверены отмена с сохранением текста и запретом позднего архива,
  opt-in в момент capture/acceptance, один итог в истории, автоматический режим,
  безопасные IDs прямой доставки и доступ к Copy при неизвестном исходе.
- TypeScript, ESLint, production frontend build, version/format/Rustfmt и
  проверка локальных ссылок документации прошли. После Cargo выполнено штатное
  обслуживание кэшей.
- Browser mock: **720×560, 900×720, 1440×900**, общий компонент overlay.
  Преобразование, однократная демонстрационная замена, доступный Copy, Cancel,
  новая сессия и пример голосовой инструкции. Горизонтального переполнения нет;
  прокрутка сохраняет доступ к действиям. Screenshot:
  `build/checks/fono131-overlay-1440x900.png` (локальный, не включён в Git).

Логи находятся в `build/checks/fono131-*`. При первом V3-прогоне исправлено
ожидание новых opt-in флагов в старом тесте адаптера; неверный пример частичного
ввода в новом UI-тесте приведён к реальному lifecycle. Проверки не ослаблялись.

## Оставшаяся приёмка и ограничения

[Ручная матрица FONO-131](qa/voice-reliability.md#ручная-приёмка-overlay-правки--fono-131)
разделяет браузер, Word, VS Code и Telegram. Владелец проверяет native фокус,
выделение, микрофон/инструкцию, реальный LLM, rich clipboard, Cancel и смену поля.
Эта приёмка не выполнена агентом и не заменяется mock/unit tests.

Сохранены ограничения FONO-130: fallback Ctrl+C + способ вставки Clipboard
отклоняется; UIA + Clipboard и fallback + SendInput проходят собственные guards.
COM/Win32 не дают атомарной транзакции с произвольным редактором и не подтверждают
фактическое принятие событий чужим приложением. При неподтверждённой отправке
следует осмотреть поле перед ручной вставкой. Внешняя поздняя копия после
ограниченного fallback ожидания — также часть ручной Windows-проверки.

В предыдущем срезе FONO-130 два полных native-прогона имели разные сбои cleanup
fake worker; этот незакрытый qualification-хвост учитывается отдельно от overlay.
В единственном полном прогоне FONO-131 оба ранее падавших cleanup-теста прошли.
Критерии, таймауты и worker cleanup не менялись. Этот проход подтверждает текущий
набор, но не объясняет прежнюю нестабильность и не доказывает её устранение.

Новая сборка desktop/installer, чистая Windows, публикация и production-приёмка
в этот этап не входят. WakeWord и «На лету» остаются выключенными. Пользовательские
изменения cache scripts и PERF-04 не входят в локальный коммит FONO-131.
