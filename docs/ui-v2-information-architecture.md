# Fono UI v2: экраны и настройки

**Статус:** рабочий документ для обсуждения до реализации UI v2.  
**Источник фактов:** текущий контракт `Settings` в `src-tauri/src/types.rs`,
зеркальный TypeScript-тип `src/lib/types.ts`, экран `src/views/Settings.tsx`
и окна из `src-tauri/tauri.conf.json`.

Документ не меняет Rust runtime, сохранённые настройки или стабильный UI v1.
Он описывает, как разложить уже существующие возможности на понятный
интерфейс v2. Решения со статусом **предложение** должны быть утверждены до
реализации.

## 1. Что существует сейчас

### Реальные окна

| Поверхность | Статус | Назначение |
| --- | --- | --- |
| Основное окно `settings` | работает | Единственный большой экран: настройки, управление моделью, тесты и голосовые команды. |
| Overlay | работает | Отдельное прозрачное окно поверх других программ; показывает этап диктовки, таймер тишины, подтверждение и отмену. |
| Onboarding | есть в коде | Шесть информационных шагов; отдельное окно для него пока не объявлено в конфигурации Tauri. |

### Текущая проблема структуры

`Settings.tsx` объединяет постоянные пользовательские предпочтения, действия
с моделями, диагностику wake word, ручные тесты, журнал и список команд. Это
делает экран длинным и не показывает главное состояние приложения — готово ли
оно к диктовке прямо сейчас.

## 2. Целевая карта UI v2

Навигация основного окна: **Голос**, **Команды**, **Настройки**. В пункт
«Настройки» входят служебные разделы; диагностические инструменты не должны
занимать основной сценарий. История не добавляется до появления реального
persisted backend-контракта: нельзя создавать видимость истории только из
локального состояния интерфейса.

### 2.1 Голос — стартовый экран

**Цель:** за несколько секунд показать, готов ли Fono, и дать запустить
диктовку без перехода в настройки.

Состав:

- крупный статус: готов / слушаю / распознаю / обрабатываю / вставляю / ошибка;
- главная кнопка начала/остановки диктовки и подсказка текущей горячей клавиши;
- карточки «Микрофон», «Модель», «Wake word» с кратким состоянием и ссылкой в
  соответствующий подраздел настроек;
- краткий результат последней транскрипции только в рамках текущей сессии;
- быстрый переход к проверке микрофона и диагностике, когда есть ошибка;
- визуальная сцена из утверждённого forest-прототипа: фон, персонаж, волна и
  статус — без переноса бизнес-логики в JSX.

Карточки готовности — интерактивные: «Микрофон» ведёт в `settings/audio`,
«Модель» — в `settings/audio/model`, «Wake word» — в
`settings/activation/wake-word`. Если состояние не готово, карточка показывает
не только проблему, но и ближайшее действие для её устранения.

Состояния для mock-режима и поздней интеграции: `idle`, `listening`,
`transcribing`, `processing`, `injecting`, `error`; отдельно — диктовка и
голосовая команда.

`Голос` — исключение из обычной структуры страниц: ему **не нужен** верхний
`PageFrame`. Это главная сцена приложения, где активный пункт сайдбара уже
сообщает контекст. Центральный персонаж, статус диктовки, горячая клавиша и
текст транскрипции должны быть важнее повторного заголовка. Для этого экрана
используется отдельная композиция `VoiceStageLayout`.

### 2.2 Команды

**Цель:** объяснить и настроить то, что Fono уже умеет выполнять голосом.

Состав:

- горячая клавиша режима команд;
- встроенные команды: управление громкостью, медиа и переключение запущенных
  окон;
- список приложений для запуска: название, путь к `.exe`, произносимые
  алиасы;
- тест команды и понятный результат выполнения;
- блок будущего LM Studio command-agent — только как выключенная идея/roadmap,
  не как имитация несуществующей функции.

### 2.3 Настройки

Настройки открываются как самостоятельный экран с внутренней навигацией:

1. **Основное** — язык, способ вставки, автозапуск.
2. **Аудио и распознавание** — микрофон, модель Whisper, ускорение.
3. **Активация** — push-to-talk, wake word и его поведение после срабатывания.
4. **Overlay** — внешний вид и поведение плавающего индикатора.
5. **AI-обработка** — опциональная настройка LM Studio / внешнего LLM.
6. **Расширенные и диагностика** — тесты, логи и тонкая настройка порогов.

В каждом разделе действует принцип: частые настройки видны сразу, опасные или
специализированные — в раскрываемом блоке «Расширенные». Сохранение остаётся
явным там, где изменение перезапускает wake word или перерегистрирует горячие
клавиши; быстрые безопасные параметры могут применяться сразу с понятным
индикатором.

### 2.4 Overlay — отдельное окно

Overlay не является компонентом главной страницы: это отдельный webview с
самостоятельным жизненным циклом. Он должен сохранить:

- отображение текущего этапа конвейера;
- визуальный таймер тишины только во время wake-диктовки;
- кнопки «закончить и распознать» и «отмена»;
- перетаскивание, сохранение позиции, масштаб, прозрачность и режим
  отображения.

### Режимы отображения overlay

Режим выбирает объём информации, но не меняет правила записи, таймер или
жизненный цикл окна:

| Режим | Состав |
| --- | --- |
| **Минимальный** | Огонёк/индикатор, компактный таймер или progress-индикатор во время wake-диктовки и управляющие кнопки. |
| **Средний** | Огонёк/индикатор, текущий этап, режим «диктовка/команда», таймер wake-диктовки и управляющие кнопки. |
| **Подробный** | Всё из среднего режима, расширенные подписи состояния и подробное сообщение об ошибке, если оно есть. |

Во всех режимах отдельный чекбокс **«Показывать огонёк»** включает или
выключает только декоративный огонёк/индикатор. Текстовый статус, таймер и
управляющие кнопки не должны исчезать из-за этого чекбокса. Если под огоньком
будет использоваться персонаж Fono, он остаётся визуальной реализацией общего
индикатора. Каноническое техническое имя настройки — `overlay_show_indicator`.

В v2 меняется только представление и адаптер интерфейса; правила записи,
таймер и lifecycle остаются в Rust.

### 2.5 Onboarding

Предложение: короткий setup-flow без декоративных обещаний и без дублирования
всех настроек.

1. Что делает Fono и что остаётся локальным.
2. Проверка/выбор микрофона.
3. Выбор и загрузка модели Whisper.
4. Выбор основного способа активации: горячая клавиша или wake word.
5. Необязательная AI-обработка.
6. Проверочная диктовка и переход на экран «Голос».

## 3. Полный инвентарь текущих настроек

### Основное

| Параметр | Текущий ключ | Что делает | Рекомендация UI v2 |
| --- | --- | --- | --- |
| Язык распознавания | `language` | Автоопределение или выбранный язык Whisper. | Основное, рядом с аудио. |
| Способ вставки | `injection_mode` | `SendInput` либо вставка через буфер обмена. | Основное, с краткой подсказкой о совместимости. |
| Автозапуск Windows | `autostart` | Запускает Fono вместе с Windows. | Основное. |

### Аудио и распознавание

| Параметр/действие | Текущий ключ/команда | Что делает | Рекомендация UI v2 |
| --- | --- | --- | --- |
| Микрофон | `audio_device_id` | Выбор устройства; `null` означает системное устройство по умолчанию. | Основное поле раздела. |
| Тест микрофона | runtime-команда | Показывает уровень входного сигнала. | Быстрое действие рядом с выбором микрофона, не настройка. |
| Модель Whisper | `whisper_model_path` | Выбранная локальная модель STT. | Карточка состояния: модель, размер, скачать/выбрать/заменить. |
| Ускорение | `acceleration` | `auto`, CUDA, Vulkan или CPU; доступность CUDA/Vulkan приходит из релиза. | Один select с «Авто (рекомендуется)»; CPU подписать как режим совместимости. |

### Активация и диктовка

| Параметр | Текущий ключ | Что делает | Рекомендация UI v2 |
| --- | --- | --- | --- |
| Горячая клавиша диктовки | `hotkey` | Global push-to-talk. | Основной элемент раздела «Активация». |
| Горячая клавиша команд | `command_hotkey` | Запускает отдельный режим голосовых команд. | На экране «Команды»; не смешивать с повседневной диктовкой. |
| Wake word: включён | `wake_word_enabled` | Включает постоянное ожидание фразы. | Главный toggle в разделе wake word. |
| Фраза | `wake_word` | Фраза, после которой начинается диктовка. | Поле с сообщением о применении и поддержке backend. |
| Backend | `wake_backend` | Sherpa-ONNX, экспериментальный Whisper или mock. | «Sherpa-ONNX» и «Whisper» как выбор пользователя; mock только в диагностике. |
| Модель для Whisper wake word | `wake_word_model` | Размер Whisper-модели, если выбран экспериментальный backend. | Показывать условно, только для этого backend. |
| Порог срабатывания | `wake_word_threshold` | Компромисс между чувствительностью и ложными срабатываниями. | Расширенная настройка. |
| Sensitivity | `wake_word_sensitivity` | Внутренний коэффициент чувствительности backend. | Расширенная настройка; объяснять применимость к выбранному backend. |
| VAD-порог | `wake_word_vad_threshold` | Минимальный уровень для начала речи в wake-пайплайне. | Расширенная настройка/диагностика. |
| Пауза до распознавания | `wake_dictation_silence_ms` | Сколько тишины завершает диктовку после wake word. | Обычная настройка wake word; именно её показывает таймер overlay. |
| Порог окончания диктовки | `wake_dictation_speech_threshold` | RMS-порог, по которому определяется тишина. | Расширенная настройка рядом с паузой. |

| Параметр | Текущий ключ | Что делает | Рекомендация UI v2 |
| --- | --- | --- | --- |

### Голосовые команды

| Параметр | Текущий ключ | Что делает | Рекомендация UI v2 |
| --- | --- | --- | --- |
| Приложения для запуска | `launch_apps` | Имя, путь к `.exe` и алиасы. | Управление на экране «Команды»; алиасы должны стать редактируемыми, а не скрытыми в данных. |
| Шаг громкости | `volume_step` | Шаг для «громче»/«тише». | Расширенная настройка команд. |

### Диагностика и сервисные действия

Это не основные настройки. Их следует открыть через «Расширенные и
диагностика», с явными подписями, что они нужны при неполадках.

- загрузка и наличие KWS-модели Sherpa;
- диагностический статус wake word: событие, RMS, peak, кадры, последнее
  ключевое слово;
- запись/распознавание тестового аудио и ручной тест диктовки;
- тест распознавания wake word из записи;
- просмотр и очистка логов;
- `verbose_logging` — переключатель подробных логов.

## 4. Технические замечания перед UI v2

- `use_gpu` — legacy-поле для чтения старых `settings.json`; его нельзя
  возвращать в интерфейс. Единственный пользовательский выбор —
  `acceleration`.
- Координаты overlay сохраняются автоматически и не должны быть отдельными
  числовыми полями.
- `overlay_scale` масштабирует выбранный режим отображения; он не заменяет
  выбор режима и не должен скрывать управляющие кнопки.
- `overlay_mini_mode` сохраняется для чтения старых конфигураций, но в новом
  контракте заменяется на `overlay_detail_level`: `false` преобразуется в
  `detailed`, `true` — в `minimal`. Новая настройка
  `overlay_show_indicator` по умолчанию включена.
- Отключение огонька не должно ухудшать доступность: состояние должно быть
  понятно по тексту, таймеру, цвету и доступным подписям элементов.
- Изменение горячих клавиш может быть отклонено, если их нельзя
  зарегистрировать; UI должен показать ошибку и сохранить старое значение.
- Изменение параметров wake word может перезапускать detector. UI должен
  сообщать об этом и показывать состояние запуска, а не оптимистично считать
  настройку рабочей.
- Настройки остаются единым контрактом Rust/TypeScript. UI v2 не меняет
  названия ключей или их смысл без отдельной миграции конфигурации.

## 5. UI kit: каталог компонентов

UI kit находится в `src/v2/shared/presentation/`. Dev-экран `UI kit` показывает
визуальные состояния компонентов на моках; он доступен только при локальном
запуске UI v2 и не является пользовательским разделом приложения.

Имена ниже описывают целевые роли дизайн-системы. На текущем этапе отдельными
React-компонентами уже являются `AppIcon`, `StatusDot` и `PageFrame`; остальные
элементы пока демонстрируются в dev UI kit как композиции и стили. Выделять их
в самостоятельные файлы следует только перед вторым реальным использованием.

### Структурные компоненты

| Компонент | Назначение | Где применять |
| --- | --- | --- |
| `AppShell` | Общая оболочка: сайдбар, content-область и, при необходимости, контекстная колонка. | Все основные окна UI v2. |
| `PageFrame` | Иконка, заголовок, короткое описание и slot для содержимого. | Команды, Настройки, Диагностика; **не** главная сцена «Голос». |
| `VoiceStageLayout` | Свободная сценическая композиция для статуса, персонажа, волны и текста. | Только главный экран «Голос». |
| `GlassCard` | Базовая полупрозрачная liquid-glass поверхность. | Карточки статуса, настроек, обзорные блоки. |
| `FeatureCard` | Карточка с иконкой, описанием и действием; есть обычный и рекомендованный варианты. | Настройки, onboarding, быстрые исправления проблем. |

### Навигация и выбор

| Компонент | Состояния | Назначение |
| --- | --- | --- |
| `SidebarNavigationItem` | default, hover, active, focus | Основная навигация. Активный вариант использует светящийся контур. |
| `Tabs` | default, active, hover, focus | Переключение компактных взаимосвязанных разделов в одной карточке. |
| `Accordion` / `AdvancedSection` | collapsed, expanded | Скрытие тонких и диагностических параметров до явного раскрытия. |
| `DropdownMenu` | closed, open, destructive item | Меню `…` для второстепенных действий с карточкой или элементом списка. |

### Формы и действия

| Компонент | Состояния | Назначение |
| --- | --- | --- |
| `GlowOutlineButton` | default, hover, active, disabled, focus | Акцентная кнопка с неравномерной светящейся рамкой; анимация блика только на hover. |
| `Button` | primary, secondary, ghost, destructive, disabled, loading | Обычные действия. Destructive всегда открывает подтверждение. |
| `IconButton` | default, hover, focus, disabled | Компактные действия: меню, стоп, настройки. |
| `TextInput` | default, focus, error, disabled | Короткие текстовые значения: фраза wake word, URL, путь. |
| `Textarea` | default, focus, error, disabled | Многострочные инструкции и prompt очистки текста. |
| `Select` | default, focus, disabled | Выбор модели, ускорения, языка, провайдера. Визуально оформляется как кастомный control, но сохраняет нативную доступность. |
| `Checkbox` | unchecked, checked, disabled | Независимые опции: автозапуск, показ индикатора. |
| `RadioGroup` | unchecked, checked, disabled | Взаимоисключающие варианты: способ вставки текста. |
| `Switch` | off, on, disabled | Быстрые булевы настройки: wake word, overlay. |
| `Range` | default, focus, disabled | Непрерывные значения: чувствительность, прозрачность, масштаб. |
| `ShortcutRecorder` | idle, recording, valid, conflict, error | Запись глобальной горячей клавиши вместо ручного текстового ввода. |
| `InlineValidation` | hint, warning, error, success | Пояснение или ошибка непосредственно под полем; не заменяет toast. |

### Состояния системы и обратная связь

| Компонент | Состояния | Назначение |
| --- | --- | --- |
| `StatusDot` / `StatusChip` | ready, active, muted, warning, error | Компактное отображение готовности микрофона, модели и wake word. |
| `ProgressBar` | idle, determinate, complete, error | Скачивание модели и подготовка worker. |
| `Skeleton` | loading | Плейсхолдер при загрузке списка устройств или модели. |
| `EmptyState` | empty with action | Отсутствие приложений для команд, истории или моделей. |
| `Toast` | success, warning, error, info | Краткое неблокирующее подтверждение после действия. |
| `Modal` / `ConfirmDialog` | open, destructive, loading | Подтверждение очистки логов, удаления приложения и других необратимых действий. |
| `Tooltip` | hidden, visible | Короткое объяснение VAD, CUDA/Vulkan и технических параметров. |

### Правила применения UI kit

1. Новый экран сначала собирается из существующих примитивов и только затем
   добавляет новый компонент, если аналог уже нельзя выразить композиционно.
2. `shared/` содержит компонент только после второго реального потребителя.
   До этого компонент остаётся в `presentation` соответствующей фичи.
3. Нативные вызовы и бизнес-правила не помещаются в UI kit. Компоненты получают
   типизированные props и callbacks.
4. Для destructive-действий обязательна схема: действие → `ConfirmDialog` →
   подтверждение → выполнение → `Toast` с результатом.
5. Технические настройки по умолчанию показываются в `AdvancedSection`; не
   перегружать ими обычные пользовательские сценарии.

## 6. Граница следующего этапа

После утверждения этого документа следующий этап — не интеграция с Rust, а:

1. mock-режим и typed runtime-port для UI без Tauri;
2. общие токены, базовые UI-компоненты и app shell;
3. экран «Голос» на мок-состояниях;
4. только затем последовательное подключение настоящего IPC по фичам.

Так дизайн можно менять быстро, не пересобирая нативную часть и не рискуя
рабочей диктовкой.
