## Исправление кнопки записи — v0.7.69

После обычной диктовки кнопка «Записать» оставалась выключенной даже при
подтверждённом согласии: форма разрешала запуск только в состояниях `idle`
и `error`, хотя `done` и `cancelled` тоже означают завершённую диктовку.
Теперь форма использует общий `captureSettingsLocked`: активная запись,
распознавание, обработка и ожидающий решения результат продолжают блокировать
новый захват. При занятой диктовке рядом показана причина блокировки.

В отдельном headless-браузере реальный Vue-компонент и checkbox сначала
воспроизвели ошибку: `done`, согласие включено, кнопка выключена. После
исправления на 720×560, 900×720 и 1440×900 проверены четыре завершённых/
свободных состояния и пять активных, включение и снятие согласия,
вызов тестового backend после клика и доступность повтора после его ошибки.
Тестовый backend микрофон не открывает. JS-ошибок и горизонтального
переполнения не было.

Изменение только во frontend: открытый native dev 0.7.68 получает его через
горячее обновление Vite. Rust и сохранённые образцы не изменяются; новый
native EXE для этого исправления не собирался. Версия исходников 0.7.69
не означает пересборку или публикацию установщика.

## Что изменилось

По умолчанию форма «Настройки → Кнопки и активация → Записи для WakeWord»
открывает «Привет, Лира». В список добавлены два прежних набора: «Эй, Фоно»
и «Hey Fono». Их можно прослушивать и удалять; новая запись доступна для Лиры.
Счётчик учитывает идентификатор фразы, язык, тип и условия записи. Старые
36 образцов не засчитываются в новый набор и не переименовываются.

Сохранение использует `fono-wake-recording@2`: `sample.phraseId=privet_lira`
и канонический текст `phrase=Привет, Лира`. Старые `@1` без phraseId читаются
как `hey_fono`. Входящий старый IPC request без ID тоже означает прежнюю
фразу, а не текущий выбор UI. Недопустимое сочетание Лиры с EN отклоняется
до захвата; английская версия новой фразы не придумана автоматически.
Противоречивый текст/ID записи отклоняется при чтении списка и прослушивании.

Сохранены общий AudioHub, ID до очереди, admission lease до завершения I/O,
адресные Stop/Cancel, таймер и проверка потерь аудио. По-прежнему нужны
согласие владельца и явная кнопка. WAV остаются локально, вне Git, истории
диктовок, REST API и диагностического экспорта. Browser mock не записывает
микрофон и не создаёт успешных фиктивных образцов.

## Один проход записи владельцем

1. Выбрать «Привет, Лира» и подтвердить локальное сохранение.
2. «Фраза пробуждения», «Тихая комната»: 5 записей по одному произнесению.
3. То же с обычным фоновым звуком: ещё 5 записей. Говорить обычным голосом.
4. «Речь без фразы пробуждения»: 3 записи примерно по 20 секунд. Упомянуть
   iPhone и похожие обращения «Привет, Лера», «Привет, Мира». Полную
   «Привет, Лира» в этих записях не произносить.
5. «Фоновый звук без речи»: одна запись примерно на 20 секунд. Прослушать
   результаты и удалить оговорки или обрезанные примеры.

Эти числа — небольшой первый dev-набор, а не заменённые критерии качества.
Для записей нужны реальные звуки комнаты; цифровые нули не доказывают
устойчивость к фону. Агент микрофон не включает и пользовательским окном
не управляет.

## Подготовленная проверка данных

`tools/wake-bench/recordings.py` проверяет согласие, dev split, обе версии
metadata, принадлежность фразе, формат/хэш/длительность WAV. Он только
читает файлы, отдельно считает цифровую тишину и выдаёт агрегированный
отчёт без путей, пользовательских ID/хэшей, текста и аудио.

```powershell
python tools/wake-bench/recordings.py `
  --root build/dev-desktop-profile/wake-recordings --phrase-id privet_lira
python -m unittest discover -s tools/wake-bench -p 'test_*.py' -v
```

Нужен Python 3.12+, сторонних Python-пакетов для аудита нет. Первичная
проверка перед записью: **0 образцов Лиры, 36 прежних**, `quality_measured=false`.
Это подтверждает разделение наборов, а не качество распознавания.

## Что осталось после записи

Проверить реальные произнесения и отрицательные примеры, затем один
ограниченный обучающий/измерительный раунд для **новой** фразы. Обязательно
оставить iPhone и обычную речь в негативном контроле, учитывать пропуски,
не выдавать отсеивание всех входов за устранение ложных срабатываний.
Личные dev-записи не объявлять независимым общим test.

Исходные цели W-02 сохранены: ≥95% quiet / ≥90% noisy recall, ≤0,5 FA/h,
p95≤800 мс, idle CPU<1% одного ядра; 100–300 произнесений разных людей/
микрофонов и ≥10 часов разрешённых негативов. Короткий проход владельца
не закрывает эти проверки. У новой фразы пока нет принятой модели,
download artifact или законченной интеграции FONO-145. FONO-144 остаётся
в работе, FONO-146 — отдельная персонализация.
