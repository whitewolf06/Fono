# FONO-119 — сравнение CPU-движков

Результат для ревью, версия 0.7.34. Зависимости FONO-115, FONO-118 и CI-03
использованы как источник runtime, закреплённых моделей и публичного корпуса.
Задача не включает настройку личного голоса, установку или публикацию release.

## Методика

Один компьютер, последовательный запуск трёх движков: GigaAM v3 e2e RNNT INT8,
Parakeet TDT 0.6B v3 INT8 и Whisper Large v3 Turbo FP16. Каждый запускается
в отдельном процессе одного и того же native test runner. Профиль — debug;
результат не является замером поставляемой release-сборки.

Используются 20 FLEURS WAV из CI-03: 10 RU (133,48 с, 205 слов) и 10 EN
(101,88 с, 245 слов). GigaAM не поддерживает английский; эти 10 записей имеют
статус `unsupported`, их знаменатель не участвует в русской метрике.
FLEURS, The Google and HuggingFace Datasets Authors (2022), CC-BY-4.0;
[закреплённая карточка источника](https://huggingface.co/datasets/google/fleurs/blob/437d9e667fa3a2a08a1957f810bf2c3b5050d221/README.md).

Каждый WAV проверяется по SHA256, проходит production `decode_file`, речевой
Silero VAD, `prepare_recording_with_result` с сохранением полного PCM и общее
разбиение по паузам с пределом 25 секунд. Все движки получают одинаковые PCM
и границы сегментов. Отчёт сохраняет их SHA256, речевое решение и границы;
collector отклоняет несовпадение входа. Пустая гипотеза при false negative VAD
остаётся ошибкой распознавания, запись не исчезает из знаменателя.

Распознавание проходит через production `SttEngine`, общий интерфейс окон и
`transcribe_segments`; контекст словаря/LLM не добавляется. CPU выбран явно,
backend проверяется в результате. Whisper использует fast / 8 потоков;
GigaAM и Parakeet — production greedy / 2 потока. Это сравнение существующих
конфигураций Fono, а не поиск лучших параметров каждого движка.

После загрузки каждый движок один раз распознаёт одинаковый `ru-01` для cold
замера, затем весь поддерживаемый корпус для warm-серии. Load включает
подготовку native-контекста и проверки файлов, но исключает запуск процесса.
Warm wall time включает все сегменты одной фразы и их объединение; не включает
декодирование исходного файла, VAD, model load, LLM, вставку и Tauri UI.
RTF — сумма warm секунд / сумма исходных аудиосекунд; меньше — быстрее.

WER/CER вычисляются общим CI-03 scorer: Unicode lower-case, буквы и числа,
без пунктуации. Числа словами/цифрами отдельно не нормализуются. Результаты
малого набора не заменяют проверку акцентов, шума, терминов и личного голоса.
Одна cold попытка и одна warm серия не дают статистической оценки latency.

## Воспроизведение

Используйте окружение из `docs/development.md`: проверенный shared sherpa/ORT,
CPU-сборку без CUDA/Vulkan, `CARGO_TARGET_DIR=src-tauri/target-codex-review` и
изолированные `FONO_TEST_DATA_DIR` / `FONO_API_PORT`. Не запускайте приложение.

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --locked -p fono --lib --no-run --message-format=json > build/comparison-artifacts.jsonl
node scripts/native-test-runtime.mjs build/comparison-artifacts.jsonl $env:SHERPA_ONNX_LIB_DIR $env:CARGO_TARGET_DIR
```

Из JSON Cargo возьмите путь к executable с `profile.test=true`. Передайте его
collector вместе с каталогом закреплённых Whisper и offline-пакетов:

```powershell
node scripts/stt-model-comparison.mjs NATIVE_TEST_EXE build/stt-quantized/models build/stt-offline build/stt-comparison/report.json
node scripts/export-stt-comparison.mjs build/stt-comparison/report.json
```

Collector проверяет точные размеры/hash моделей, WAV и идентичность входа,
запускает только явный ignored test и сохраняет состояние после каждой фразы.
Лимит — шесть минут на модель, без автоматических повторов. Незавершённая
серия не получает итоговый WER/RTF и не экспортируется в подсказки UI.

Первая попытка обнаружила ошибку самого измерительного адаптера: настройки
Whisper были переданы offline-движкам. Исправлено использование capabilities;
фактический повтор сохраняет native параметры каждой модели. Первый запуск
не смешивается с финальными данными. Production-декодеры не менялись.

## Полученные результаты

На Intel Core i5-12600KF GigaAM завершил 10 RU WAV: WER 1,95%, CER 0,34%,
RTF 0,059. Parakeet завершил обе части: RU — WER 11,22%, CER 4,31%, RTF 0,090;
EN — WER 15,51%, CER 12,65%, RTF 0,085. На данном русском наборе у GigaAM
меньше ошибок и warm времени. Эти данные не обобщаются на другие голоса.

GigaAM: load 4,294 с, первый `ru-01` 1,324 с, средняя warm RU-фраза 0,787 с.
Parakeet: load 11,868 с, первый `ru-01` 1,402 с, средняя warm RU-фраза 1,198 с.
Отдельные load/cold числа не являются p95 и не гарантируют задержку приложения.

Подробная таблица находится в [README](../../../README.md#cpu-engine-comparison).
Сырые гипотезы, счётчики, хэши моделей, VAD, PCM, границы сегментов, hardware и
source lineage сохранены в [fono119-comparison.json](evidence/fono119-comparison.json).
Закреплённые источники весов берутся из существующих manifest FONO-115/118;
новые веса, токены или закрытые аудиоданные не добавлялись в Git.

В V3 отображаются только фактически завершённые измерения для точного набора
имён/размеров/SHA256 артефактов. При изменении пакета, неизвестной или
квантованной модели старая цифра не наследуется. Browser mock показывает те же
опубликованные данные с обычной маркировкой демонстрации. Неподдерживаемый EN
имеет явную подпись, а не нулевой WER.

## Проверка изменения

Пройдены 507 штатных native-тестов; 6 проверок с внешними ресурсами/soak по
умолчанию пропущены. Новый ignored comparison явно выполнен для трёх моделей:
GigaAM и Parakeet завершены, Whisper остановлен лимитом, как описано ниже.
Пройдены strict Clippy всех app targets и CPU-only check.

Пройдены 280 UI-тестов, 48 release/CI-контрактов и 35 quality-контрактов,
включая 6 новых проверок сравнения и экспорта. Они проверяют unsupported EN,
сохранение пустых гипотез в знаменателе, неполный корпус, PCM и границы,
невалидные длительности, отказ экспорта незавершённой серии и точное
сопоставление измерений с артефактами модели. Новые проверки включены в
`stt-quality.yml`. Успешны typecheck, lint, build, format, version и local links.

При экспорте итоговые счётчики повторно вычислены по сырым гипотезам без
повторного STT. SHA256 evidence совпадает с UI snapshot, хэши PCM и границ
совпали у всех трёх процессов, включая частичный Whisper. Метаданные
разделяют collector исходного запуска и verifier перед экспортом.
Замер снят с рабочего состояния 0.7.34 поверх `bb9a75b`: `source_revision`
обозначает базовый HEAD, а hash test runner и нового native helper фиксируют
исполненное измерительное состояние. Production-код движков соответствует базе.

Браузерный mock проверен при 720×560, 900×720 и 1440×900. Метрики GigaAM и
Parakeet, `EN: не поддерживается` и предупреждение о незавершённых сериях
видны; переполнений документа и строк нет. Tauri UI и пользовательское
приложение автоматически не открывались. Production-распознавание и
настройки не менялись; native-добавление существует только под `cfg(test)`.

## Хвосты

- Полная серия Whisper Large v3 Turbo FP16: native-процесс достиг лимита
  шесть минут, завершив 9 из 20 warm WAV. Состояние `incomplete / ETIMEDOUT`,
  частичные гипотезы и preprocessing сохранены отдельно от итоговых метрик.
  Прогон не повторялся; перенос цифр из FONO-118 или старого Tiny baseline
  не выполнялся. Это открытая часть исходного критерия FONO-119.
- Полное CPU-сравнение квантованных вариантов из FONO-118 остаётся там же
  открытым. Эта задача не утверждает прохождение quantization CI-03.
- Повторные AB/BA серии, release/GPU и end-to-end latency, длительные записи,
  шум, термины и личный голос требуют отдельной приёмки. Числовые показатели
  этого небольшого корпуса не являются обещанием для пользователя.
- Remote CI, переключение через установленный desktop и чистая Windows не
  проверялись. Installer, установка и публикация не выполнялись.
