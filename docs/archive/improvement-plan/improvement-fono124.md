# FONO-124 — проверка длинной диктовки

Версия 0.7.39. Зависимости FONO-122 (`73331e0`, 0.7.37), FONO-123
(`3efe312`, 0.7.38) и CI-03/FONO-108 проверены перед работой.
Результат подготовлен для ревью; полной приёмки F-02 нет.
Предварительное распознавание остаётся выключенным по умолчанию.

## Исходные требования и условия проверки

Карточка [FONO-124](https://kvorum.gorbach-dev.ru/tasks/FONO-124/f-02-5)
требует сравнить обычный Stop и предварительное распознавание одинаковых
длинных WAV: WER/CER, Stop → готовый текст, память, отмену и конкуренцию API.
Критерии: для 60 секунд после Stop обрабатывается хвост, WER не хуже
контрольного распознавания, Cancel не оставляет работы. Цель roadmap
1–3 секунды не становится подтверждённой характеристикой без измерения.

Для этого прохода выбраны Tiny с закреплённым SHA256 из CI-03, Fast,
8 потоков, debug host, явный CPU или Vulkan. Это условия ограниченного
smoke-прогона, а не новые продуктовые требования. Другие модели и профили
этот результат не квалифицирует. Сделано ровно по одной попытке на backend;
автоповторов и подбора параметров нет.

Две записи состоят из первых четырёх целых RU и первых шести целых EN
фрагментов FLEURS из CI-03. Между ними и перед первым добавлена тишина,
после последнего — 100 мс. Получено ровно 960 000 сэмплов, 16 кГц mono,
60 секунд. Речь не обрезалась, выбор не зависел от результата STT.
Это разные дикторы и отдельные предложения, а не естественные монологи.
Происхождение и условия использования — в [NOTICE](../../evidence/licenses/fono124-long-dictation-NOTICE.md).

Контрольная пара использует один и тот же декодированный PCM, модель,
язык, настройки и фактический backend. Старые 18,89% WER CI-03 относятся
к двадцати коротким записям и другому replay: переносить это число на новые
60-секундные WAV нельзя. Принятый файл baseline CI-03 не изменён.

## Реализация проверки

- Блокирующий финализатор Stop вынесен в `segment_completion::Runtime::finish`.
  Desktop и replay вызывают один код планирования хвоста, VAD, scheduler,
  загрузки модели, ограниченного контекста и склейки. Обёртка desktop
  сохраняет `spawn_blocking`, cancellation и activity lease.
- Ignored native-тест `long_dictation_public_replay` подаёт PCM в настоящий
  bounded writer по 1600 сэмплов каждые 100 мс. Используются production
  capture consumer, порог 15 секунд, операция и scheduler. Подменён только
  физический источник аудио; микрофон, Tauri-окна, LLM и вставка не вызываются.
- Проверяются сохранность PCM, разделение префикса/хвоста и реальный backend.
  Сервисная полоса scheduler ждёт завершения интерактивной операции.
  Проверка отмены начинает настоящую STT-работу и ждёт её фактического join.
- `long-dictation-quality.mjs` проверяет WAV и модель, фиксирует хеши бинарника
  теста, runtime DLL, VAD и worker, сохраняет исходники/настройки и оценивает
  Unicode WER/CER общим scorer CI-03. Полного результата для незавершённого
  backend не создаёт. CI запускает пять быстрых тестов сборщика; реальные
  распознавания остаются явно запускаемой проверкой.
- Windows-метрики и защита дочерних процессов используются из одного
  test-only модуля. Каждый replay ограничен 240 секундами и собственным
  kill-on-close job; установленное приложение в него не входит.

## Полученные результаты

Полные данные, тексты публичного корпуса, хеши и границы диапазонов:
[fono124-long-dictation.json](evidence/fono124-long-dictation.json).

| Backend / язык | WER batch → пред. | CER batch → пред. | Stop batch, с | Таймер пред., с† |   Хвост, с |
| -------------- | ----------------: | ----------------: | ------------: | ---------------: | ---------: |
| CPU / RU       |   56,45% → 24,19% |    42,38% → 5,52% |         1,288 |            1,411 |     11,119 |
| CPU / EN       |   71,77% → 16,13% |    66,11% → 6,16% |         3,196 |            1,271 |      7,343 |
| Vulkan / RU    |   56,45% → 24,19% |    42,38% → 5,30% |         7,638 |            5,505 |     11,119 |
| Vulkan / EN    |   нет полной пары |   нет полной пары |   не сохранён |     timeout 34 с | не измерен |

† В сохранённых измерениях таймер предварительного Stop включает один
дополнительный проверочный проход VAD по хвосту. Поэтому это верхние оценки
задержки ядра; дополнительные расходы Tauri/UI/LLM/вставки сюда не входят.
В финальном тесте аудит вынесен за таймер. После этой поправки распознавания
не повторялись. Разница 0,123 с на CPU/RU не доказывает регрессию production
Stop. Цель 1–3 с для desktop и Vulkan этим проходом не подтверждена.

В трёх завершённых парах WER/CER улучшились относительно соответствующего
batch, префикс переиспользован, полного fallback не было. Готово 48,881 с
RU и 52,657 с EN; весь оставшийся PCM входит в хвост без потери диапазонов.
Высокий WER batch на этой смеси дикторов — реальный результат данного
корпуса и Tiny, не оценка обычных коротких диктовок или других моделей.

CPU Cancel запросили во время настоящего распознавания: join — 0,603 с,
после него активных inference — 0, scheduler свободен, activity lease
освобождён после cleanup. За отдельные 100 мс покоя CPU-время процесса
не увеличилось. Общие 0,704 с в `cleanup_seconds` включают эту проверку покоя.
Сервисная полоса вошла только после завершения интерактивной операции.
Это проверка общего scheduler, не HTTP-нагрузка через API.

Память — sampled private bytes тестового процесса с интервалом 100 мс.
На CPU максимум batch/пред.: RU 748,9/765,9 МиБ, EN 753,3/767,5 МиБ.
На Vulkan/RU — 35,2/43,0 МиБ только основного тестового процесса.
RAM worker и VRAM сюда не входят; это не полный расход Fono и не доказательство утечки.

Vulkan/EN завершился ошибкой при join предварительного consumer:
`worker_request_timeout`, 34 с. Native-тест остановился, сохранив RU-пару;
полные EN-метрики и GPU Cancel отсутствуют. Сам пользовательский dev не падал.
В production для ошибки consumer предусмотрен обычный Stop по всей записи,
но этот реальный GPU fallback данным прогоном не подтверждён.

Сборщик CPU-отчёта сначала ошибочно сравнил сырой WAV PCM с декодированным.
Производственный PCM16 → f32 → i16 меняет 61 сильный EN-сэмпл на один LSB.
Исправлен строгий расчёт ожидаемого хеша, добавлен отдельный тест границ.
CPU-данные пересчитаны офлайн из сохранённого native JSON без новых STT-запусков.
История поправки и исходная lineage сохранены в evidence. SHA256 реально
выбранного `resources/stt-workers` совпадает с копией `stt-base`, указанной
в исходном отчёте; сборщик теперь явно учитывает порядок выбора worker.

## Запуск dev и проверки

По отдельной просьбе собран и запущен настоящий desktop dev 0.7.39
в изолированном профиле. Владелец подтвердил появление интерфейса.
Установленный Fono не остановлен; личные история и настройки не переносились.

При запуске исправлены два дефекта: `custom-protocol` больше не включён
безусловно у Tauri dependency, поэтому dev читает Vite вместо старого `dist`;
окна создаются после регистрации состояния и сервисов Rust. Frontend имеет
одно ожидание readiness без постоянного IPC-опроса. Параметры основного окна
и overlay, включая `focus: false` / `focusable: false`, сохранены.

Прошли TypeScript, lint, frontend build, 289 тестов V3, 48 release/CI-тестов,
27 quality-contract тестов и пять тестов нового сборщика. Прошли strict Clippy,
Rustfmt, проверки `custom-protocol`, CPU-only и no-default-features.
Полный последовательный native-прогон: 527 passed, 7 ignored.
В первом параллельном прогоне два старых worker cleanup-теста упали;
последовательный прошёл с исходными таймаутами. Таймауты не увеличивались.
Проверялось рабочее дерево с ранее существовавшими правками обслуживания кэша;
они сохранены и в коммит FONO-124 не включены.

## Хвосты

- Разобрать timeout Vulkan/EN и проверить реальный полный fallback и GPU Cancel.
  По незавершённому сценарию нет принятого WER/Stop-результата.
- Повторная проверка точного Stop с исправленным таймером, полный расход
  RAM worker/VRAM и конкуренция API через HTTP. Принятый baseline не заменён.
  Другие модели, естественные монологи и production-сборка — расширение
  покрытия; они не объявляются новыми условиями исходной карточки.
- Стабильность старых worker cleanup-тестов при параллельном запуске.
- Голос, hotkey, поля и overlay проверяет владелец. Матрица browser mock
  720×560 / 900×720 / 1440×900 в этом проходе не выполнялась. Подтверждение
  открытия dev-интерфейса не является такой матрицей или голосовой приёмкой.
- Remote CI, installer, публикация, установка и чистая Windows не выполнялись.

Для воспроизведения сначала подготовить native-окружение по
[инструкции CI](../../fono-ci-updates.md), собрать lib-тесты с Cargo JSON и
положить проверенные DLL через `scripts/native-test-runtime.mjs`.
Затем явно передать путь этого тестового EXE и закреплённого Tiny:

```powershell
node scripts/long-dictation-quality.mjs ABSOLUTE_NATIVE_TEST_EXE build/stt-quality/ggml-tiny.bin cpu build/fono124-long/cpu
node scripts/long-dictation-quality.mjs ABSOLUTE_NATIVE_TEST_EXE build/stt-quality/ggml-tiny.bin vulkan build/fono124-long/vulkan
npm run cache:maintain
```

Это команды для отдельного согласованного повторения, а не указание повторять
проверку до желаемых чисел. Сохранённые артефакты относятся к описанным выше
двум попыткам; вторая GPU-попытка в рамках задачи не запускалась.
