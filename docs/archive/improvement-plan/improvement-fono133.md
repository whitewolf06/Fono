# FONO-133 — профили приложений

Исходники v0.7.48, 21 октября 2026 года. Реализован F-06.1 из родительской
истории FONO-61. У карточки нет отдельных блокирующих dependency links;
использованы существующие snapshot, overlay choice, CLI admission и защищённая
вставка. Исходный код перед началом — v0.7.47 / `6bd1e7c`.
Задача передаётся в `in_review`; работа в настоящих VS Code/терминале остаётся
ручной приёмкой, родительская история — в `in_progress`.

## Поведение

В **Настройки → Основные → Профили приложений** можно добавить, изменить,
отключить и удалить профиль. Он содержит название, список имён exe и
необязательные overrides: включение обработки, стиль, включение перевода,
язык перевода, язык распознавания и способ вставки. Каждый параметр может
наследовать общую настройку. Новая установка и старые настройки имеют пустой
список профилей. Отключение сохраняет все значения.

Изменения применяются после общего «Сохранить» и для следующей диктовки.
Поддерживаются до 32 профилей, до 16 exe в каждом; одно имя exe относится к
одному профилю, сравнение без учёта регистра. Пути, шаблоны, управляющие символы
и неоднозначные правила отклоняются. Распознавание в редакторе поддерживает
те же варианты, что общая форма: русский, английский и авто. Несовместимый
с выбранной моделью язык останавливает запуск с ошибкой, без отправки текста.

Приоритет внутри сессии:

1. Ручной выбор в overlay, применённый после успешного сохранения.
2. Совпавший включённый профиль приложения.
3. Глобальные настройки для остальных полей и неизвестного приложения.

Автоматически выбранный профиль не переписывает глобальные параметры.
Ручной выбор обработки сохраняется прежним delta transaction для следующих
диктовок; при новом старте профиль снова накладывается на глобальную базу.
Ошибка сохранения оставляет подтверждённый профиль/выбор. Стиль не включает
обработку сам по себе: для этого есть отдельный параметр включения.

## Native lifecycle и приватность

- Идентификатор операции и глобальный snapshot создаются до постановки CLI
  в очередь. Обычный старт использует тот же механизм резервирования.
- Аудио начинает захватываться до проверки поля/процесса, чтобы lookup не
  отрезал начало речи. Проверки выполняются без capture/configuration locks;
  inference и фоновые сегменты запускаются после установки итогового snapshot.
- Исходное поле фиксируется один раз до показа overlay. По его HWND/PID
  запрашивается `QueryFullProcessImageNameW` с ограниченным process access;
  до и после запроса проверяются foreground HWND/PID. Из пути выходит только
  basename, сам путь сразу отбрасывается. При ошибке/смене окна профиль не
  применяется. Если безопасного внешнего поля нет, используются global.
- Для запуска из главного окна Fono, diagnostics и записи голосовых команд
  профиль внешнего приложения не подбирается. Скрытый live не изменялся.
- Смена фокуса после старта не подбирает новый профиль и не заменяет цель.
  Обычный insertion guard продолжает блокировать другую цель и частичный повтор;
  текст остаётся доступен для копирования.
- Stop замораживает snapshot. Поздняя инициализация не заменяет его; cleanup
  не отменяет уже начатое завершение и не останавливает аудио следующей сессии.
  Admission lease удерживается до завершения lookup, настройки и cleanup.
- Session preferences в desktop snapshot передают только имя профиля и
  подтверждённые параметры обработки. Overlay показывает имя и эти параметры,
  сохраняя очередь выбора/rollback. Transient label исключён из сериализации
  Settings; фактический exe/PID/путь не добавляется в историю, диагностику или LLM.
  Настроенные пользователем правила остаются локальной конфигурацией Rust.
- Browser mock не определяет процессы и не сохраняет профили в browser storage.
  Vue-компоненты работают через существующие типизированные порты настроек.

## Хвосты и приёмка

Нужен ручной Windows-прогон: VS Code с выбранным стилем, Windows Terminal
с SendInput, неизвестное приложение с global, переключение поля во время
записи и ручной override в overlay. Проверить реальное сохранение после
перезапуска и поведение разных версий/провайдеров UI Automation.
Unit/browser fixtures подтверждают контракты; успешная внешняя вставка ими
не объявляется. Сценарии — [QA профилей](../../qa/application-profiles.md).

Профили сопоставляются по точному имени exe: дочерние процессы и приложения,
использующие общий host exe, требуют подходящего имени в настройках; автоматического
поиска установленных программ и правил по заголовкам/URL нет. Возможности модели
и Windows/UIPI-ограничения вставки сохраняются. Нет новых обещаний качества STT.
Installer, публикация, установка и приёмка владельца — отдельные этапы;
WakeWord/live не включались. Хвосты FONO-132 не расширялись и не закрывались.
