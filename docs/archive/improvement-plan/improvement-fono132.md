# FONO-132 — личный словарь в STT и LLM

Исходники v0.7.47. Зависимость CODE-04 / FONO-100 проверена: подготовленный
неизменяемый glossary contract подключён к обычной диктовке и обработке текста.
Задача передаётся в `in_review` с явно открытыми хвостами качества и hotwords;
полная приёмка истории FONO-58 не объявлена.

## Реализовано

- Снимок настроек операции передаёт только канонические написания. Варианты
  произношения остаются для существующих точных замен после обработки.
- CPU/CUDA Whisper используют `set_tokens`; Vulkan — принадлежащий запросу
  `prompt_tokens`. Максимум 32 термина / 896 UTF-8 байт и 224 токена реального
  токенизатора. Термины сохраняются целиком, контекст предыдущего окна занимает
  оставшийся бюджет. Утечки `set_initial_prompt` не возвращены.
- Обычная диктовка, фоновые сегменты и хвост после Stop используют один снимок
  словаря. Профиль готового префикса учитывает его хэш. Diagnostics и голосовые
  команды словарь не получают. Scheduler, operation IDs, cancellation и leases
  фактической работы сохранены.
- GPU protocol повышен до 4: отдельное поле `glossary` в batch/window requests,
  проверка границ до загрузки модели, пустое поле не отправляется. Старые
  protocol-3 workers отклоняются. CUDA/Vulkan пересобраны локально, базовая копия
  Vulkan обновлена. Публикация подписанного CUDA asset не выполнялась.
- Канонические написания добавляются к общему составителю LLM-инструкций как
  JSON-данные с запретом добавлять отсутствующие термины. Обычная обработка,
  повтор и тест промпта используют этот путь. Raw без перевода сохраняет обход LLM.
- Отдельное согласие `personal_dictionary_llm_enabled` по умолчанию выключено:
  прежнее включение локального словаря не разрешает отправку всего списка
  провайдеру. UI поясняет, что список может содержать термины вне расшифровки.
  Главный выключатель отключает подсказки, передачу списка и замены для новых
  диктовок, сохраняя записи и отдельный выбор LLM. Настройки активной операции
  заморожены; изменение действует на следующую сессию.
- UI уточняет поле произношения. Browser storage сохраняет только разрешённые
  булевы настройки, без терминов и текстов; диагностика словарь не раскрывает.

## Одно сравнение качества

[Полный JSON с источниками, хэшами и результатами каждой записи](evidence/fono132-glossary-quality.json).
Шесть публичных WAV FLEURS RU/EN выбраны до запуска сравнения: `en-03`, `en-07`,
`ru-02`, `ru-03`, `ru-05`, `ru-07`. Все хэши WAV сверены с закреплённым корпусом.
Атрибуция: FLEURS, Google and HuggingFace Datasets Authors (2022), CC BY 4.0;
[лицензия и преобразования корпуса](../../../src-tauri/tests/fixtures/stt-quality/README.md).
Whisper tiny CPU, fast, 2 потока; одинаковые PCM, модель и настройки, один
baseline и один glossary run, без LLM и финальных замен. Подбора новых фраз
или параметров после результата не было.

| Метрика                     | Выключено       | 10 терминов     |
| --------------------------- | --------------- | --------------- |
| Точные канонические термины | 2/10            | 6/10            |
| WER, 111 слов               | 26/111 = 23,42% | 27/111 = 24,32% |
| CER, 772 символа            | 45/772 = 5,83%  | 45/772 = 5,83%  |
| Токены prompt               | 0               | 45 из 224       |

`Marianas`, `Мадагаскар`, `Буша`, `йод` появились до замен; `Sintra`,
`Аристотеля`, `Новоорлеанской`, `цезий` остались неточными. Две записи ухудшили
WER, три улучшили, одна сохранила WER. Улучшение терминов подтверждено только
этим малым набором; общего улучшения точности нет. Словарь остаётся выключенным
по умолчанию. Регрессия +1 слово / +0,90 п.п. WER записана как открытый хвост,
без ослабления исходных критериев и без следующего цикла подбора.

## Проверки

- Native: **590 passed, 0 failed, 7 ignored**, `--test-threads=1`, изолированный
  каталог данных и закреплённые Sherpa/ONNX DLL. Новые проверки: отсутствие
  неявного LLM-согласия, capability gating, инструкции и смена профиля префикса.
- Protocol/worker CPU unit tests: **34 passed**, включая границы prompt,
  отсутствие токенизации выключенного словаря и ошибки без эха терминов.
- Настоящие CUDA/Vulkan workers: по **17/17 process-contract cases**, protocol 4;
  базовая копия Vulkan тоже прошла. Это framing/control/validation, без модели
  и GPU inference. Verifier использует общий Node contract вместо второго
  PowerShell `ReadLineAsync` handshake; проверки capabilities/лимитов сохранены.
- V3: **314/314**; release/CI scripts: **48/48** в рабочем дереве, включая
  20 пользовательских cache tests, которые в этот коммит не включаются.
- CUDA package fixtures на Python 3.12: **12 passed, 1 skipped** (создание
  symlink недоступно без отдельного Windows-права). Junction fixture прошёл;
  source и expected version тестового package согласованы с protocol 4.
- Typecheck, lint, build, strict Clippy, CPU-only/minimal checks, Rust fmt,
  format/version/docs прошли. Browser mock проверен на 720×560, 900×720,
  1440×900: отдельный LLM-переключатель, пример/редактор произношения, сохранение
  записей после выключения и отсутствие терминов после reload. На 720×560
  редактор прокручивается, обе кнопки доступны. Это проверка mock UI;
  микрофон, GPU, clipboard и пользовательское приложение не использовались.

Локальные полные логи находятся в `build/checks/fono132-*`; они не являются
пользовательским UAT или опубликованной сборкой.

## Оставшиеся хвосты

1. Качество: отдельно проверить большой корпус, длинные сессии, личный голос и
   CPU/GPU; устранить рост общей WER без потери полезных терминов. Текущий
   ограниченный результат не объявляет готовность качества для всех моделей.
2. GigaAM/Parakeet: текущие закреплённые пакеты настроены на greedy decoding,
   `hotwords: false`. Нужны совместимый decoder, проверенная токенизация/словарь
   BPE и собственная проверка качества перед включением capability. У Sherpa
   [hotwords требуют подходящего transducer и modified beam search](https://k2-fsa.github.io/sherpa/onnx/hotwords/);
   [закреплённый NeMo runtime](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.4/sherpa-onnx/csrc/offline-recognizer-transducer-nemo-impl.h)
   имеет такой путь, но Fono его пока не квалифицировал. Подсказки не отправляются
   backend без capability, финальные замены и opt-in LLM остаются доступны.
3. Остаток выбора частых/недавних терминов, отмеченный в v0.7.47, реализован
   в v0.7.65: [приоритет в текущем процессе](improvement-fono132-priority.md).
   Учёт только в памяти, без чтения архива; после перезапуска действует исходный
   порядок. Критерии качества из пунктов 1–2 этим не закрываются.
4. Ручная Windows/голосовая приёмка — по [сценариям QA](../../qa/voice-reliability.md).
   Installer, подпись/публикация CUDA package и release требуют своих этапов.
   WakeWord и экспериментальный live не включались.
