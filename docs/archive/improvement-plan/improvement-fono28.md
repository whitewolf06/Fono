# FONO-28 — контекст вставки и статистика приложений

Дата: 22 октября 2026 года. Исходники v0.7.63, база `74d40a6` / v0.7.62.
Порядок: FONO-40 (согласие и хранение), FONO-39 (снимок попытки),
FONO-41 (история и локальная сводка). Формальных depends-on между историями нет.
Реализация готова к ревью; общий native gate пока не полностью зелёный:
в финальном последовательном прогоне 663 passed, 1 failed, 7 ignored.
Не прошёл существующий STT fixture `one_hundred_failed_worker_sessions_are_recoverable`
на ожидании завершения cleanup. Новые восемь native-сценариев прошли.
Desktop dev v0.7.63 собран и запущен с прежним изолированным профилем;
запуск процесса подтверждён, визуальная приёмка остаётся за владельцем.

## Реализация

Отдельная настройка «Сохранять приложение для вставки» выключена по умолчанию
и не зависит от согласия на речевую аналитику. Для сбора нужна включённая история.
Разрешение привязано к началу конкретной диктовки и ревизии приватности.
Выключение останавливает новые снимки и скрывает метки; уже сохранённые метаданные
можно удалить отдельно. Поздняя операция после отключения/повторного включения
или очистки не восстанавливает старый контекст.

Снимок использует существующую проверку executable для исходного TextTarget.
До и после попытки берётся только basename exe с проверкой foreground window/process.
Путь остаётся временным внутри системного вызова; заголовок окна, URL, документ,
чат, выделение, координаты и содержимое поля не добавляются в снимок.
Дополнительного UI Automation обхода, опроса или чтения буфера для контекста нет.
Работа выполняется на существующем blocking worker с admission lease.

Идентификатор стабилен по имени exe без учёта регистра, например `exe:code.exe`.
Отображаемая подпись — basename без `.exe`. Это не глобальный package ID: две
программы с одинаковым именем exe объединяются, браузер учитывается целиком,
а Windows host-процесс может иметь имя host-приложения. Недоступные данные
остаются неизвестными, новое foreground-приложение не присваивается задним числом.

Контракт хранит before/after, способ, факт попытки и наблюдаемый исход:
`not_attempted`, `unknown`, `sent`, `partial`, `focus_changed`, `failed`.
`sent` означает отправленные события, а не подтверждённый приём сторонним полем.
При блокировке/частичной отправке повтор автоматически не запускается.
Неподтверждённая доставка старого архива остаётся неподтверждённой.

Контекст — необязательное поле metadata истории. Старые JSON/SQLite записи
читаются без выдуманного приложения, схема SQLite остаётся 2. Срок хранения,
удаление и очистка родительской записи удаляют контекст вместе с ней. Есть
отдельное удаление метаданных одной записи и всех записей; тексты, технические
факты и сохранённые варианты LLM остаются. Используется существующая политика
удаления истории, отдельная корзина не добавлена.

Контекст не передаётся в LLM, REST API или диагностический отчёт. Renderer
получает его через историю и не задаёт снимок через IPC. Очистка — отдельная
async-команда с blocking lease и обновлением истории после сохранения.

В V3 доступны метка приложения, исход попытки, фильтр по приложению/неизвестным/
несобранным данным и раскрываемая сводка попыток/долей за период. Сводка явно
независима от текстового поиска и фильтра приложения; заблокированные и частичные
попытки учитываются, случаи без внешней вставки — нет. Пустая сводка не рисуется.
Есть RU/EN, семантические токены и отдельная демонстрация в браузере.
Browser mock не определяет настоящие приложения и не сохраняет контекст/тексты
в storage; вымышленные снимки живут в памяти.

## Проверки и ограничения

Проверки и хэши исходников: [validation receipt](evidence/fono28-validation.json).
Новые native-тесты проверяют opt-in/legacy, basename, старые операции,
повторное включение, SQLite reopen, адресную/общую очистку и сохранность текста.
UI-тесты проверяют whitelist, отображение при выключении, агрегаты и фильтры,
отдельную очистку и отсутствие текстов/контекста в browser storage.
V3 384/384 и release/CI contracts 48/48 прошли. Строгий Clippy, typecheck,
lint и frontend build прошли. Browser mock проверен на RU/EN при 720×560,
900×720, 1440×900; root и сводка не выходят за доступную ширину.
Фильтр Code оставляет одну запись, сводка периода сохраняет три демо-попытки.

Первый запуск native/release из sandbox блокировал loopback HTTP, временные
Git-репозитории и Windows ACL fixtures. Эти прогоны не считаются успешными;
проверки повторены с доступом к собственным локальным fixtures. Строгий Clippy
нашёл два вызова `Option::is_none_or`, несовместимых с MSRV 1.75; они заменены
на совместимый `map_or`, без изменения условий.

Первый полный native-прогон до исправления MSRV дал 664 passed / 0 failed.
После финальных правок параллельный прогон дал 661/664 (graceful shutdown,
mailbox health, package hello/cleanup); последовательный — 663/664.
Assertions и таймауты не ослаблялись, код STT worker не менялся. Причина
нестабильности старых fixtures отдельно не исследовалась и остаётся хвостом.
Дополнительные циклы повторов ради зелёного результата не запускались.

[Ручная Windows-приёмка](../../qa/application-context.md) остаётся за владельцем:
настоящие приложения/host-процессы, оба способа вставки, смена фокуса,
неполный ввод и отсутствие ощутимой задержки. Unit/HTTP fixtures и browser mock
эту приёмку не заменяют. Агент не записывал микрофон, не отправлял ввод сторонним
приложениям и не включал сбор в профиле пользователя.
Публикация и installer не выполнялись; PERF-04 и WakeWord не расширялись.
