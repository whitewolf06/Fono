# FONO-130 — безопасная замена выделения

Версия 0.7.45. Этап F-05.3 использует
[FONO-129](improvement-fono129.md) и общий target guard STAB-04 / FONO-85.
Обе зависимости остаются в `in_review`; родитель FONO-60 — в работе.
Overlay, режим автоматической вставки и итоговая Windows-приёмка выделены
в следующую задачу FONO-131.

## Что сделано

После успешного преобразования можно подтвердить конкретный результат.
Подтверждение само не вставляет текст: пользователь возвращается в исходное
поле с прежним выделением и нажимает отдельное сочетание выделения.
Fono не активирует чужое окно и не выбирает поле автоматически.

Перед отправкой проверяются исходное окно/процесс/поле и диапазон выделения.
После одной попытки замены повтор в этой сессии блокируется независимо от
результата. Для следующей попытки нужно заново получить выделение. При смене
цели, частичной отправке, Cancel или неизвестном результате текст остаётся
для копирования; автоматической повторной отправки нет.

Кнопка «Копировать результат» работает отдельно и не вставляет в чужое поле.
Ошибка копирования сохраняет текст. Просмотренный ответ привязан к собственному
result ID; renderer отправляет только IDs, не подменяет итог, исходный текст
или native target proof.

## Проверки цели и версии результата

- Подтвердить можно только последний успешно завершённый результат, пока
  редактирование не занято. Новая инструкция/преобразование снимает подготовку.
  После ошибки или отмены старый ответ сохраняется для просмотра/копирования,
  но не считается новым подтверждённым результатом.
- Shortcut переносит в delivery точный selection ID и ожидаемый result ID.
  Старый ответ, Cancel или shortcut не меняет другую сессию; результат LLM
  сам никогда не запускает вставку.
- В UIA COM owner хранится исходный range. Перед первым вводом снова проверяются
  target metadata, один текущий range, его совпадение с сохранённым range и
  точный исходный текст. Читается только выделение в рамках подтверждённого
  действия. Обычные фоновые target guards содержимое полей не читают.
- Для исходного fallback Edit/RichEdit в режиме SendInput проверяются прежние
  EM_GETSEL границы и повторно полученный текст через полный clipboard
  backup/restore FONO-128. Неизвестное или изменившееся выделение отклоняется.
- Сочетание **исходный fallback Ctrl+C + режим вставки Clipboard** отклоняется
  до отправки. Его проверка потребовала бы вложенного Ctrl+C на том же clipboard
  owner, который уже готовит paste. Проверка не пропускается ради совместимости:
  интерфейс оставляет результат для копирования.

## Общий путь вставки и отмена

Повторно используется `target::append` через расширение с необязательным
preflight. Для обычной диктовки preflight отсутствует: дополнительных проверок
содержимого и ожиданий в её пути нет. SendInput проверяет цель перед каждой
порцией; подтверждённое выделение проверяется перед первой. Clipboard проверяет
выделение непосредственно перед Ctrl+V на отдельном COM owner и использует
существующий rich-format backup, delayed restore и защиту новой посторонней копии.
COM ranges не передаются между потоками.

Delivery заранее занимает единственную попытку, фиксирует operation ID до
фоновой очереди и удерживает configuration reservation/admission lease до
фактического завершения работы. Native I/O выполняется в `spawn_blocking`.
Clipboard cleanup удерживает собственный lease до восстановления. Закрытие
формы отменяет работу; уже принятые Windows события отозвать нельзя.

Полная отправка обозначается как «текст отправлен», а не подтверждённый ответ
чужого приложения. Win32 не подтверждает фактическое принятие текста произвольным
редактором. Между проверкой UIA и вводом нет общей атомарной транзакции с другим
приложением; реальные переключения/правки и временные границы проверяет владелец.
При частичной или неизвестной отправке нужно осмотреть поле перед ручной вставкой.

## Проверки

- **81/81** целевых UI/native-adapter тестов; полный V3: **308/308**.
- Новые Rust-проверки: единственное явное подтверждение, точные версии результата,
  busy/cancel до очистки, старое завершение, смена цели, частичная/неизвестная
  отправка и сохранение Copy при запрете повтора. Тесты используют подставленные
  результаты, не отправляют системный ввод и не читают clipboard пользователя.
- Strict Clippy all-targets, TypeScript, ESLint и production frontend build прошли.
- CPU-only и сборка без default features прошли; version/format/Rustfmt/docs
  checks прошли. После Cargo выполнено штатное обслуживание кэшей.
- Release/CI contracts: **48/48**. В них входят 20 локальных cache-тестов
  из отдельных незакоммиченных изменений пользователя, не включённых в FONO-130.
- Browser mock: **720×560, 900×720, 1440×900**. Проверены подтверждение без
  автоматической вставки, отмена подготовки, демозамена, блокировка повтора,
  доступ к Copy и закрытие. Горизонтального переполнения нет; тело формы
  прокручивается. Другие приложения и системный clipboard не использовались.

При первом параллельном native-прогоне: **582 passed, 1 failed, 7 ignored**.
Сбой — существующий `mailbox_shutdown_reaps_an_owner_whose_worker_acknowledges_but_never_exits`.
Отдельный неизменённый тест затем прошёл. Его код и таймауты не менялись;
первый лог сохранён отдельно.

Один повтор полного набора без параллельных тяжёлых проверок тоже дал
**582 passed, 1 failed, 7 ignored**, теперь в прежнем тесте
`acknowledged_shutdown_without_exit_is_force_killed_within_the_cleanup_bound`.
Первый падавший тест в этом прогоне прошёл. Новые delivery/result-ID проверки
прошли в обоих прогонах. Причина нестабильности worker cleanup не установлена;
полный native-набор **не считается зелёным**. Дальнейшие перезапуски и отдельная
доработка worker cleanup не входят в этот проход FONO-130. Release-приёмку
эти результаты не подтверждают; критерии и таймауты не ослаблялись.

Логи: игнорируемый `build/checks/fono130-*`.

## Хвосты приёмки

[Ручная матрица](../../qa/voice-reliability.md): browser/Word/VS Code/Telegram,
смена поля/окна/диапазона или исходного текста после LLM, оба поддержанных режима
вставки, protected/UIPI, частичный SendInput, Cancel и конкурентный clipboard.
Все эти сценарии остаются для владельца. Clipboard fallback + Clipboard insertion
пока даёт явный отказ; нужна отдельная безопасная реализация, если этот вариант
понадобится. Поддержка остальных UIA providers также не считается подтверждённой.

FONO-131 остаётся отдельным следующим этапом: overlay без активации,
явный выбор автоматической вставки, политика истории и итоговая ручная приёмка.
В этой задаче история не записывается; WakeWord/live остаются выключенными.
Микрофон, установленное приложение и чужие поля автоматически не использовались.
Installer, установка, публикация, remote CI и production acceptance не выполнялись.
