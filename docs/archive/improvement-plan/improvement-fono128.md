# FONO-128 — явное получение выделения

Версия 0.7.43. Это первый этап истории F-05 / FONO-60: получить выбранный
фрагмент по отдельному действию пользователя. Зависимости PERF-05 / FONO-80
и STAB-04 / FONO-85 использованы повторно и остаются в `in_review`:
их ручная Windows-приёмка ещё не завершена.

## Что сделано

В «Настройки → Кнопки и активация» добавлено отдельное сочетание для выделения.
Функция выключена по умолчанию; начальное сочетание — Ctrl + Alt + Space.
Получение начинается после отпускания сочетания, повторное действие отменяет
текущее. Конфликты с диктовкой и голосовыми командами проверяются до регистрации,
включая порядок модификаторов и пересечение с правым Alt/Ctrl или CapsLock.
Сохранение использует существующий откат регистрации при ошибке.

Выделенный фрагмент появляется в отдельной форме только для чтения. Он остаётся
в памяти до закрытия, без записи в историю, словарь, настройки или диагностику.
В этой задаче нет записи голоса, LLM, изменения исходного поля или вставки.
Голосовая инструкция и подтверждение замены относятся к FONO-129 и FONO-130.

## Native-контракт

- Один COM owner получает только `TextPattern.GetSelection()`. Нужен один
  непустой диапазон в доступном, включённом, незащищённом редактируемом поле
  активного приложения. Пустая каретка, несколько диапазонов, неизвестный
  провайдер или ошибка не превращаются в чтение всего поля.
- `GetText` вызывается только у выбранного диапазона. Ограничения: 32 768 UTF-16
  единиц и 65 536 UTF-8 байт; NUL и неподдерживаемая кодировка отклоняются.
  После чтения повторно сверяются цель и диапазон.
- HWND, process, runtime ID, границы/COM range и SHA256 точного фрагмента
  остаются в Rust. COM range хранится и уничтожается на своём owner thread.
  IPC возвращает только operation ID, фазу, текст, источник и разрешённую ошибку.
  Фоновые проверки цели по-прежнему читают только метаданные.
- Operation ID создаётся до фоновой очереди. Cancel, закрытие окна и shutdown
  очищают текущую операцию; старые результаты и Cancel не меняют следующую.
  Update admission lease удерживается до фактического окончания чтения,
  восстановления clipboard и уничтожения native range.
- При активной диктовке, API-операции или подготовке захвата новое чтение
  отклоняется. Обработчик сочетания использует неблокирующую попытку admission.
  COM и clipboard работают вне UI-потока; окно показывается и получает фокус
  через UI dispatcher только после завершения чтения и очистки.
- В IPC нет команды запуска чтения внешнего поля. Доступные команды читают
  снимок уже начатой явным сочетанием операции и отменяют её точный ID.

Проверка пустого диапазона следует контракту Microsoft
[GetSelection](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.textpattern.getselection?view=windowsdesktop-10.0):
при отсутствии выделения провайдер может вернуть вырожденный диапазон.

## Резервный Ctrl+C и сохранение буфера

Fallback отдельно выключен по умолчанию и применяется только при отсутствии
TextPattern, если пользователь разрешил его. Безопасное подтверждение границ
сейчас ограничено классами Edit/RichEdit через
[EM_GETSEL](https://learn.microsoft.com/en-us/windows/win32/controls/em-getsel).
Для остальных неподдерживаемых полей возвращается отказ: обычный Ctrl+C
при пустой каретке в некоторых редакторах может копировать целую строку.

Используется owner из PERF-05: полный backup поддерживаемых global-memory
форматов, включая HTML/RTF/custom, максимум 64 формата, 16 МиБ на формат,
32 МиБ суммарно. Неподдерживаемый handle, bitmap/owner-display и превышение
лимита отклоняются до изменения буфера.

Временный пустой маркер исключает принятие старого текста за выделение.
Ctrl+C отправляется один раз после отпускания модификаторов. Нужны новое
состояние clipboard и владелец из целевого процесса/окна; цель и границы
повторно проверяются перед чтением. Ответ приложения ожидается до 500 мс,
в том числе при отмене или частичном SendInput. Повторной отправки клавиш нет.

До ответа вызывающему выполняется восстановление, в том числе после ошибки
или Cancel: до 20 попыток с паузой 25 мс. Новая посторонняя копия сохраняется,
даже если её текст совпадает. Ошибка восстановления не выдаётся за успех.
Исходное приложение может добавить копию в историю Windows; это указано
в настройке fallback.

## Проверки

- 73 целевых UI/native-adapter теста прошли. Дополнительно исправлена старая
  SSR-заглушка формы активации; её 12 тестов прошли.
- Полный V3-набор после обновления заглушки: **300/300**.
- Полный Rust-набор: **574 passed, 7 ignored**. Проверены старый Cancel,
  позднее завершение, приватность снимка, границы/Unicode/digest, rich-format
  cleanup при отмене/ошибке, clipboard sequence/owner и неблокирующий admission.
  Тесты clipboard используют подставленные данные и не читают буфер пользователя.
- Строгий Clippy all-targets, CPU-only и конфигурация без default features прошли.
  Native-тесты используют закреплённые Sherpa/ONNX DLL и изолированный test data.
- TypeScript, ESLint и production frontend build прошли.
- Browser mock проверен на **720×560, 900×720, 1440×900**: настройки, отдельные
  выключатели, readonly preview, источник demo и закрытие. Горизонтального
  переполнения на проверенных размерах нет; форма настроек прокручивается.
  Browser demo содержит фиксированный пример, не читает другие приложения
  и не обращается к системному clipboard.
- Release/CI contracts: **48/48**. В них входят 20 локальных cache-проверок
  из незакоммиченных изменений пользователя, не включённых в коммит FONO-128.
- Проверки версии, форматирования, Rustfmt и ссылок документации прошли.
  После Cargo выполнено штатное обслуживание кэшей.

Логи запуска: игнорируемый `build/checks/fono128-*`.

## Осталось проверить владельцу

[Ручные сценарии](../../qa/voice-reliability.md) охватывают реальные browser/Word/
VS Code/Telegram, защищённые и неподдерживаемые поля, смену цели/выделения,
Cancel в разные моменты, rich clipboard и конкурентное копирование.
Текущий metadata probe STAB-04 сохранён; совместимость каждого провайдера
редактируемого поля ещё не подтверждена.

Отдельные хвосты приёмки — заблокированный clipboard, UIPI, медленный UIA
provider, частичный SendInput и ответ приложения на Ctrl+C позже 500 мс.
Ограниченные ожидания и тесты с fake-портами не доказывают универсальное
восстановление при любом поведении внешнего приложения. До этой проверки
fallback остаётся явной опцией; ручная матрица не считается выполненной.

Микрофон, установленный Fono, глобальные сочетания и внешние поля автоматически
не использовались. WakeWord/live остаются выключенными. Installer, установка,
публикация и production-приёмка не выполнялись.
