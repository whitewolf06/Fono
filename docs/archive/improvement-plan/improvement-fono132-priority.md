# FONO-132 — приоритет терминов по использованию

22 октября 2026 года, исходники v0.7.65. База `02b50f17` / v0.7.64.
Уточнение владельца: объём работы — весь FONO-47 и общий dev.
В этом дополнении закрыт отдельный остаток реализации F-03: выбор частых
и недавно использованных терминов при ограничении подсказки.

## Поведение

Приоритет зависит от принятых обычных диктовок в текущем процессе Fono.
Сначала идут термины, встретившиеся в большем числе диктовок; при равенстве —
использованные позже. Повторы одного термина в одной записи учитываются
один раз. Для неизвестных или равных значений сохраняется порядок пользователя.
Редактор словаря сам не переставляет записи.

Учитывается исходная расшифровка, по целым словам/фразам: каноническое
написание или настроенный вариант произношения. Текст, добавленный LLM или
сниппетом, не становится свидетельством использования. Работа ограничена
последними 16 КиБ исходной расшифровки; обрезанный первый фрагмент слова
пропускается. Это вспомогательный выбор подсказок, а не архивная статистика.

Приоритет фиксируется вместе с настройками при начале обычной диктовки.
Фоновые сегменты и Stop используют один снимок. Ограничения сохраняются:
32 термина, 896 UTF-8 байт и 224 токена фактического Whisper-токенизатора.
Для LLM остаётся отдельное согласие; счётчики туда не отправляются.

Учёт находится в общем завершении принятого результата под существующим
terminal commit fence. Ожидание, preview, NoSpeech и Cancel до него не доходят;
принятие через overlay учитывается один раз. Сниппеты передают выключенный
словарь. История может быть выключена: существующий текст используется
только в памяти, старые записи не читаются и не пересчитываются.

## Приватность и lifecycle

Счётчики и порядковый номер последнего использования живут только в памяти
процесса. Они исключены из сериализации настроек, IPC, истории, диагностики
и журналов; отдельный файл не создаётся. После перезапуска приоритеты снова
неизвестны, действует порядок пользователя. Постоянная статистика не
добавлена как новое условие исходного плана.

Выключение очищает приоритеты, сохраняя записи словаря. Удалённый термин
исключается из учёта. Изменение словаря инвалидирует разрешение старой
операции: выключение/повторное включение и удаление/повторное добавление
не дают позднему результату восстановить счётчик. Обновления настроек через
полный setter и delta проходят одну сверку; прочие предпочтения не сбрасывают
счётчики. Новых I/O, фоновых потоков или освобождения admission раньше
завершения работы нет.
