# FONO-143 — отдельный стенд оценки WakeWord

Исходники v0.7.59, 21 октября 2026 года. База — v0.7.58 / `79a0bb6`.
Зависимость W-01 / FONO-142 реализована и находится в `in_review`.
WakeWord приложения остаётся выключенным; обучение и интеграция не начинались.

## Что сделано

- Новый optional example `wake_bench` в `fono-wake` воспроизводит WAV через
  текущий RU/EN `SherpaDetector` и `DecoderSession`. Это отдельный процесс,
  без AudioHub, микрофона, Tauri IPC, истории или изменения настроек Fono.
- Реальный sample clock 20 мс, полный PCM без добавленного хвоста, события
  и время доставки, отдельная загрузка модели и process CPU kernel+user.
  Paced replay считает wall-clock задержку; fast не выдаёт её за real-time.
- Python CLI без внешних пакетов проверяет WAV/SHA256, происхождение и
  декларацию лицензии/согласия, временные аннотации и разделение train/dev/test.
  Одинаковые аудио, говорящие, сессии и исходные записи не пересекают выборки.
- Отчёт содержит recall quiet/noisy, FA/h с реальным отрицательным знаменателем,
  p50/p95, idle/speech CPU в процентах одного ядра, события, hardware/model/
  binary/runtime/runner hashes. Неизвестные значения остаются `null`.
  Синтетические позитивы не подтверждают recall, нулевой знаменатель не даёт
  нулевой FA/h. Один event не обнаруживает два произнесения.
- Рабочие точки задают стабильность/подтверждения/cooldown. Test допускает
  одну точку из dev-отчёта с совпадающим lineage. Для ASR сохраняются
  дискретные FA/h–miss точки; вероятностный classifier score не выдумывается.
- Исходные цели сохранены: ≥95% quiet, ≥90% noisy recall; ≤0,5 FA/h;
  p95 ≤800 мс; idle CPU <1% одного ядра. Недостаточные данные и `--smoke`
  не могут дать `qualified=true`. Подготовлены методика и CI для Python contracts.

[Запуск, формат корпуса и методика](../../../tools/wake-bench/README.md).
Программа проверяет декларации и целостность; условия использования записей
проверяет оператор. Личные записи не собирались, микрофон не использовался.

## Один инженерный baseline

Использованы уже существующие локальные RU T-one и EN Zipformer,
два закреплённых публичных FLEURS WAV и два синтетических idle-файла.
Новых загрузок нет. Native example — **debug**, Windows 11 x64,
Intel Family 6 Model 151 Stepping 2, 16 логических CPU. Полные SHA256
в [сыром отчёте](evidence/fono143-baseline-smoke.json).

- Реальные негативы: **27,48 с**, событий **0**; позитивов **0**.
- Recall и p50/p95 **не измерены**. Короткий отрицательный replay
  не подтверждает целевые FA/h на многочасовом корпусе.
- Два synthetic idle replay: **16,02 с**. Взвешенный CPU — **34,84% одного
  ядра**; RU 32,27%, EN 37,13%. На двух speech clips — 47,71% в сумме,
  RU 29,69%, EN 82,28%. Загрузка моделей исключена из этих процентов.
- Итог инструмента: **`insufficient_data`, `qualified=false`**.
  Цель idle CPU в этом коротком инженерном прогоне не выполнена.
  Измеряется отдельный decoder, без стоимости устройства/приложения;
  это не окончательный release benchmark и не расход работающего Fono.

Повторных подборов параметров и оптимизации по этому smoke не выполнялось.

- Default native — **631 passed, 0 failed, 7 ignored**; audio —
  **44 passed, 0 failed, 1 ignored**. Default normal dependency tree
  по-прежнему не содержит `fono-wake` или bench.
- Release/CI scripts — **48/48**, workflow contracts дополнительно **8/8**.
  В рабочем дереве присутствуют 20 отдельных cache tests владельца,
  они в этот коммит не входят. Удалённый GitHub workflow не запускался.

Общий [validation JSON](evidence/fono143-validation.json) хранит результат

Python fixtures потребовали запуска вне ограниченной Windows-песочницы:
внутри неё не было доступа к собственному Temp.

## Хвосты

Нужен согласованный корпус: 100–300 реальных произнесений разными людьми,
quiet/noisy RU/EN и ≥10 часов разрешённых негативов. Записи голоса владельца
сейчас не требуются. Сбор и проверка прав — отдельный следующий шаг.

После корпуса остаются полноценный dev sweep, зафиксированная test-точка,
release baseline, recall/latency и длинный idle/FAh. Для будущего
классификатора будет нужен собственный score sweep. Пока итоговые цели
качества открыты; FONO-144/145 не разблокируются этим smoke.
Приложение, пользовательские данные, установка и публикация не затронуты.
