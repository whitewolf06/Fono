# FONO-126 — управление работающим Fono через CLI

Версия 0.7.41. Реализация использует STAB-07 / FONO-87: существующий
single-instance plugin 2.4.3 и startup gate. Зависимость находится
в `in_review`; её ручная Windows-приёмка не подменяется тестами этой задачи.

## Команды

```text
Fono.exe --start
Fono.exe --stop
Fono.exe --toggle
Fono.exe --cancel
Fono.exe --show
```

За запуск принимается одна команда. Без аргументов Fono открывает главное
окно, как прежде. Неизвестный аргумент, значение вместо команды или несколько
команд дают фиксированную ошибку и exit code 2 до создания runtime,
окна, порта и загрузки настроек. На Windows ошибка выводится в терминал
родительского процесса, если к нему можно подключиться; новое консольное
окно не создаётся. Содержимое неизвестного аргумента не повторяется в ошибке.

| Команда    | Поведение                                                                                            |
| ---------- | ---------------------------------------------------------------------------------------------------- |
| `--start`  | Начинает обычную диктовку; при уже начатой записи ничего не меняет                                   |
| `--stop`   | Завершает текущую запись; в idle и после начала обработки ничего повторно не запускает               |
| `--toggle` | В idle начинает запись, во время записи завершает её; во время обработки возвращает ошибку занятости |
| `--cancel` | Отменяет конкретную активную операцию; в idle ничего не меняет                                       |
| `--show`   | Показывает, восстанавливает и фокусирует главное окно                                                |

Если Fono уже работает, второй процесс передаёт команду через прежний
single-instance transport и завершается до настройки сервисов. Второй
аудиопоток, API-порт и профиль не создаются. Если экземпляра ещё нет,
запускается один основной процесс и выполняет команду после готовности
сервисов и event loop. Для команд записи главное окно стартует скрытым
и не забирает фокус у внешнего поля. Положение и политика фокуса оверлея
не меняются. `--show` остаётся явным способом открыть настройки.

В плагине 2.4.3 код 0 второго процесса означает передачу команды, а не
успешное распознавание или вставку. Ошибки выполнения сообщает основной
интерфейс Fono. Ожидание результата в stdout и отдельный headless-протокол
в эту задачу не входят.

## Lifecycle и защита от гонок

Аргументы проверяются до single-instance bootstrap, повторно — на приёме.
Путь запуска и cwd не используются как команды, не сохраняются и не
логируются; shell не вызывается. Плагин остаётся первым в Builder.
Основной процесс обрабатывает только пять перечисленных действий.

До постановки Start в ограниченную очередь резервируются `operation_id`
и снимок настроек. Это операция только с памятью: микрофон открывает
worker, используя тот же идентификатор. Быстрый Stop привязан к уже
зарезервированной записи, даже если устройство ещё открывается. Отменённый
Start не может открыть микрофон для следующей операции. Ошибка постановки
освобождает резерв; shutdown закрывает приём и отменяет оставшуюся операцию.

FIFO ограничена 32 ожидающими действиями и ждёт `RunEvent::Ready`.
Первичная команда ставится в очередь до освобождения startup gate.
Повторные Stop объединяются до окончания реальной работы, включая flush
настроек оверлея. После ошибки flush запись остаётся доступной для повтора.
Cancel обходит очередь Start/Stop и ожидание распознавания; повторная
отмена той же операции объединяется. Старые команды содержат точный ID,
поэтому не выбирают текущую сессию заново после ожидания.

Обычная диктовка использует существующие capture, speech VAD,
pretranscription, scheduler, Stop/CompletionGate, обработку и защищённую
вставку. Командная запись при внешнем Stop использует прежний
voice-command runner, чтобы текст команды не превращался в диктовку.
Пробная диктовка и проверка микрофона блокируют Start/Stop/Toggle:
их звук не передаётся обычной диктовке, истории или внешней вставке.
Предварительное распознавание и выбор обработки не включаются принудительно.

Update admission lease принадлежит ожидающему заданию и фактической работе,
включая асинхронный Stop/Cancel. Мьютекс admission больше не удерживается
во время открытия устройства: защита установки сохраняется счётчиком lease.
Резервирование CLI не ждёт занятого capture configuration fence, а возвращает
ошибку занятости. Снятие очереди и join worker выполняются без блокировки
главного потока; cleanup lease сохраняется до завершения join.

Основание transport-контракта — закреплённый код плагина и
[документация Tauri Single Instance](https://v2.tauri.app/plugin/single-instance/).

## Проверки и хвосты

Тесты используют подставленный AudioRecorder и события команд. Они проверяют
парсер, закрепление ID, очередь до Ready, порядок действий, предел очереди,
освобождение guard, совместимость Start, коалесцирование Stop/Cancel,
отмену зарезервированного Start и отсутствие захвата следующей сессии.
Глобальные хуки, личный микрофон и пользовательское приложение в проверках
не запускаются.

- Общий прогон приложения: 557 Rust PASS, 7 штатно ignored. После
  последнего запрета Stop для диагностического аудио отдельно прошли
  все 12 CLI-тестов. Это целевой повтор изменённого контракта;
  общий прогон после этой последней правки не повторялся.
- 290 тестов V3 и 48 release/CI-проверок прошли. В последние входят
  20 существовавших owner-проверок кэшей; эти owner-правки в коммит
  FONO-126 не включены. Удалённый Actions не запускался.
- Strict Clippy all-targets, CPU-only и no-default-features compilation,
  Rustfmt, typecheck, lint, frontend build, version/format/docs checks прошли.

Логи: `build/checks/fono126-*.log`. Проверено текущее рабочее дерево;
посторонние изменения обслуживания кэша и PERF-04 сохранены отдельно.

Реальные два запуска EXE, отсутствие второго процесса/порта, вывод ошибки
из GUI EXE в Windows Terminal/PowerShell, начальный скрытый запуск,
фокус внешнего поля, голос, Stop/Cancel во время STT и внешнюю вставку
проверяет владелец. Отдельный browser resize-прогон не выполняется:
визуальных изменений в V3 нет. Установка и публикация не выполняются.
WakeWord/live остаются выключены. Выбор триггеров и конфликты в UI
остаются в следующем этапе FONO-127.
