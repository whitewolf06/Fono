# ADR 0001: отдельные процессы GPU-распознавания

Дата фиксации: 17 октября 2026 года. Статус: принято, реализовано.

## Контекст

Основное Tauri-приложение должно запускаться без установленного CUDA Toolkit. GPU-backend загружает крупные библиотеки и может аварийно завершиться или зависнуть внутри native inference. Такая ошибка не должна уничтожать интерфейс и сохранённый результат диктовки. CPU-распознавание доступно во встроенном движке.

## Решение

CUDA и Vulkan работают в отдельных процессах. Приложение общается с ними через [STT protocol 3](../MULTI_BACKEND_ARCHITECTURE.md): handshake, capabilities, request/operation IDs, bounded frames, отмену, health и shutdown. Supervisor владеет процессом и очередью; поколение сессии ограждает новый worker от старых ответов. При сбое выбранная модель восстанавливается в фоне с ограниченным числом попыток.

Явный выбор ускорения возвращает ошибку своего backend. В Auto допускается переход к следующему кандидату; фактический backend сохраняется отдельно от предпочтения пользователя. Отмена фонового ожидания не освобождает admission lease раньше фактического завершения работы.

## Альтернативы

- Все backend в основном процессе: меньше IPC, но native crash и загрузка GPU runtime затрагивают приложение целиком.
- Отдельный процесс и для CPU: единый lifecycle ценой ещё одного процесса и протокольной границы; сейчас CPU встроен.
- Запуск нового процесса на каждую реплику: простое освобождение памяти, но повторная загрузка модели ухудшает задержку.

## Последствия

GPU runtime поставляется отдельно от embedded CPU. Worker можно завершить и восстановить, сохранив UI. За изоляцию приходится платить сериализацией аудио, проверкой совместимости бинарников и отдельным lifecycle. Успешный handshake подтверждает контракт процесса, но сам по себе не подтверждает качество распознавания или работу драйвера на всех GPU.
