# ADR 0006: Vulkan по умолчанию и отдельная поставка CUDA

Дата: 13 ноября 2026 года. Решение согласовано владельцем.

## Контекст

Fono Desktop и Fono Server используют общий STT runtime и отдельные GPU workers.
Библиотеки CUDA заметно увеличивают загрузку. Пользователю нужна лёгкая основная
поставка с GPU-распознаванием, при этом поддержку CUDA необходимо сохранить.

На Kari, RTX 3060 Ti 8 ГБ, изолированный прототип Vulkan с Large v3 Turbo показал
близкую к CUDA скорость после прогрева. Архив полного API без моделей занимал
158,52 МиБ против 2,27 ГиБ у подготовленного CUDA-образа. На 20 публичных записях
нормализованные расшифровки совпали. Windows-замеры и AMD/Intel-приёмка учитываются
отдельно; результат одного NVIDIA-сервера не подтверждает все устройства.

## Решение

- Auto использует Vulkan на подходящей физической дискретной GPU. Без такой
  видеокарты доступен CPU. Программный Vulkan и встроенная графика не включают
  GPU в Auto.
- Установка CUDA-пакета не меняет Auto. CUDA выбирается явно.
- Базовый установщик Windows содержит Vulkan и CPU. CUDA worker, библиотеки,
  подписанный манифест и проверка пакета сохраняются в отдельной поставке.
- Для API основной Docker-образ содержит Vulkan и CPU. CUDA-образ собирается и
  проверяется отдельно из того же репозитория. API у вариантов общий.
- Ошибка явно выбранного GPU, загрузки модели или её прогрева возвращается
  пользователю. Нехватка памяти не должна незаметно переводить Auto на CPU.
- Vulkan worker проверяет класс и возможности устройства, закрепляет один
  физический индекс и прогревает модель до ответа `model_loaded`.
- Кэш шейдеров хранится в пользовательском каталоге кэша; серверный Compose
  сохраняет его в отдельном volume. Кэш не включается в дистрибутив.

## Последствия

Базовая сборка не требует CUDA Toolkit. Для подготовки дополнительного CUDA
worker остаётся отдельная сборочная зависимость. CI проверяет обе серверные
поставки; публикация по-прежнему требует выбранного тега и подтверждённого SHA.

Открытие модели включает внутренний прогрев. При первом запуске или смене
драйвера подготовка может занять больше времени; запрос не должен получать эту
работу после сигнала готовности. Прогрев не пишет историю, не публикует текст и
не вставляет его во внешнее поле.

Бюджет Vulkan [`VK_EXT_memory_budget`](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceMemoryBudgetPropertiesEXT.html)
относится к текущему процессу. Он не
подменяет глобальную свободную VRAM. Неизвестная глобальная метрика остаётся
неизвестной и не публикуется как ноль или как свободный бюджет процесса.

## Рассмотренные варианты

Единая поставка со всеми библиотеками CUDA сохраняла большой размер загрузки.
Отдельные CUDA-пакет Windows и CUDA-образ API позволяют поддерживать backend и
скачивать его только при выборе пользователя. Выбран второй вариант.

## Статус

Реализация подготовлена в 0.9.1; результаты и открытая аппаратная приёмка —
[проверка основной поставки](../qa/vulkan-default.md). Подготовленный релиз 0.9.0,
публикация, обновление Kari, установка Windows и ручная приёмка — отдельные этапы.
Существующая C++/CMake-реализация Vulkan сохранена по [ADR 0002](0002-vulkan-cpp-worker.md).
