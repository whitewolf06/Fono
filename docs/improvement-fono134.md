# FONO-134 — транскрибация файлов

Исходники v0.7.49, 21 октября 2026 года. Реализован F-07.1 из истории FONO-62.
База — v0.7.48 / `f733cf4`. Зависимость PERF-01 / FONO-76 проверена в Кворуме:
реализация асинхронного IPC находится в `in_review`. Новые команды следуют
тому же контракту. FONO-134 передаётся в `in_review`, история FONO-62 —
в `in_progress`; приёмка настоящего длинного файла остаётся открытой.

## Что сделано

- Отдельный экран **Файлы**: несколько аудиозаписей через Windows-диалог
  или drag&drop, очередь, подготовка, прогресс, отмена отдельного задания и
  всех активных файлов, просмотр результата, явное сохранение TXT/SRT/VTT.
- Используются существующие `audio_ingest`, `TranscriptionJobQueue`,
  `DesktopTranscriptionRuntime`, STT engine и scheduler. REST API можно
  оставить выключенным: создаётся только общий worker очереди. Включение API
  подключает к нему HTTP transport, выключение не создаёт второй runtime.
- WAV, MP3, FLAC и OGG/Vorbis/Opus; прежние ограничения — 100 МиБ и 3 часа
  на файл. В очереди хранятся пути, декодируется только текущий файл.
  Одновременно ждут до четырёх заданий; одно добавление — до 16 файлов.
  Частичный отказ добавления виден пользователю. Исходники не перемещаются.
- UUID задания выделяется до чтения аудио и не повторяется после перезапуска
  API/очереди. Путь не передаётся в результат и историю: сохраняется только
  имя файла. PCM после выполнения освобождается. Готовые результаты хранятся
  в существующей локальной истории задач с лимитом 100 записей.
- Whisper сохраняет реальные абсолютные метки слов из существующего
  протокола worker v4. Перекрывающиеся окна используют тот же `LiveAgreement`,
  экспорт получает только принятые слова без дублей. Короткие cues сохраняют
  паузы, имеют миллисекундную точность, SRT использует запятую, VTT — точку
  и заголовок WEBVTT. Поддерживается переход через час.
- Для offline-моделей используются только реальные token timestamps.
  Старые результаты и модели без таких меток остаются TXT-only: SRT/VTT
  недоступны, равномерная разметка текста не подставляется.
- Файлы работают с низким приоритетом scheduler. Вытеснение диктовкой повторяет
  только текущее ограниченное окно/сегмент; пользовательская отмена останавливает
  всё задание и запрещает публикацию позднего результата.
- Отмена проверяется между пакетами декодера и окнами STT. Pending и actual work
  удерживают admission leases обновлений. Отмена pending освобождает его сразу,
  отмена активного задания/выход — после фактического возврата native work.
  Освобождение leases и callbacks вынесены из блокировки очереди.
- Новые IPC-команды асинхронны; filesystem работает в `spawn_blocking`,
  Windows-диалоги создаются и закрываются на главном потоке с owning window
  `settings`. Доступ ограничен главным окном. Экспорт запускается отдельной
  кнопкой с Windows-подтверждением перезаписи.
- Browser preview содержит явно обозначенные демофайлы; drag&drop берёт
  только имена, аудио не читает. Browser storage для файлов не используется.
  Vue обращается к типизированному `FilesPort`, без IPC и browser API внутри
  компонента.

## Проверки

- Native default: **603 passed, 0 failed, 7 ignored**, последовательный запуск
  с отдельным каталогом данных и закреплёнными Sherpa/ONNX DLL.
- V3: **322/322**; release/CI scripts: **48/48** в рабочем дереве. 20 cache tests
  относятся к отдельным изменениям владельца и не включаются в этот коммит.
- Typecheck, lint, production build, strict Clippy, CPU-only/minimal compilation,
  Rust fmt, format/version/docs checks прошли.
- Browser mock: **720×560, 900×720, 1440×900** — пустой экран, добавление двух
  демофайлов, просмотр результата и доступность TXT/SRT/VTT. Выполнен явный
  демоэкспорт SRT; горизонтального переполнения страницы нет. Это проверка
  браузерного интерфейса, без настоящего STT или Windows picker/save.

Результаты, логи и screenshots — `build/checks/fono134-*`.

Новые проверки покрывают декодирование WAV через общую очередь, отменённый
pending без открытия файла, progress, отмену/выход при некооперативной native
работе, отсутствие позднего результата, overlap/preemption на 30-минутной
синтетической шкале, точный SRT/VTT, старую историю без меток и UTF-16
мультивыбор. Это проверки контрактов; они не являются распознаванием настоящей
30-минутной записи.

## Хвосты

Ручной сценарий — [QA транскрибации файлов](qa/file-transcription.md).
Нужно проверить Windows picker/save, настоящий drag&drop, реальный 30-минутный
файл с проверкой SRT по аудио, вытеснение горячей диктовкой, Cancel/выход и
сохранение результата после перезапуска. Микрофон, чужие поля и пользовательское
приложение агентом не управлялись; публикация/installer не выполнялись.

Необязательные пункты исходного плана — LLM clean/summary и видео через
установленный пользователем ffmpeg — оставлены отдельным продолжением.
Автозапуск ffmpeg, новая модель/STT runtime и облачная отправка не добавлялись.
