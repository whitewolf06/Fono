# Правила изменений Fono

Правила сохраняют контракты Desktop, сервера и общих crates.
Команды и этапы вынесены в [разработку](development.md),
[тестирование](testing.md) и [доставку](delivery.md).

## Версия и границы изменений

Источник версии — `package.json`. Версия синхронизируется с
`package-lock.json`, Tauri config, desktop Cargo.toml и записью `fono`
в корневом Cargo.lock. Каждый новый коммит, включая документацию,
повышает patch через `npm run version:bump -- patch` и содержит `vX.Y.Z`
в теме. Перед коммитом выполняется `npm run version:check`.

Minor и состав публикации согласуются отдельно. Версии внутренних Rust crates
не повторяют номер приложения. Коммит, push, сборка, публикация,
установка и приёмка остаются самостоятельными действиями.

Сохраняйте чужие изменения и идентичность установленного приложения:
`com.fono.desktop`, каталог данных, credential targets и миграционные пути.
Рефакторинг не должен создавать пустой профиль вместо существующего.

## Зависимости и интерфейсы

- Общие зависимости и профили задаются в корне workspace. Windows-only
  зависимости и MSVC-флаги остаются условными.
- Shared crates не импортируют Tauri и приложения. `fono-types` не получает
  Tokio runtime или native inference. Проверка границ входит в CI.
- Хост внедряет STT пути, progress/readiness, безопасные сообщения,
  activity guards и GPU package handles через порты.
- Vue-компоненты не обращаются напрямую к IPC, browser storage, clipboard
  или window API. UI использует Vue V3, WhiteUI 0.6.0 и общие токены.
- Имена IPC, сериализация, стабильные коды ошибок и версии протоколов
  сохраняются при переносе кода. Несовместимое изменение требует явной версии
  контракта и обновления потребителей.

Карта компонентов — в [архитектуре](architecture.md), границы UI —
в [архитектуре фронтенда](frontend-architecture.md).

## Потоки, отмена и владение

Tauri-команда с дисковым, сетевым, аудио-, clipboard/input- или process-I/O
должна быть `async`; блокирующая работа выполняется через `spawn_blocking`.
Чистые операции с памятью могут оставаться синхронными. Окна и меню создаются
на owning UI thread, поток устройства — у своего владельца.

Фиксируйте operation ID до постановки задачи в очередь. Настройки и целевое
поле принадлежат этой операции. Старые Stop, Cancel, Release и результаты
не действуют на следующую запись. Повторный Stop ожидает один результат,
архивирование принятой сессии выполняется один раз.

Admission lease живёт до фактического завершения inference, загрузки и cleanup,
даже если вызывающий IPC/HTTP уже отменён. Установка обновления резервирует
общий `application::updates::activity` fence; новые фоновые операции участвуют
в нём. Соблюдайте порядок блокировок: admission до pipeline, очереди
и download registry. Routing lock не удерживается во время native
распознавания и уничтожения worker.

Смена поля или частичная вставка запрещает автоматический replay.
Текст остаётся для копирования. Overlay сохраняет `focus: false` и
`focusable: false`. Не проверяйте результат чтением содержимого чужого поля.

## Модели и экспериментальные функции

GPU workers и протокол обновляются вместе и проходят общий исполняемый
process contract. Бинарники старого протокола не считаются проверенными
ресурсами. SHA-проверка и handshake не заменяют реального распознавания
и активной отмены.

Vulkan — основной GPU-вариант, CUDA — явная дополнительная поставка.
Установка CUDA не меняет Auto. Ошибка загрузки или нехватка VRAM не должна
скрываться под успешным CPU fallback. Пул не выгружает занятую модель
и удерживает её ёмкость во время cleanup.

Сохраняйте C++/CMake Vulkan и Rust CUDA workers, пока замена не воспроизводится
и не проверена на согласованных исходниках, моделях, протоколе и качестве.
Одинаковый wire contract не делает результаты движков эквивалентными.

Не открывайте legacy WakeWord или «На лету» через обход выключенных gates.
Лира beta — отдельный фиксированный runtime. Её пороги и критерии качества
не ослабляются ради скорости или выпуска. Подробнее — [STT](stt.md).

## Данные, сеть и проверяемые утверждения

Настройки сохраняются атомарно; миграции и privacy-изменения не теряют данные
при ошибке. Ключи не возвращаются renderer. Секреты, аудио, тексты, инструкции
и пользовательские пути не входят в диагностические DTO и метрики.
Remote STT не разрешает неявно включать сохранённую локальную модель.

Сервер слушает loopback по умолчанию. Доступ между машинами требует выбранного
защищённого канала, аутентификации, scope и ограничений тела/времени.
Контракты — в [сервере](server.md) и [API](api.md).

Updater и онлайн-загрузчик проверяют HTTPS, подпись и подписанную версию,
запрещают downgrade. Приватный signing key не попадает в Git, логи и артефакты.
Автопроверка опциональна, не чаще раза в сутки с сохранением времени попытки;
она не скачивает и не устанавливает пакет. Установка требует явного действия
после завершения операций. Подпись updater не заменяет Windows Authenticode.

Различайте source review, unit/contract tests, browser mock, native replay,
пользовательскую проверку и чистую установку. Fixture показывает только своё
аудио, модель, параметры и границы проверки. Исторические quality-данные
сохраняют происхождение, лицензии и предупреждения. Их нельзя выдавать
за свежую независимую квалификацию личного голоса, всех GPU, recall
или ложных активаций.

Микрофон, личный голос, hotkey, поля, overlay и установку проверяет пользователь.
Агент использует код и разрешённые публичные WAV, не управляя пользовательским
приложением ради UI-приёмки. Входная расшифровка для LLM — материал редактирования,
а не инструкция ответить на содержащийся в ней вопрос.

Результаты прогонов и планы не входят в постоянные руководства.
Для fixtures и поставляемых моделей сохраняйте upstream notices и условия
распространения. Правила названия и прав — в [BRAND](../licenses/BRAND.md).
