# «Привет, Лира»: ручная проверка в dev — v0.7.72

Следующий шаг по разрешению владельца — [живое пробуждение v0.7.73](improvement-wake-lira-live.md).

22 октября 2026 года. В форме «Настройки → Кнопки и активация → Записи для
WakeWord» добавлена кнопка **«Проверить детектор»** у сохранённых образцов
Лиры. Она проверяет выбранный WAV через замороженный CNN v0.7.70 и точный
русский CTC-verifier v0.7.71. Подходит и для новых записей, сделанных
владельцем обычной кнопкой формы.

Результат — «Фраза обнаружена» или «Фраза не обнаружена», отдельно время
обработки записи. Ошибка не считается отрицательным ответом. Результаты
проверок существуют только в памяти текущего приложения: WAV и исходные
метки не меняются, истории диктовок и внешней вставки нет.

## Короткий проход владельца

1. Открыть форму и выбрать «Привет, Лира». На одном прежнем положительном
   образце нажать «Проверить детектор»; дождаться результата.
2. Проверить один прежний образец другой речи, затем при желании записать
   новое обычное произнесение «Привет, Лира» и проверить его.
3. В «Речь без фразы пробуждения» можно записать «Привет, Лера», «Привет,
   Мира», iPhone и обычную речь, без полной целевой фразы. Ожидается
   «Фраза не обнаружена».
4. Уйти со страницы во время проверки и вернуться: поздний результат
   отменённой проверки не должен появиться. После её фактического
   завершения кнопка снова доступна.

Нужно сообщить, на какой записи есть пропуск или ложное событие, и видна
ли ошибка. Новый большой набор или повтор обучения сейчас не требуется.
Проверка не запускает диктовку по голосу. Постоянное пробуждение остаётся
выключенным; это ручной доступ к стенду из настоящего desktop.

## Границы dev-моста

- Доступен только debug-сборке с явно заданным абсолютным
  `FONO_WAKE_DEV_PYTHON`. В release переменная не включает функцию;
  browser mock не запускает модель или микрофон.
- Используются существующие локальные Python 3.12 / NumPy 1.26.4 /
  SciPy 1.17.1 / PyTorch 2.7.1+cu128 (CPU) / ORT 1.23.2 и assets.
  Это подготовленная рабочая среда разработчика, а не новый способ
  поставки зависимостей пользователям.
- Проверяются точные SHA256 CNN, config, исходников и T-one assets.
  Порог CNN 0,8, окно, шаг, cooldown и lookahead сохраняются.
  Нового train/TTS или подбора порога нет.
- В Python передаются проверенные consented-local-only/dev WAV Лиры через
  stdin. Нет путей к голосу в аргументах, временных копий, расшифровок
  в IPC, сетевых запросов и записи микрофона агентом.
- Резервирование получает operation ID до очереди; один фоновый процесс
  с пониженным приоритетом, ограниченный PCM и 60-секундный watchdog.
  Зависший процесс завершается и дожидается вместе с writer; update lease
  и занятость удерживаются до фактического завершения, включая исчезновение
  IPC waiter. Поздний ответ после закрытия страницы не публикуется.
- Запись по-прежнему использует AudioHub, явное согласие/кнопку, ограничение
  времени и прежний session-fenced Stop/Cancel.

Один публичный WAV используется только как smoke-тест реального протокола
stdin → модель → JSON. Это не новый прогон личного корпуса и не оценка
общего качества. Время обработки файла, включая загрузку модели, не
является p95 пробуждения.

## Проверки подготовки

Прошли 400/400 Vue/IPC (в том числе 16 проверок формы), 14/14 целевых
Rust-тестов записей и dev-моста, 29/29 Python contracts и 48/48 локальных
release/CI-тестов. Остальные 678 app unit tests этим целевым native-запуском
не выполнялись. Strict Clippy для app/all-targets, typecheck, ESLint,
frontend build и формат прошли. Browser mock проверен на 720×560, 900×720,
1440×900: без ошибок JS/горизонтальной прокрутки и с выключенным микрофоном.

Первый полный UI-запуск остановлен после транспортного таймаута Vite;
окончательный ограниченный прогон прошёл 400/400 за 107,88 с. После снятия
блокировки DLL старой dev-копией и исправления экспорта общего capture guard
native-проверки прошли. Release fixture tests потребовали разрешённого
доступа к собственным временным Git-каталогам. Критерии не менялись.

Публичный PCM16 WAV / 16,92 с прошёл реальный протокол обработчика:
0 предложений / 0 итоговых событий, 5,719 с обработки с загрузкой модели.
Это технический smoke, а не новая оценка recall или задержки пробуждения.
Удалённый CI и installer не запускались; голос и окно проверяет владелец.
[Агрегаты подготовки](evidence/wake-lira-dev.json).

## Оставшаяся работа

Сохраняются два исходных пропуска CNN, независимые реальные near misses
и голоса, длительные негативы, p95/idle CPU, полный lock/поставляемый artifact
и native-интеграция с AudioHub/admission/worker. Цели W-02 неизменны.
FONO-144 остаётся в работе; этот ручной мост не закрывает FONO-145/146.
