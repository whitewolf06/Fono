# OSS-05: проект отдельного CUDA-пакета

Статус: предложение для решения владельца, 17 октября 2026 года. Канал и ключ
ещё не согласованы; этот документ не активирует загрузчик и не объявляет пакет
опубликованным. Карточка — [FONO-75](https://kvorum.gorbach-dev.ru/tasks/FONO-75/oss-05).

## Задача и исходный размер

Базовая поставка должна содержать embedded CPU и Vulkan, а CUDA worker и его
runtime — загружаться отдельно. В проверенном локальном наборе CUDA-компоненты
занимают 548 556 624 байта, около 523,1 MiB без сжатия. Vulkan worker — около
50,1 MB. Это размеры файлов, а не замер нового installer. Ориентир <100 MB
из плана требуется проверить сборкой конкретного базового NSIS.

Одного `-SkipCuda` недостаточно: текущий скрипт сохраняет прежние CUDA-файлы,
а resource glob и закрытый manifest учитывают общий каталог. Нужны раздельные
base/CUDA staging и точный список файлов; старые CUDA DLL не должны попасть
в базовую поставку через оставшийся glob.

## Предлагаемый канал доверия

Использовать существующие GitHub Releases `whitewolf06/fono` и публичный ключ,
уже встроенный в Fono. На теге версии приложения размещать отдельные immutable
manifest, detached signature и архив CUDA для Windows x64. Runtime не принимает
произвольный URL или новый ключ из аргументов и настроек.

Подписываются точные байты небольшого manifest. Внутри находятся:

- purpose `fono-cuda`, версия схемы и платформа `windows-x86_64`;
- точная версия Fono и точная версия STT-протокола;
- монотонная ревизия пакета;
- HTTPS URL архива, его размер и SHA256;
- точный список имён файлов с размерами и SHA256;
- лицензии и notices поставляемых runtime.

Подпись аутентифицирует хэш архива; SHA256 или успешный handshake отдельно
подпись не заменяют. Версия внутри подписанного payload сверяется с текущим
приложением и подписанной версией по контракту updater. Публичный ключ не
даёт права распространять сторонние CUDA runtime: notices и условия NVIDIA
должны входить в подготовленный пакет.

Приватный signing key остаётся вне Git. Подпись и публикация официальных
assets — отдельная операция владельца или защищённого workflow, а не часть
обычного fork PR. В тестах используются только отдельный публичный test key
и небольшие заранее подписанные fixtures.

## Установка и runtime

Загрузка запускается явной кнопкой в настройках. Auto может предложить CUDA
при обнаружении NVIDIA; до установки использует доступный Vulkan/CPU.
Явно выбранный отсутствующий CUDA показывает понятное состояние и не
подменяется CPU молча.

Порядок подготовки: подпись manifest → версии/purpose/platform → bounded
download → размер/SHA256 → безопасная распаковка → все хэши файлов →
production hello/handshake. До этих проверок worker не запускается.
Извлечение отвергает traversal, ссылки/reparse, ADS, дубликаты и несовпадающий
список файлов, а также превышение лимитов размеров.

Пакет публикуется в неизменяемый пользовательский slot. Атомарное состояние
хранит активный hash и старшую принятую ревизию; старую ревизию и другую
начинку под той же ревизией принимать нельзя. Несовместимый с новой Fono
slot не исполняется. Точная привязка версии означает, что для нового выпуска
понадобится совместимый официальный asset даже при неизменном worker.

Download, verify, probe и cleanup удерживают update activity lease до
фактического завершения. Активация выполняется в idle configuration transaction
с generation guards и откатом при ошибке. Модель загружается существующим
`ensure_loaded`; сам downloader новую модель не создаёт. Recovery provider
должен получать свежий проверенный slot, а не путь, захваченный при старте.

## Проверка решения

Локально проверяются правильная и поддельная подписи, несовместимые версии,
хэши/размеры, downgrade и same-revision replacement, опасные архивы, обрыв до
и после promotion, отмена, двойная установка, admission/idle и поздние ответы.
Положительные тесты используют маленькие fixtures и не требуют настоящего GPU.

Отдельно остаются подготовка и публикация подписанного официального архива,
измерение размера базового installer и Windows/GPU-приёмка установки из
настроек, Auto и восстановления. Пока этих результатов нет, OSS-05 не принят.
